# Release 规范

Release 是面向使用者的版本公告，应说明这次交付了什么、影响谁以及是否需要操作。每次推送 `main` 都会触发 Pages 部署；需要形成可追溯的版本里程碑时再创建 GitHub Release，不要求每次提交都发布版本。

## 版本与目标

版本采用 [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html)，Git 标签为 `vX.Y.Z`，`package.json` 的 `version` 为不含 `v` 的相同版本。先核对远端已有版本和标签，再选择下一版本，不能仅依据本地标签或当前包版本推断。

本项目的兼容性约定包括公开 Hash 页面入口、已公开的笔记链接、已记录的浏览器支持及部署配置。1.0 前处于演进阶段，尚不承诺接口稳定；仍需在公告中明确不兼容变化和替代入口。

| 变化 | 版本规则 |
| --- | --- |
| 修复、兼容性维护或需要单独公布的内容修订 | PATCH |
| 向后兼容的新功能或成组内容交付 | MINOR，PATCH 归零 |
| 1.0 后破坏既有兼容性约定 | MAJOR，MINOR / PATCH 归零 |
| 1.0 前的不兼容变化 | 本仓库约定递增 MINOR，逐项说明影响 |
| 候选版本 | 使用 `vX.Y.Z-rc.1` 等标签，标记为 Pre-release |

普通文档修订可随下一版本公布。提交类型是归类线索，版本以本次全部实际变化中影响最大的级别决定；不依据提交数量升级版本。

## 发布流程

1. 确认上一公开版本、本次范围和目标提交。正式版本选择已进入 `main` 的提交，逐项核对从上一版本到目标提交的 PR 与直接提交。
2. 将版本调整作为独立的 `chore(release): 准备 vX.Y.Z 版本` 提交；如产生锁文件变化，一并核对。发布源使用干净检出，已有无关改动时使用独立检出，保留原工作区。
3. 在最终目标提交执行 `pnpm build`，确认全部检查通过；核对该提交的 Pages 工作流成功和线上关键入口。将目标 SHA、工作流结果与实际检查范围记入公告。CI 会刷新贡献快照，线上结果以该次部署产物为准。
4. 按下方格式准备发布说明，核实版本、日期、链接、兼容性和已知问题。GitHub 自动生成内容只作变更清单素材，人工补充直接提交及使用者可见的影响。
5. 标签准确指向经过验证的目标提交；检查同名标签与版本是否已存在。可先保存 Release 草稿；候选版使用 Pre-release，正式公告就绪后再发布。
6. 发布后核对标签 SHA、公告链接和部署结果；已完成的关联 Issue 补充版本并验收关闭。

GitHub Release 的创建不会触发当前 Pages 工作流。发布完成要求版本记录和部署结果都已核对，不能用其中一个代替另一个。

## 公告格式

标题使用 `vX.Y.Z · 中文发布主题`。正文以中文描述结果，技术名称按原名保留；删去没有内容的变更分类，兼容性和已知问题没有事项时明确写“无”。发布前替换全部占位符，链接使用真实记录。

```md
## 发布概览

<用一至三句话说明主要交付及受益场景。>

- 发布日期：<YYYY-MM-DD，Asia/Shanghai>
- 版本范围：<上一版本> → <本次版本；首次发布说明基线>

## 主要变更

### 功能与体验

- <具体场景与新行为>（<PR / 提交链接>）

### 问题修复

- <原问题与修复结果>（<Issue / PR 链接>）

### 内容与文档

- <新增或修订的内容及入口>（<PR / 提交链接>）

### 工程维护

- <对构建、部署或维护的实际影响>（<PR / 提交链接>）

## 兼容性与操作

<不兼容变化、受影响入口、迁移或替代方式；无事项时写“无”。>

## 验证与部署

- 目标提交：<完整 SHA 及提交链接>
- 构建：<pnpm build 的实际结果及工作流链接>
- 部署与检查：<部署链接、核对的页面 / 场景及结果>

## 已知问题

<尚存问题、影响及跟踪 Issue；没有已知问题时写“无”。>

## 完整记录

<上一标签到本次标签的 compare 链接；首次发布使用目标提交链接。>
<有外部贡献时，保留贡献者署名与对应记录。>
```

`.github/release.yml` 按 [Issue 与 PR 规范](issues.md) 的 PR 标签配置自动变更分类，并保留未分类项。它不会自动判断版本号、补全上述公告或执行发布。分类机制见 [GitHub 自动发布说明文档](https://docs.github.com/en/repositories/releasing-projects-on-github/automatically-generated-release-notes)。

## 发布后的修正

已公开的版本保留原标签及其指向的代码。说明中的文字或链接错误可作勘误并注明更正；代码或内容需要修复时新增合规提交并发布下一版本，不覆盖已有版本。线上需要回退时，先定位最后可用提交，以新的回退提交触发部署，并在相关 Issue / Release 中记录影响与修复进度。
