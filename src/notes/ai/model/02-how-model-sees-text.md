# 模型怎样看到文字？

第一篇把模型写成：

$$
y = f_\theta(x)
$$

但在语言模型中，$x$ 究竟是什么？

我们在输入框里写下“重新理解模型”，看到的是具有字形、读音和含义的文字；神经网络执行的却是向量与矩阵计算。屏幕上的字符串必须先经过一套与模型匹配的输入转换，才能成为模型可以继续处理的数值状态。

这篇只追踪其中一条路径：

~~~text
字符串
  ↓
Token 序列
  ↓
Token ID 序列
  ↓
Token 向量序列
  ↓
初始激活
~~~

## 字符串怎样变成 Token ID

文本首先交给一个**具体分词器（tokenizer）**。它按照已经确定的规则和词表，把字符串切成一串离散符号，再为每个符号给出整数编号。

下面是一个人为构造的示意，不代表任何真实模型：

~~~text
字符串：
重新理解模型

Token 序列：
[重新] [理解] [模型]

Token ID 序列：
[1842, 7310, 926]
~~~

这些离散符号称为 **Token（词元）**。Token 是模型输入协议中的单位，不保证等于自然语言中的一个词，也不保证等于一个汉字；它还可能是子词、字符片段或者字节。

可以把整个转换记为：

$$
(t_1,t_2,\ldots,t_n)=T(s)
$$

- $s$ 是原始字符串；
- $T$ 是一套已经确定的具体分词器；
- $t_i$ 是第 $i$ 个 Token 对应的 ID。

同一字符串交给不同分词器，可能得到不同切分和不同 ID。原因不只是它们采用了哪种算法，还包括归一化规则、词表、合并规则、特殊 Token 和 ID 映射都可能不同。

BPE、WordPiece 或 Unigram 描述的是形成切分方案的算法家族；真正决定这段字符串会变成哪些 ID 的，是某个模型所使用的具体分词器。两个模型都使用 BPE，不代表它们拥有相同词表或相同 ID。

## Token ID 只是索引

先观察上面的三个编号：

| Token | Token ID |
| --- | ---: |
| 重新 | 1842 |
| 理解 | 7310 |
| 模型 | 926 |

在继续阅读前可以先判断：ID 7310 是否比 ID 926 表示“更多含义”？如果另一个分词器也产生 ID 1842，它是否一定表示“重新”？

答案都是否定的。

Token ID 的作用类似数组下标：它稳定地指出词表和模型参数中的一个位置。编号的大小不表示重要程度、概念复杂度或者语义距离。另一个分词器完全可以把 ID 1842 分配给不同 Token。

因此，模型的入口不能只写成一串没有上下文的整数；还必须知道这些整数来自哪一套词表和映射规则。

> **Token ID 是查找模型参数的索引，不是 Token 含义的数值编码。**

## ID 怎样取得一个向量

语言模型拥有一个训练得到的**嵌入矩阵（embedding matrix）**：

$$
E\in\mathbb{R}^{V\times d}
$$

- $V$ 是词表中的 Token 数量；
- $d$ 是每个 Token 向量的维度；
- 矩阵的每一行对应一个 Token ID。

对于 ID 为 $t_i$ 的 Token，模型读取嵌入矩阵的对应行：

$$
e_i=E[t_i]
$$

假设这个示意模型只有三维，并且：

$$
E[1842]=[0.12,-0.40,0.73]
$$

那么 ID 1842 的作用不是把数值 1842 送进神经网络做乘法，而是选择这一行参数。本次查找得到的向量就是：

$$
e_1=[0.12,-0.40,0.73]
$$

这些数字同样是人为构造的，只用于说明查找关系。

这里正好可以复用第一篇建立的参数—激活区别：

| 对象 | 在这一步中的角色 |
| --- | --- |
| 嵌入矩阵 $E$ | 训练形成、推理时通常固定的模型参数 |
| Token ID $t_i$ | 指定读取嵌入矩阵的哪一行 |
| Token 向量 $e_i$ | 本次输入查找得到的初始激活 |

矩阵中的那一行在请求到来之前就是模型参数；它被当前 Token ID 选中并进入本次计算后，又成为当前数据流中的一个激活。两者数值可以相同，角色却不同。

对整个 Token ID 序列逐个查找，可以得到：

$$
H^{(0)}=(e_1,e_2,\ldots,e_n)
$$

这里的 $H^{(0)}$ 表示由 Token 嵌入组成的一组初始激活。它是模型开始处理这段文字的数值起点。

## 初始嵌入还不是当前含义

假设“苹果”在下面两个句子中被同一分词器编码成了同一个 Token ID：

> 这种水果叫苹果。

> 这家公司叫苹果。

在同一个模型中，相同 ID 会从嵌入矩阵选择同一行，因此两处“苹果”的初始 Token 嵌入可以相同。但模型不会停在嵌入查找这一步。

后续层还会让位置和上下文 Token 参与计算。以使用因果注意力的解码器式语言模型为例，后面的“苹果”位置可以读取左侧已经出现的“水果”或“公司”。随着激活逐层变化，两处“苹果”可以形成不同的上下文状态。

因此要区分：

~~~text
Token 嵌入
  = 一个 Token 可复用的数值起点

上下文激活
  = 这个 Token 在当前序列中逐层计算形成的状态
~~~

嵌入向量的每一维通常也不能直接命名为颜色、形状或材质。一个坐标只是整个计算空间的一部分，向量怎样参与后续层的计算比孤立读取某个数字更重要。

> **Token 嵌入是上下文计算的起点，不是模型对一个词的完整理解。**

至于位置怎样参与计算、不同 Token 怎样相互影响，以及 $H^{(0)}$ 怎样逐层变成新的隐藏状态，是下一篇需要展开的问题。

## 为什么分词器必须与模型匹配

分词器通常不属于神经网络参数 $\theta$，却属于模型的输入契约。它规定每个 ID 指向什么 Token，而嵌入矩阵是在这套映射下训练出来的。

假设训练时：

~~~text
ID 1842 → “重新” → 读取 E 的第 1842 行
~~~

如果随意换用另一套分词器，而它规定：

~~~text
ID 1842 → “香蕉” → 仍然读取 E 的第 1842 行
~~~

模型就会把“香蕉”送到原本为另一种输入训练出来的参数位置。矩阵形状即使完全兼容，输入含义也已经错位。

因此：

- 不同模型之间不要求使用相同分词器；
- 同一个具体模型必须使用与训练时匹配的词表和 ID 映射；
- 同一种分词算法不保证产生相同的具体分词器；
- 上下文窗口使用 Token 数量衡量，因此同样长的可见文字在不同分词器下可能占用不同空间。

> **模型权重、分词器和输入约定必须彼此匹配，才能组成可以正确使用的语言模型接口。**

## 检查这条输入路径

根据本文建立的关系，可以判断几个新情况：

1. **Token ID 5000 是否比 Token ID 1000 包含更多含义？**

   不包含。ID 只是特定词表中的索引。

2. **同一段文字交给两个模型，Token 数量是否一定相同？**

   不一定。它们可能使用不同的分词器、词表和编码规则。

3. **两个模型都使用 BPE，是否可以交换 Token ID？**

   不可以据此交换。算法家族相同，不代表具体词表和 ID 映射相同。

4. **嵌入矩阵和查出的 Token 向量是同一种对象吗？**

   不是。前者是长期参数；后者是参数在当前输入中被选中后形成的初始激活。

5. **同一个 Token 在两个句子中的初始嵌入相同，最终内部状态是否也一定相同？**

   不一定。位置和上下文会参与后续逐层计算。

6. **只替换分词器而保持模型权重不变，模型还能正常工作吗？**

   通常不能。新的 ID 很可能选择与训练时含义不匹配的嵌入参数。

现在可以把第一篇中的抽象输入 $x$ 展开为：

~~~text
用户提供字符串 s
    ↓ 具体分词器 T
Token ID 序列 (t₁,t₂,…,tₙ)
    ↓ 嵌入矩阵 E
初始激活 H⁽⁰⁾
    ↓
交给模型后续层继续计算
~~~

本文到这里停止：我们已经知道文字怎样成为模型能够继续处理的初始数值状态，但还不知道这些状态怎样通过注意力、非线性变换和层间连接形成上下文表示。

## 延伸阅读

- [Neural Machine Translation of Rare Words with Subword Units](https://arxiv.org/abs/1508.07909)：说明子词单位怎样缓解固定词表对罕见词的限制。
- [SentencePiece: A simple and language independent subword tokenizer and detokenizer for Neural Text Processing](https://arxiv.org/abs/1808.06226)：介绍直接从原始文本训练和执行子词分词的方法。
- [Attention Is All You Need](https://arxiv.org/abs/1706.03762)：给出 Transformer 中 Token 嵌入、位置信息和后续层计算的原始结构。
