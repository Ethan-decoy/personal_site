# C++ 语言、标准与实现（C++ Language, Standard, and Implementations）

“C++”首先指由语言标准（language standard）定义的一门编程语言，而不是某个具体开发工具或操作系统。标准规定共同的语言契约，具体实现（implementation）再把这份契约落实到不同平台。

本套笔记以 C++23 为语言基线。理解一段 C++ 代码时，需要区分标准保证、实现选择和工程判断；三者回答的问题不同，不能用其中一个代替另外两个。

## 控制力与抽象能力

C++ 的设计始于 1979 年。Bjarne Stroustrup 希望把 Simula 组织程序的能力与 C 贴近机器、适合系统编程的特点结合起来。最初的语言称为“C with Classes”，1983 年开始使用 C++ 这个名称。

现代 C++ 已经不只是“给 C 加上类”。它既允许程序直接表达与存储、硬件和平台边界密切相关的操作，也允许把反复出现的细节封装成具有明确接口、能够组合复用的程序部件。

**C++ 提供控制力和抽象工具，但不会自动让程序安全、高效或易于维护。**语言规则决定哪些程序具有含义，接口与资源怎样组织则仍然需要工程判断。

## 标准规定共同的语言契约

C++ 标准规定源程序中各种结构的含义，以及程序必须满足的行为约束。只要某项结论属于标准保证，符合相应条件的 C++ 实现就必须保留它，不能因为换用另一种编译器而任意改变。

标准并不提供一个名为“C++”的可执行程序，也不要求所有实现生成相同的机器指令（machine instruction）。实现可以在不破坏标准要求结果的前提下调整内部执行方式，这类转换称为优化（optimization）。标准描述语言契约，编译器（compiler）等实现工具负责兑现这份契约。

C++ 会持续演进，因此“符合 C++”还需要说明采用哪个标准版本。本文中的代码与语言结论默认以 C++23 为准；具体工具是否已经支持所用规则，则属于实现能力问题。

## 实现把语言落实到平台

C++ 实现通常包含编译器和标准库（standard library）的具体实现，并与平台提供的其他工具共同工作。GCC、Clang 和 MSVC 是常见的 C++ 编译器家族；它们实现的是同一门语言，而不是三种不同的 C++。

不同实现可以采用不同的内部结构和生成策略，也可以处在不同的标准支持进度。如果当前实现和选项允许标准没有规定的扩展（extension），它接受使用该扩展的代码只说明这一组合允许这种写法，不能推出其他 C++ 实现也必须接受。

## 区分三种结论

| 结论层次 | 回答的问题 | 判断依据 |
| --- | --- | --- |
| 标准保证 | 符合条件的 C++ 程序必须具有什么含义 | 对应版本的语言与标准库规则 |
| 实现选择 | 规则允许变化时，当前编译器和平台采用什么方案 | 实现文档、编译选项与目标平台 |
| 工程判断 | 多种合法方案中，哪一种更清楚、安全并适合当前约束 | 接口意图、维护成本与经过验证的实际需求 |

例如，语言标准可以规定一项操作必须产生什么结果，却不必固定实现它的每条机器指令；实现可以选择不同的代码生成方式，却不能因此破坏标准要求的结果；项目还需要在合法方案中选择能够准确表达意图的接口。

**学习 C++ 不只是记住某个编译器当前做了什么，而是判断一项结论究竟来自语言标准、具体实现，还是项目自身的工程选择。**
