# 词法记号、空白与注释（Tokens, Whitespace, and Comments）

C++ 源文件是一系列字符，但编译器不能把每个字符都当作彼此独立的语法单位。它需要先识别哪些字符共同组成一个名称、一个字面量或一段标点，再按照这些单位理解程序。

## 字符组成词法记号

在[从源文件到可执行程序](04-source-file-to-executable.md)建立的翻译过程中，源文件会先被分解为预处理记号（preprocessing token）与空白序列；预处理完成后，保留下来的预处理记号再转换为 C++ 的词法记号（token）。下面只在这项区别影响结论时写出完整名称，其余位置统称为记号。

观察第一个程序中已经见过的入口函数：

```cpp
int main() {
    return 0;
}
```

其中：

- `int` 与 `return` 是具有语言规定含义的关键字（keyword）；
- `main` 是标识符（identifier），也就是可以作为名称使用的记号；
- `0` 是直接表示一个值的字面量（literal）；
- 圆括号、花括号与分号是标点符号（punctuator）。

**词法记号是编译器继续进行语法分析时使用的基本单位；同一个记号内部的字符不能再像记号之间的空白那样任意增删。**

## 空白通常分隔记号

常见的空白字符（whitespace character）包括空格、制表符与换行。只要没有改变记号边界，下面两种排版会形成相同的记号序列：

```cpp
int main() {
    return 0;
}
```

```cpp
int main() { return 0; }
```

两段代码在语言中具有相同含义，但第二种排版没有把函数体结构清楚地展示给读者。**空白在许多位置不改变程序含义，不表示排版没有工程价值。**统一的缩进与换行能够直接呈现代码结构，也让自动格式化工具减少无意义的差异。

空白也不能无条件删除：

```text
return 0;  -> 关键字 return、字面量 0、分号
return0;   -> 标识符 return0、分号
```

第一行需要空白来结束关键字 `return`。第二行的连续字母与数字会组成一个标识符，已经不是相同的记号序列。

## 有些空白属于语言结构

第一个程序使用了下面的字符串字面量：

```cpp
"Hello, C++!\n"
```

引号之间的空格属于这个字面量表示的字符序列，删除它会改变输出内容；不能把它当作记号之间的分隔空白。整个字符串字面量形成一个记号，其中的 `\n` 是表示换行字符的转义序列。

换行在预处理指令中也具有额外作用。下面的 `#include` 指令在当前行结束：

```cpp
#include <iostream>
```

因此，更准确的模型不是“编译器忽略空白”，而是：**空白通常分隔记号，但也可能属于字面量内容，或参与确定预处理指令的边界。**

## 注释在翻译时成为空白

注释（comment）用于把信息留给源代码读者。C++ 提供行注释与块注释两种形式；翻译程序时，注释本身不会形成运行时需要执行的操作。

### 行注释

行注释（line comment）从 `//` 开始，延续到当前行结束：

```cpp
#include <iostream>

int main() {
    // 向标准输出写入一行问候文本。
    std::cout << "Hello, C++!\n";
    return 0;
}
```

换行结束当前注释，下一行重新按照普通 C++ 源代码处理。行注释既可以独占一行，也可以放在代码之后；位置合法并不表示注释内容一定有价值。

### 块注释

块注释（block comment）以 `/*` 开始，以随后遇到的第一个 `*/` 结束，因此可以跨越多行：

```cpp
int main() {
    /*
     * 运行环境使用返回状态判断程序是否成功。
     */
    return 0;
}
```

**块注释不能嵌套。**块注释内部再次出现 `/*` 不会开始新的内层注释；随后遇到的第一个 `*/` 仍会结束原来的块注释，其余字符将重新作为源代码处理。

在标准描述的翻译过程中，每段注释会被替换为一个空格，行注释末尾的换行仍然保留。因此，下面这种刻意排版仍会让 `int` 与 `main` 保持为两个记号：

```cpp
int/* separator */main() {
    return 0;
}
```

它在语言中可以成立，却迫使读者先移除注释才能看清代码结构，不应作为日常写法。注释可以出现在两个记号之间，不表示每个合法位置都适合放置注释。

## 注释补充代码没有表达的信息

清楚的名称和代码结构首先负责说明程序正在做什么。下面的注释只是逐字复述代码：

```cpp
std::cout << "Hello, C++!\n";  // 输出 Hello, C++!
```

如果输出文本受外部约束，注释才可能提供代码本身没有表达的信息：

```cpp
// 自动检查会逐字匹配这行文本，标点也是接口的一部分。
std::cout << "Hello, C++!\n";
```

代码发生变化时，相关注释也必须同步更新。过时的注释会让读者在代码与文字之间作出错误判断，往往比没有注释更危险。

C++ 语言只规定 `//` 与 `/* ... */` 两种注释形式；开发工具可以对特定注释格式赋予额外用途，但这些工具约定不会增加新的 C++ 注释语法，也不会改变程序的语言语义。

**空白与注释首先参与源代码的词法组织；工程代码再通过一致排版和准确说明，让同一份记号序列能够被人可靠地理解与维护。**
