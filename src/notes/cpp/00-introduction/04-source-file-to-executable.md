# 从源文件到可执行程序（From Source File to Executable Program）

在[编译并运行第一个 C++ 程序](02-choosing-cpp-development-tools.md)中，编译器驱动程序接收了 `main.cpp`，最终生成可以启动的程序。这个面向用户的入口会协调多个工具，一条命令因而隐藏了从源文本到可执行文件的不同职责。

共同完成 C++ 构建的一组工具称为工具链（toolchain）。

## 标准翻译与工具链实现不是同一层

C++ 标准描述源程序经过哪些翻译阶段（phases of translation），规定符合要求的程序应当呈现什么行为，并区分哪些违规需要诊断。它不要求编译器把每个阶段实现成独立进程，也不要求磁盘上实际出现固定名称的中间文件。

GCC、Clang 与 MSVC 等常见工具链通常可以用下面的过程理解：

```text
C++ 源文件
    │  预处理与后续语言转换
    ▼
翻译单元（translation unit）
    │  狭义编译（compilation）
    ▼
汇编代码（assembly code）或其他目标相关表示
    │  汇编（assembly）
    ▼
目标文件（object file）
    │  与其他目标文件一起链接（linking）
    ▼
可执行程序
```

某个实现可以合并相邻阶段，也可以从 C++ 直接生成目标文件而不保存汇编文本。**这张图划分的是典型工具链中的职责，不是 C++ 标准强制规定的进程、文件数量或内部实现。**

## 源代码处理形成翻译单元

预处理会处理第一个程序中的 `#include` 指令。

第一个程序中的：

```cpp
#include <iostream>
```

使标准输入输出设施的相应内容参与 `main.cpp` 的处理。一份源文件及由 `#include` 纳入的内容经过语言规定的后续转换后，共同形成一个翻译单元（translation unit）。

在当前模型中，翻译单元是由一份源文件及其纳入内容形成、作为整体接受后续分析和翻译的 C++ 内容。实现可以在内部直接传递处理结果，不必把它保存为独立文本文件。

## 编译与汇编产生目标文件

狭义的编译会分析已经形成的翻译单元，检查它是否符合 C++ 规则，并生成面向目标平台（target platform）的代码。目标平台是程序准备运行的处理器与系统环境。

编译器可以先产生汇编代码。汇编代码是目标处理器机器指令的一种文本表示；汇编器（assembler）再把它转换成处理器能够执行的机器指令与构建信息。实现也可以不保存汇编文本，直接生成相同阶段所需的结果。

这些结果通常进入目标文件。**目标文件是已经包含目标平台代码或数据、但仍可能需要与其他编译产物组合的构建产物。**它不等于完整的可执行程序。

## 符号（symbol）记录跨文件关系

一个目标文件可能提供其他编译产物需要使用的代码或数据，也可能需要使用当前文件没有提供的内容。目标文件使用符号记录后续组合时需要识别的这类实体（entity）。

这里的定义（definition）是实际提供某个实体、能够满足相应引用的程序内容。

当前目标文件需要某个实体、却没有包含其定义时，这项需求构成外部引用（external reference）。可以把两个目标文件的关系抽象为：

```text
目标文件 A：提供符号 alpha，引用符号 beta
目标文件 B：提供符号 beta
```

符号不是源代码名称的简单文本副本，也不是程序运行时重新查询 C++ 源代码的机制。工具链会按照目标平台的规则，把需要跨编译产物识别的信息记录进目标文件。

## 链接组合编译产物

库（library）在这里可以先理解为供程序复用的一组编译产物。库的组织格式由具体工具链与目标平台决定，不是 C++ 源语言固定的文件形式。

链接器（linker）读取目标文件与所需的库，根据符号把外部引用匹配到相应定义，并生成当前构建需要的最终产物。构建普通程序时，这个产物通常是可执行文件。

```text
目标文件 A ─┐
目标文件 B ─┼─> 链接器 ─> 可执行程序
所需的库  ──┘
```

如果某个外部引用始终找不到相应定义，相应翻译单元可能已经分别通过编译，链接仍然会失败。编译错误与链接错误因而位于不同边界：

| 失败位置 | 当前工具缺少什么 |
| --- | --- |
| 编译 | 无法把当前翻译单元解释为合法 C++ |
| 链接 | 无法为目标文件中的外部引用找到可组合的定义 |

## 分别编译让翻译单元独立产生目标文件

多个翻译单元可以分别完成翻译，再在链接阶段组合，这种组织方式称为分别编译（separate compilation）：

```text
main.cpp      ─> 翻译单元 ─> main.o      ─┐
greeting.cpp  ─> 翻译单元 ─> greeting.o  ─┼─> 链接器 ─> 程序
库中的产物   ───────────────────────────┘
```

修改一个源文件后，工具链通常只需重新生成受影响的目标文件，再执行链接。大型程序因而不必在每次修改后把所有源文本作为一个整体重新处理。

链接器组合的是已经生成的目标文件，不会重新按照 C++ 源代码解释其中的表达式。分别编译的产物若要正确协作，就必须对符号表示以及跨文件传递的信息采用一致规则；这构成分别编译产物之间的协作边界。

## 观察 GCC 的停止位置

GCC 驱动程序允许构建停在典型流程的不同位置：

| 命令 | 停止位置 | 常见输出 |
| --- | --- | --- |
| `g++ -std=c++23 -E main.cpp -o main.ii` | 预处理完成后 | 预处理后的文本 |
| `g++ -std=c++23 -S main.cpp -o main.s` | 编译完成、汇编之前 | 汇编代码 |
| `g++ -std=c++23 -c main.cpp -o main.o` | 目标文件生成、链接之前 | 目标文件 |
| `g++ main.o -o hello` | 链接完成后 | 可执行程序 |

`.ii`、`.s` 与 `.o` 是这套工具链常用的文件扩展名，不是 C++ 标准要求所有实现采用的名称。即使日常交流把整条命令统称为“编译”，判断错误与编译产物时，仍应区分预处理、狭义编译、汇编和链接各自承担的职责。

**源代码规定程序含义，C++ 实现负责完成翻译，工具链再用目标文件、符号与链接把分别生成的编译产物组合成程序。**
