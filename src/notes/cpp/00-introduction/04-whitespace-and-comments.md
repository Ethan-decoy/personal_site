# 词法记号、空白与注释（Tokens, Whitespace, and Comments）

C++ 源文件是一系列字符，但编译器不能把每个字符都当作彼此独立的语法单位。它需要先识别哪些字符共同组成一个名称、一个字面量或一段标点，再按照这些单位理解程序。

## 字符组成词法记号

观察第一个程序中已经见过的入口函数：

```cpp
int main() {
    return 0;
}
```

其中：

- `int` 与 `return` 是具有语言规定含义的关键字（keyword）；
- `main` 是标识符（identifier），也就是可以作为名称使用的记号；
- `0` 是直接表示一个值的字面量（literal）；
- 圆括号、花括号与分号是标点符号（punctuator）。

这些单位称为词法记号（token），是编译器继续进行语法分析时使用的基本单位。

原问候程序的输出语句还包含已经见过的多字符记号：

| 源代码片段 | 记号怎样组成这段代码 |
| --- | --- |
| `std::cout` | `std`、`::`、`cout` 三个记号；连写的内容不一定是一个记号 |
| `<<` | 一个由两个字符组成的运算符（operator）记号 |
| `"Hello, C++!\n"` | 一个字符串字面量记号，引号内的空格与 `\n` 都属于它的内容 |

> [!IMPORTANT] 字符与词法记号的边界
> **一个记号可以包含多个字符，连写的源代码也可能包含多个记号。**继续分析和调整排版时，应以实际记号边界为准，不能把每个字符都当作独立单位，也不能把一个记号内部任意拆开。

## 空白通常分隔记号

常见的空白字符（whitespace character）包括空格、制表符与换行。先比较只有 `return 0;` 的这段普通函数：下面两种排版形成相同的记号序列，第二种刻意压在一行，用于观察排版与记号的区别。

```cpp
int main() {
    return 0;
}
```

```cpp
int main() { return 0; }
```

两段代码在语言中具有相同含义，但第二种排版没有把函数体结构清楚地展示给读者。**空白在许多位置不改变程序含义，不表示排版没有工程价值。**统一的缩进与换行能够直接呈现代码结构，也让自动格式化工具减少无意义的差异。

空白也不能无条件删除：

```text
return 0;  -> 关键字 return、字面量 0、分号
return0;   -> 标识符 return0、分号
```

第一行需要空白来分隔 `return` 与 `0`。第二行的连续字母与数字会组成一个标识符，已经不再表达“返回 `0`”。

多字符记号也不能随意拆开：

```text
<<    -> 一个记号 <<
< <   -> 两个记号 <、<
```

把原输出语句中的 `<<` 改成 `< <`，得到的就不再是本例合法的输出写法。

> [!IMPORTANT] 调整空白需要保持记号不变
> **在普通语句的记号之间调整空白时，必须保持记号本身及其先后顺序。**删去 `return 0` 中的分隔空白，或在 `<<` 内插入空白，都会改变记号序列，不能当作只改变排版。

## 有些空白属于语言结构

第一个程序使用了下面的字符串字面量：

```cpp
"Hello, C++!\n"
```

引号之间的空格属于这个字面量表示的字符序列，删除它会改变输出内容；不能把它当作记号之间的分隔空白。整个字符串字面量形成一个记号，其中的 `\n` 是表示换行字符的转义序列。

源文件中直接保存的每一行称为物理行（physical source line）。在识别记号与处理预处理指令之前，C++ 会先进行行拼接（line splicing），由物理行形成逻辑行（logical source line）。

对于本篇使用的普通源文本，C++23 的相关规则是：如果反斜杠 `\` 之后直到本行结束都只有空白（也可以没有空白），行拼接会删除这个反斜杠、后续空白和换行，把下一物理行接到当前行后面。这里处理的是源文件中的实际换行，与字符串中表示换行字符的 `\n` 写法不同。

对于下面这种普通 `#include` 写法，指令在行拼接之后的换行处结束。这里没有行拼接，所以指令就在当前物理行末尾结束：

```cpp
#include <iostream>
```

> [!IMPORTANT] 空白的作用取决于所在位置
> **记号之间的空白可以用于分隔；字面量内部的空白属于内容；源文件中的换行还参与确定预处理指令的边界，并可能先被行拼接移除。**修改空白时，要先辨认它处于哪一种位置，不能一概按“编译器忽略空白”处理。

## 注释在翻译时成为空白

注释（comment）用于把信息留给源代码读者。C++ 提供行注释与块注释两种形式；翻译程序时，注释本身不会形成运行时需要执行的操作。

### 行注释

行注释（line comment）从被识别为注释起始的 `//` 开始，延续到行拼接之后的下一个换行之前。下面没有行拼接，注释只占一个物理行：

```cpp
#include <iostream>

int main() {
    // 向标准输出写入一行问候文本。
    std::cout << "Hello, C++!\n";
    return 0;
}
```

这个例子中，保留下来的换行结束注释，下一行的输出语句仍然参与编译。行注释既可以独占一行，也可以放在代码之后；位置合法并不表示注释内容一定有价值。

行拼接先于注释识别，因此，在行注释末尾意外留下反斜杠，可能让下一物理行也进入注释。下面刻意加入这个错误，观察它对同一个问候程序的影响：

```cpp
#include <iostream>

int main() {
    // 向标准输出写入一行问候文本。 \
    std::cout << "Hello, C++!\n";
    return 0;
}
```

> [!WARNING] 行尾反斜杠可能把下一行代码并入注释
> 上例中，反斜杠与其后的换行先被删除，输出语句因而接到 `//` 注释后面，随后一起作为注释处理。程序仍可能编译成功并返回 `0`，但不会输出问候文本。
>
> 在 C++23 中，反斜杠与换行之间即使只有空白，也符合上述拼接条件。检查行注释边界时，不能只按编辑器显示的物理行判断；日常注释应避免这种意外续行。

### 块注释

块注释（block comment）以 `/*` 开始，以随后遇到的第一个 `*/` 结束，因此可以跨越多行：

```cpp
int main() {
    /*
     * 运行环境使用返回状态判断程序是否成功。
     */
    return 0;
}
```

> [!IMPORTANT] 块注释在第一个结束标记处终止
> **块注释不能嵌套。**块注释内部再次出现 `/*` 不会开始新的内层注释；随后遇到的第一个 `*/` 仍会结束原来的块注释，其余字符将重新作为源代码处理。因此，不能直接用一对 `/* ... */` 包住已经含有块注释的整段代码。

### 字符串中的注释符号属于内容

回到原问候程序，在 `main` 内只替换输出语句，把注释符号放进字符串：

```cpp
std::cout << "Hello, C++! // /* */\n";
```

这条语句会输出 `Hello, C++! // /* */` 并换行。这里的 `//`、`/*` 与 `*/` 都处于字符串字面量内部，属于输出内容；它们不会开始或结束源代码注释。

> [!IMPORTANT] 注释符号需要结合词法上下文识别
> **相同字符在不同位置可以承担不同职责。**字符串中的 `//`、`/*` 与 `*/` 是字面量内容；只有在相应词法上下文中被识别为注释边界时，它们才具有注释作用。辨认注释时，应先确定这些字符是否已经处于字面量或其他注释之内。

### 注释替换为空白，保留记号之间的分隔

在[从源文件到可执行程序](03-source-file-to-executable.md#源代码处理形成翻译单元)涉及的翻译过程中，行拼接完成后，源文件被分解为预处理记号（preprocessing token）与空白序列。预处理记号是预处理阶段使用的词法单位；每段注释被替换为一个空格，这时仍存在的换行会保留。预处理等步骤完成后，相应预处理记号再转换为接受 C++ 语法、语义分析的词法记号。

因此，下面这种刻意排版仍会让 `int` 与 `main` 保持为两个记号：

```cpp
int/* separator */main() {
    return 0;
}
```

它在语言中可以成立，却迫使读者先移除注释才能看清代码结构，不应作为日常写法。注释可以出现在两个记号之间，不表示每个合法位置都适合放置注释。

> [!IMPORTANT] 注释不会把两侧字符拼成一个记号
> **注释作为空白保留分隔作用，不会把两侧字符直接粘合。**因此，`int/* separator */main` 中仍然有 `int` 和 `main` 两个记号；同样，`re/* separator */turn` 也不能组成关键字 `return`。

这里需要理解替换结果怎样影响记号边界；完整的记号分类与翻译阶段细则，可在处理具体词法或预处理问题时按文末标准条款查阅，不要求背诵全部分类与阶段编号。

## 注释补充代码没有表达的信息

清楚的名称和代码结构首先负责说明程序正在做什么。以下两个片段都用于替换原问候程序 `main` 内的输出语句，保留 `#include <iostream>` 与其他代码。第一种注释只是逐字复述代码：

```cpp
std::cout << "Hello, C++!\n";  // 输出 Hello, C++!
```

如果输出文本受外部约束，注释可以说明为什么需要保留当前写法：

```cpp
// 自动检查会逐字匹配这行文本，标点也是接口的一部分。
std::cout << "Hello, C++!\n";
```

这里的外部约束只是一个例子；设计原因、必要假设和行为限制，也可能是代码本身没有充分表达的信息。代码发生变化时，相关注释也必须同步更新，否则读者可能依据已经失效的说明作出判断。

> [!IMPORTANT] 注释补充原因、约束与边界
> **名称和代码结构负责表达程序在做什么；注释补充代码没有充分表达的原因、约束、假设或边界，并应随相关代码保持准确。**评价一条注释时，应看它是否提供了有用且仍然成立的信息，而不是只看它是否描述了某条语句。

C++ 语言只规定 `//` 与 `/* ... */` 两种注释形式；开发工具可以对特定注释格式赋予额外用途，但这些工具约定不会增加新的 C++ 注释语法，也不会改变程序的语言语义。

分析空白和注释时，先确认行拼接是否改变了源文本，再辨认字面量、注释与记号边界；维护代码时，同时核对排版是否清楚、注释是否仍与代码和约束一致。
