# 面向对象编程（Object-Oriented Programming，OOP）

绘图程序需要保存画布上的图形，响应移动操作，并在需要时重新绘制画面。即使两个圆看起来完全相同，程序也需要分清正在移动哪一个；绘制圆和矩形时，又需要采用不同的具体做法。

面向对象编程把相关信息与操作围绕对象（object）组织起来，并通过明确的使用约定使用对象。本篇用同一个绘图场景说明这些关系，再观察不同种类的对象怎样响应共同的操作。

## 图形对象保存各自的状态

假设画布上有圆 A、圆 B 和一个矩形。程序分别保存这些图形的位置与大小；这里的图形对象是程序中对图形的表示，不是屏幕上的那片像素本身。

一个对象在某个时刻保存的信息，称为它的状态（state）。例如，圆的状态可以包括中心位置与半径。下面只比较两个圆的中心横向位置与半径，数字采用绘图程序约定的同一种长度单位：

| 图形对象 | 中心横向位置 | 半径 |
| --- | ---: | ---: |
| 圆 A | 20 | 10 |
| 圆 B | 20 | 10 |

即使两个圆的其他状态也相同、当前画面中完全重合，它们仍然可以是两个不同的图形对象。程序需要保留这种区别，才能只选中并移动其中一个。

> [!IMPORTANT] 对象与当前状态的区别
> **状态相同，不表示是同一个对象；对象的状态改变后，也可以仍然是原来的对象。**判断一次移动影响谁时，需要先辨认操作的目标，不能只比较两个图形当前是否相同。

## 操作怎样改变状态

程序允许对对象执行的动作称为操作（operation）。对于当前绘图场景，可以约定：

| 操作 | 输入与结果 |
| --- | --- |
| 读取位置 | 取得目标图形当前的中心位置，不改变它的状态 |
| 移动到指定位置 | 接收新的中心位置，改变目标图形的位置，保持大小不变 |
| 绘制 | 读取目标图形的位置与大小，在画布上生成相应图像，保持这些状态不变 |

现在只把圆 A 的中心横向位置从 `20` 改到 `35`，其余状态保持不变。在这个分别保存状态、没有联动更新的例子中，圆 A 的半径仍为 `10`，圆 B 的横向位置仍为 `20`。圆 A 被移动了，并没有因此变成另一个圆。

本例把移动与绘制作为两个操作：移动先更新保存的位置，随后绘制再读取新位置，画面才反映这次变化。对象不会因为被称为“圆”就自行移动或绘制，具体行为仍由程序执行相应操作完成。

这些对外提供的操作，以及它们的输入、结果和使用条件，共同构成对象的接口（interface）。使用者知道怎样请求移动、移动影响什么，就可以使用这项操作，不必了解对象内部怎样保存位置。

> [!IMPORTANT] 接口规定对象的使用方式
> **接口说明可以请求哪些操作、需要提供什么，以及操作具有怎样的作用和条件。**对象的实现负责兑现这些约定；使用者依赖约定使用对象，内部表示可以在保持约定成立的前提下调整。

## 共同接口与不同实现

圆与矩形需要保存的信息并不完全相同：圆可以用中心位置与半径描述大小和位置；本例的矩形各边与画布边缘平行，可以用中心位置、宽和高描述。它们的绘制过程也不同。

不过，重绘画面的过程可以只提出共同要求：“把这个图形绘制到给定画布上。”圆按照圆的规则绘制，矩形按照矩形的规则绘制；具体实现各自读取所需的状态，满足同一个操作约定。

如果重绘过程始终只通过这个共同接口使用图形，新增椭圆时，就可以为椭圆提供符合约定的绘制实现，并继续沿用这段重绘过程。这里复用的是依赖共同接口的处理过程，不要求所有图形采用相同的内部表示或绘制步骤。

> [!IMPORTANT] 共同接口与对象各自的实现
> **通过共同接口提出同一种操作请求，再根据运行时实际使用的对象执行相应实现，是运行时多态（runtime polymorphism）的一种表现。**使用者依赖共同约定，不必在这一处理过程中分别写出每一种图形的绘制细节。

这个例子也区分了两层关系：把相关状态与操作组织起来、通过接口使用而不依赖内部表示，建立了数据抽象（data abstraction）；让不同种类的对象通过共同接口被使用，并保留各自的实现，进一步展示了这里讨论的面向对象多态。只把程序拆成若干部件，还不足以说明已经建立了后一层关系。

程序可以为圆与矩形分别定义类型（type），规定同类对象需要保存什么状态、能够怎样使用。在 C++ 中，类（class）用于定义这样的用户自定义类型，继承（inheritance）与虚函数（virtual function）可以支持上述共同接口和运行时选择。

给两个互不相关的操作取相同名字，并不会自动建立这些关系；需要由程序实际采用的类型关系与调用机制来支持。类、继承与虚函数在这里用于定位实现手段，具体规则按文末的标准条款查阅；当前要分清的是共同接口、目标对象与对应实现之间的关系。

## C++ 对象与面向对象设计

图形对象是设计绘图程序时选择的组织单位；C++ 语言规则中的对象（object）范围更广。即使只保存圆 A 中心横向位置的那一份数值，也可以是一个 C++ 对象。完整图形的状态则可能由多份这样的数值组成。

把一份数值命名为“圆的位置”，不会让它自动成为能够移动和绘制的完整图形。数值怎样参与图形状态，以及哪些操作会使用它，都要由程序明确组织。

> [!IMPORTANT] 存在对象不等于采用面向对象编程
> **C++ 对象是语言模型中的概念，OOP 是组织和使用程序部件的一种方式。**程序中存在数值对象，不表示已经采用 OOP；C++ 支持 OOP，也允许结合其他程序组织方式解决问题。

沿着这个绘图场景，已经可以分别判断：正在操作哪个图形、操作读取或改变了什么状态，以及共同请求最终由哪一项实现完成。落实到代码时，还需要区分保存状态的对象、对象当前的值，以及规定其使用方式的类型。
