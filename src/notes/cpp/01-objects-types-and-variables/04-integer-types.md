# 整数类型（Integer Types）

## 有限存储中的整数

数学中的整数可以向正负方向无限延伸，计算机对象能够使用的存储空间却是有限的。一个整数类型只有有限数量的比特组合，因此只能表示有限范围内的整数。

在前面的画布上有两个圆和一个矩形，可以用一个整数记录图形数量。下面的片段放在 `main` 函数体内：

```cpp
int shape_count{3};
```

`int` 是 C++ 最常用的整数类型，适合表示这里的图形数量。但无论使用哪一种整数类型，它都只能表示一定范围内的值。

整数类型用于表示值的位数称为**位宽（width）**，有符号类型的位宽也包含符号位（sign bit）。对象的存储中还可能存在不参与表示值的**填充位（padding bits）**，这些位不计入位宽。因此，讨论取值范围时，应使用表示值的位宽，不能直接把整个对象的存储位数代入。

## 有符号与无符号整数（Signed and Unsigned Integers）

标准整数类型分为有符号整数类型（signed integer type）与无符号整数类型（unsigned integer type）。`int` 与 `signed int` 是同一种类型，可以表示负数、零和正数；`unsigned int` 只表示零和正数。单独写出的 `signed` 和 `unsigned` 分别是 `signed int` 与 `unsigned int` 的简写。

以 4 位的数值模型为例，4 个比特共有 $2^4=16$ 种组合。无符号模型把它们全部用于表示非负整数；有符号模型把一半用于负数，另一半用于零和正数：

| 数值模型 | 取值范围 | 值的数量 |
| --- | --- | --- |
| 4 位无符号整数 | `0～15` | 16 个非负整数 |
| 4 位有符号整数 | `−8～7` | 8 个负整数，8 个非负整数 |

有符号模型的负数一侧是 `−8～−1`，零和正数一侧是 `0～7`。零也要占用一个值，所以最大的正数是 `7`，负数一侧却可以到 `−8`。这里的 4 位模型用于说明范围关系，并不是一种 C++ 标准整数类型。

> [!IMPORTANT] 位宽与取值范围
> **每一对相应的标准有符号与无符号整数类型具有相同的位宽，占用相同大小的存储，但表示不同的值域。**位宽为 $N$ 时：
>
> - 无符号类型的范围是 $[0,\,2^N-1]$。
> - 有符号类型的范围是 $[-2^{N-1},\,2^{N-1}-1]$，这里的 $N$ 包含符号位。
>
> 两者都能表示 $2^N$ 个值。无符号类型把这些值全部分配给零和正数，有符号类型则同时表示负数、零和正数。

例如，位宽为 32 的 `int` 能表示 $[-2^{31},\,2^{31}-1]$，对应的 `unsigned int` 能表示 $[0,\,2^{32}-1]$。无符号类型扩大了非负范围，但相应地失去了表示负数的能力。

## 标准整数类型

C++ 的标准有符号整数类型包括 `signed char`、`short`、`int`、`long` 和 `long long`；每一种都有相应的无符号类型。标准保证它们的位宽至少分别为 8、16、16、32 和 64，按上述顺序，后一个类型占用的存储不小于前一个。

> [!IMPORTANT] 标准保证与实现大小
> **标准规定整数类型的最小位宽和相对存储大小，具体大小由实现决定。**相同的类型名称不保证在所有平台上占用相同的字节数；“64 位平台”也不意味着所有整数类型都具有 64 位位宽。

下表选取 `short`、`int`、`long`、`long long` 及其无符号类型，比较 Windows x64 与 Linux x86-64 的常见实现。这两种实现都采用 8 位字节，表中这些类型没有填充位，所以可以用“字节数乘以 8”得到位宽。`signed char`、`unsigned char` 也属于标准整数类型，它们与 `char` 的区别见[字符与文本编码中的说明](06-characters-and-text-encoding.md#char)。

表中的具体字节数和数值端点供比较与查阅，不必逐项记忆。运算可能接近端点，或需要固定宽度、对接外部二进制格式时，应先核对目标实现。可从 [Microsoft 的类型规格](https://learn.microsoft.com/en-us/cpp/cpp/data-type-ranges?view=msvc-170)和 [GCC 的 x86 目标选项](https://gcc.gnu.org/onlinedocs/gcc/x86-Options.html)查阅下面两种实现的相关约定。

| C++ 类型 | Windows x64 常见实现 | Linux x86-64 常见实现 | 对应实现中的表示范围 |
| --- | ---: | ---: | ---: |
| `short` | 2 字节 | 2 字节 | `−32,768～32,767` |
| `unsigned short` | 2 字节 | 2 字节 | `0～65,535` |
| `int` | 4 字节 | 4 字节 | `−2,147,483,648～2,147,483,647` |
| `unsigned int` | 4 字节 | 4 字节 | `0～4,294,967,295` |
| `long` | 4 字节 | 8 字节 | Windows： $[-2^{31},\,2^{31}-1]$；Linux： $[-2^{63},\,2^{63}-1]$ |
| `unsigned long` | 4 字节 | 8 字节 | Windows： $[0,\,2^{32}-1]$；Linux： $[0,\,2^{64}-1]$ |
| `long long` | 8 字节 | 8 字节 | $[-2^{63},\,2^{63}-1]$ |
| `unsigned long long` | 8 字节 | 8 字节 | $[0,\,2^{64}-1]$ |

例如，表中的 `long` 在 Windows x64 上占 4 字节，在 Linux x86-64 上占 8 字节，两者都符合 C++ 的最低要求。这个差异来自目标平台采用的约定，不能只凭类型名称或编译器名称判断。

## 无符号算术与模运算

一个只保留 `0～7` 的数值模型共有 8 个值。如果计算结果必须落在这个范围内，可以约定：数学结果为 `9` 时，减去 `8`，得到 `1`；结果为 `-1` 时，加上 `8`，得到 `7`。超出范围时反复加上或减去 `8`，直到结果回到范围内。

这种计算称为**模运算（modular arithmetic）**，这里的 `8` 称为**模（modulus）**。两个整数之差是模的整数倍时，称它们对该模**同余（congruent）**；例如 `9` 与 `1` 模 `8` 同余，`-1` 与 `7` 也模 `8` 同余。

C++ 的无符号算术采用这样的模规则。当加法、减法或乘法以位宽为 $N$ 的无符号整数类型进行时，该类型共有 $2^N$ 个值，因此以 $2^N$ 为模，得到范围内与数学结果同余的值。

例如，下面是另一个放在 `main` 函数体内的独立片段。画布上没有图形，计数为 `0`，代码却仍然从中减去 `1`：

```cpp
unsigned int shape_count{0};
unsigned int removed_count{1};

shape_count = shape_count - removed_count;
```

`-` 执行减法，`=` 把结果写回 `shape_count`。减号两侧的值都是 `unsigned int`，减法也以 `unsigned int` 进行。数学结果是 `-1`，加上模 $2^N$ 后，得到该类型的最大值 $2^N-1$。若 `unsigned int` 的位宽为 32，`shape_count` 最终保存的是 `4,294,967,295`，并不会因为计数应当非负就停在 `0`。

> [!IMPORTANT] 运算类型与整数越界
> **整数算术的范围规则取决于实际执行运算的类型。**对于加法、减法和乘法：
>
> - 以无符号类型运算时，按 $2^N$ 取模，$N$ 是该运算类型的位宽。
> - 以有符号类型运算时，数学结果若超出该类型范围，就会产生未定义行为，不能依赖结果回绕。
>
> 无符号算术有规定的模规则，并不意味着其结果一定符合计数、差值等业务含义。

参与运算的值可能先转换为另一种类型，再执行计算。例如，在常见的 32 位 `int`、16 位 `unsigned short` 实现中，`unsigned short` 的值参与普通加减乘运算前会先转换为 `int`，因为 `int` 能表示它的全部取值。这时应按 `int` 的范围判断结果，不能直接套用 16 位无符号模规则。混合不同整数类型时也要先确定实际运算类型，具体规则见[整数提升](../02-expressions-and-operators/03-usual-arithmetic-conversions.md#整数提升integral-promotions)与[共同类型决定运算边界](../02-expressions-and-operators/03-usual-arithmetic-conversions.md#共同类型决定运算边界)。

> [!PRACTICE]
> 普通计数、差值和算术通常优先使用有符号整数。无符号类型适合明确需要模运算、处理比特组合或外部接口规定无符号表示的场景。若业务上不允许从 `0` 个图形中再减去 `1` 个，应在减法之前检查数量；把计数声明为无符号类型不能替代这个判断。
