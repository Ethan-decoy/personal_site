# 字符与文本编码（Characters and Text Encoding）

## 从 bit patterns 到字符

内存只能保存由 `0` 和 `1` 构成的比特组合，那么字母 `A` 应当怎样存入内存？

假设只使用一个比特，可以自行约定 `0` 代表 `A`，`1` 代表 `B`；如果还要表示 `C`，就需要增加比特，从而获得更多组合。但这些组合本身不具有字符含义：一个程序可以规定 `00` 代表 `A`，另一个程序也可以把它解释成 `B`。

把文本表示成可存储、传输的数值序列，需要采用**字符编码（character encoding）**规则。读取这些数值时，也要按相应规则恢复字符含义。

> [!IMPORTANT] 字符含义与编码约定
> **比特组合本身不带字符含义。**写入和读取文本的程序需要采用一致的编码约定，才能把存储内容解释为预期字符；换一套解释规则，相同内容就可能被理解为不同文本。

## ASCII

20 世纪 60 年代形成的 ASCII（American Standard Code for Information Interchange，美国信息交换标准代码）使用 7 比特定义了 128 个编码值，范围是 0 到 127。它统一规定了控制字符（control character）、空格、数字字符、英文字母和常用标点各自对应的数值。

例如，数字字符 `0` 对应 48，大写字母 `A` 对应 65，小写字母 `a` 对应 97。这里的数字字符 `0` 与用于计数的整数 `0` 是不同含义，前者的 ASCII 编码值是 48。当不同系统都遵循 ASCII 时，编码值 65 就会被一致地解释为字符 `A`。

下表用于按类别查阅，不必逐项记忆区间端点。需要确认某个字符的具体编码值时，可以核对 [RFC 20 的完整编码表](https://www.rfc-editor.org/rfc/rfc20.html#section-2)。

| ASCII 编码值 | 内容 |
| --- | --- |
| `0～31`、`127` | 控制字符 |
| `32` | 空格 |
| `33～47`、`58～64`、`91～96`、`123～126` | 常用标点与符号 |
| `48～57` | 数字字符 `0～9` |
| `65～90` | 大写字母 `A～Z` |
| `97～122` | 小写字母 `a～z` |

## char

`char` 是 `character` 的缩写，也是 C++ 的一种整型。一个 `char` 对象占用一个 C++ 字节。

编码文本由一串基本单位组成，每个单位称为**编码单元（code unit）**，单元的位数由具体编码规定。一个编码单元不一定能表示完整字符。`char` 可以用于承载这样的文本数据，但它本身只保存一个值，不附带文本采用哪种编码的信息。

下面的独立片段放在 `main` 函数体内，用一个 `char` 对象记录字母 `A`：

```cpp
char letter{'A'};
```

单引号包围的 `'A'` 是普通字符字面量（ordinary character literal），这里的类型是 `char`，为对象 `letter` 提供初值。普通字符字面量采用的编码由具体实现决定；在常见的 ASCII 兼容环境中，`'A'` 的值是 65，初始化后 `letter` 就保存这个值。

> [!IMPORTANT] 字符类型与编码约定
> **`char`、`signed char` 和 `unsigned char` 是三种不同的类型，每一种都占用一个 C++ 字节。**一个 `char` 保存的是该类型的值，不保存字符的形状，也不携带编码声明；把它用于文本时，字符含义取决于编码约定和程序语境。

一个 C++ 字节至少有 8 比特，具体位数由实现规定；普通 `char` 采用有符号还是无符号范围，也由实现决定。下表只列出采用 8 位字节时的数值范围，端点供核对：

| C++ 类型 | 采用 8 位字节时的表示范围 |
| --- | ---: |
| `char` | `−128～127` 或 `0～255`，由实现决定 |
| `signed char` | `−128～127` |
| `unsigned char` | `0～255` |

ASCII 编码值都位于 0 到 127，因此普通 `char` 无论采用哪种符号形式，都能表示这些编码值。需要处理超出该范围的字节数值时，应先核对目标实现的字节位数和 `char` 符号形式；默认选择也可能受工具链选项影响，例如 [GCC 的字符符号选项](https://gcc.gnu.org/onlinedocs/gcc/C-Dialect-Options.html)。范围相同也不会使 `char` 与另外两种类型变成同一种类型。

## Unicode 与 UTF-8

ASCII 足以表示基础英文字母、数字和符号，却无法容纳中文以及世界上其他书写系统。单纯增加更多比特只能扩大编号数量；如果不同系统仍然采用各自的字符映射，交换文本时依然可能得到不同结果。

Unicode（统一码）建立统一的**码点（code point）**空间，并为收录的抽象字符分配码点。码点是编号，例如 `A` 对应 `U+0041`，`中` 对应 `U+4E2D`。

`U+` 是码点的书写标记，后面使用十六进制编号。十六进制使用 `0～9` 和 `A～F` 作为数码，其中 `A～F` 表示十进制的 10 到 15。`U+0041` 对应十进制 65，`U+4E2D` 对应十进制 20013。这些写法用来识别码点，不要求逐个背诵编号。

同一个码点可以采用不同编码形式写入存储。**UTF-8（8-bit Unicode Transformation Format，8 位 Unicode 转换格式）**是 Unicode 定义的一种编码形式，以 8 比特为一个编码单元，用 1 到 4 个单元表示一个可编码的码点。它完整保留 ASCII：码点 0 到 127 仍然编码为相同数值的单个单元。

在采用 8 位字节的实现中，一个 UTF-8 编码单元恰好占一个字节。下表只计算字符的编码内容，每组 8 位是一个编码单元；具体比特组合供核对，关键是分清码点编号与编码后的序列：

| 字符与码点 | UTF-8 编码单元的比特组合 | 存储字节数（8 位字节） |
| --- | --- | ---: |
| `A`：`U+0041` | `01000001` | 1 |
| `中`：`U+4E2D` | `11100100` `10111000` `10101101` | 3 |

`A` 的 UTF-8 编码只有一个单元，可以由一个 `char` 对象承载。`中` 的编码有三个单元，需要三个字节共同表示；单独取出其中一个字节，不能得到完整的 `中`。这里展示的是字节的比特组合：普通 `char` 若采用有符号形式，其中一些组合对应的 `char` 数值会是负数，但文本仍按 UTF-8 的规则解释这些位。

“人看到的一个字符”与码点数量也可能不同。例如，字母 `e`（`U+0065`）后接组合尖音符（`U+0301`），通常显示为 `é`，读者把它看作一个带重音的字母，但这个序列包含两个码点。这种按阅读感知识别的文字单位称为**用户感知字符（user-perceived character）**。

> [!IMPORTANT] 码点、编码单元与字节的关系
> **码点是编号，编码单元组成具体编码的表示，字节是 C++ 的存储计量单位。**在采用 8 位字节的实现中，一个 UTF-8 编码单元占一个字节；一个码点可能需要多个单元，一个用户感知字符也可能包含多个码点。
>
> 因此，UTF-8 文本中的一个 `char` 承载一个编码单元时，不保证对应完整码点，也不保证对应完整的用户感知字符。字节数、码点数与用户感知字符数需要分别判断。

## 其他字符类型

C++23 还提供 `wchar_t`、`char8_t`、`char16_t` 和 `char32_t` 等内建字符类型。下面按编码单元和接口用途列出查阅入口；接口要求这些类型时，应核对相应编码和目标实现的存储大小：

| 类型 | 编码单元或接口用途 |
| --- | --- |
| `char8_t` | 表达 UTF-8 的 8 位编码单元，是独立于 `char` 的类型 |
| `char16_t` | 表达 UTF-16 的 16 位编码单元 |
| `char32_t` | 表达 UTF-32 的 32 位编码单元 |
| `wchar_t` | 用于宽字符接口；大小由实现决定，所用编码需按具体接口核对 |

UTF-16、UTF-32 与 UTF-8 都属于 Unicode 的编码形式，采用不同的编码规则与单元宽度。类型名和单元宽度都不能保证“一个对象恰好对应一个用户感知字符”；选择类型时，需要同时看编码规则与接口约定。
