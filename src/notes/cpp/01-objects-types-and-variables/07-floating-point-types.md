# 浮点类型（Floating-Point Types）

整数类型适合表示图形数量，而绘图程序还可能需要记录 `2.4` 这样的圆半径。C++ 提供 `float`、`double` 和 `long double` 三种标准浮点类型（floating-point type），用于表示带有小数部分或跨越较大数量级的数值。

下面的片段放在 `main` 函数体内，用 `radius` 保存以绘图单位计量的半径：

```cpp
double radius{2.4};
```

## 范围与精度

浮点类型只有有限数量的比特组合，因此只能表示有限个离散数值。**表示范围（range）**涉及能够达到多大的有限值、能够表示多小的非零值；**表示精度（precision）**涉及某个数量级上能区分多细微的差别，通常用有效位数说明。

例如，一个十进制数值模型只保留三位**有效数字（significant digits）**，但允许把整组数字按十的幂放大或缩小。`1.23` 和 `1230` 使用的有效数字都是 `1`、`2`、`3`，后者末尾的 `0` 来自整体放大，而不是新增的精度。在不同数量级上，相邻可表示值的间隔也会不同：

| 数值所在区域 | 相邻可表示值 | 间隔 |
| --- | --- | ---: |
| `1` 附近 | `1.23`、`1.24` | `0.01` |
| `1000` 附近 | `1230`、`1240` | `10` |

`1231` 位于 `1230` 和 `1240` 之间。即使它没有超出这个模型覆盖的范围，也没有精确对应的可表示值。这是说明精度的十进制模型；C++ 类型具体能表示哪些数值，还要由实际浮点格式决定。

> [!IMPORTANT] 范围与精度约束不同的问题
> **范围决定所需数量级能否被覆盖，精度决定在该数量级上能区分多细的变化。**数值没有超出范围，仍可能无法精确表示；有效精度也不等于小数点后固定保留多少位。

## 可表示值与舍入

主流实现通常采用二进制浮点表示。`2.5` 可以写成有限长度的二进制小数，`2.4`、`0.1` 则不能。将不能直接表示的数值转换为附近的可表示值，称为**舍入（rounding）**。

回到开头的半径。下面假设 `double` 使用 IEEE 754 的 binary64（64 位二进制浮点格式），并把这里的十进制写法转换为最近的可表示值。在这一前提下，`radius` 保存的值与数学上的 `2.4` 并不完全相同：

| 希望保存的半径 | 对象实际保存的值 | 是否精确 |
| --- | --- | --- |
| `2.4` | 十进制展开以 `2.39999999999999991118…` 开头 | 否，保存的是附近的可表示值 |
| `2.5` | `2.5` | 是，可以精确表示 |

表中的长尾数只用于显示差别，不需要逐位记忆。`radius` 初始化后保存的就是第一行的可表示值；即使显示时只看到较短的 `2.4`，也不能据此认定存储值与数学上的 `2.4` 完全相等。

浮点运算还可能再次舍入：运算结果即使仍在有限表示范围内，也可能落在两个可表示值之间，需要转换为相应类型能够保存的值。

> [!IMPORTANT] 对象保存可表示值，转换与计算可能舍入
> **浮点对象保存的是该类型能够表示的值。**在常见二进制实现中，部分十进制小数可以精确表示，另一些只能近似表示；初始化和后续计算都可能发生舍入。因此，判断计算是否满足需求，需要同时考虑范围、精度和舍入，而不能仅凭源代码中的十进制写法判断实际值。

## 零、无穷与 NaN

IEEE 754 浮点算术标准规定了广泛采用的浮点格式与运算规则。采用这些格式的常见实现，除了普通有限数，还能表示带符号的零、无穷和 NaN。辨认这些类别时，需要区分：

| 类别 | 包含的表示或含义 |
| --- | --- |
| 有限值 | 普通有限数，以及正零、负零；零仍然属于有限值 |
| 无穷 | 正无穷与负无穷，不是某个特别大的有限数 |
| NaN（Not a Number，非数） | 不表示某个实数数值的一类表示 |

这些类别可以出现在同一种浮点类型中，不是另外几种 C++ 类型。具体支持仍取决于实现采用的格式；能够表示无穷，也不能据此认定所有超出范围的表达式都会自动得到无穷。

## 标准保证与实现规格

> [!IMPORTANT] 三种标准浮点类型的保证
> **C++ 保证 `double` 的精度至少不低于 `float`，`long double` 的精度至少不低于 `double`，可表示值的集合依次包含。**这允许两种类型具有相同的精度；三种标准类型的具体存储大小、表示方式和运算精度仍由实现规定。
>
> 存储大小与有效精度是不同的规格，不能把对象占用的存储位数直接当作有效精度。

下面选取 Windows 的 MSVC x64 和 Linux 的 GCC x86-64 默认配置作为实例，均采用 8 位字节。表中的大小、精度和最大有限值供比较与查阅，不必逐项记忆；需要依赖它们处理外部格式或满足误差要求时，应先核对 [Microsoft 的类型规格](https://learn.microsoft.com/en-us/cpp/cpp/data-type-ranges?view=msvc-170)或 [GCC 的 x86 目标配置](https://gcc.gnu.org/onlinedocs/gcc/x86-Options.html)。

| C++ 类型 | 实现配置 | 对象大小 | 二进制有效精度 | 最大有限值（约） |
| --- | --- | ---: | ---: | ---: |
| `float` | 上述两种配置 | 4 字节 | 24 位 | $3.40\times10^{38}$ |
| `double` | 上述两种配置 | 8 字节 | 53 位 | $1.80\times10^{308}$ |
| `long double` | MSVC x64 / Windows | 8 字节 | 53 位 | $1.80\times10^{308}$ |
| `long double` | GCC x86-64 / Linux 默认配置 | 16 字节 | 64 位 | $1.19\times10^{4932}$ |

表中的 `float`、`double` 分别采用 binary32、binary64 格式。MSVC 示例中的 `long double` 与 `double` 使用相同格式；GCC 示例中的 `long double` 使用 x87 的 80 位扩展格式，存储时填充到 16 字节。**对象占用的存储位数不能直接当作有效精度。**其他工具链或编译选项可能采用不同格式，不能只凭操作系统或类型名称推断规格。

24、53、64 位二进制有效精度，大致对应 7、16、19 位十进制有效数字。这些约数便于比较，不保证任意具有相应位数的十进制数都能被精确保存，也不是固定小数位数或统一的往返转换保证。表中只列出最大有限值；涉及极小数时，还需核对最小正值和接近零时的精度。

## 类型选择

> [!PRACTICE] 根据精度与接口要求选择类型
> 一般浮点计算通常优先使用 `double`，它在主流实现中比 `float` 提供更高精度。存储空间、内存带宽、硬件接口或既有数据格式提出明确约束时，可以考虑 `float`；选择 `long double` 前，则要核实目标实现是否确实提供了所需的额外范围或精度。

例如，绘图程序需要在较大的坐标值附近区分很小的位移时，只确认坐标没有超出最大有限值还不够；还要确认该数量级上的精度足以保留这次变化。

若要理解二进制小数怎样形成、`0.1` 为什么通常只能保存为近似值，可继续看附章中的[二进制浮点表示](deep-dives/01-binary-floating-point-representation.md#二进制浮点表示)与[为什么 0.1 无法被精确表示](deep-dives/01-binary-floating-point-representation.md#为什么-01-无法被精确表示)。

需要查看 IEEE 754 的字段组织或辨认特殊值时，分别查阅[位结构](deep-dives/01-binary-floating-point-representation.md#binary32-与-binary64-的位结构)与[数值分类](deep-dives/01-binary-floating-point-representation.md#ieee-754-的数值分类)。
