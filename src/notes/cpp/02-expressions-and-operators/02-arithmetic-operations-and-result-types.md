# 算术运算与结果类型（Arithmetic Operations and Result Types）

把七个图形平均分成三组，按整数计数，每组分到两个，还剩一个；把一段长度分成三等份，则可能需要带小数的结果。C++ 的算术运算不仅取决于运算符，还取决于参与运算的类型。

以下代码片段各自独立，均放在 `main` 函数体内。示例主要使用 `int` 和 `double`，计算结果用于初始化新对象，不会自动写回参与运算的原对象。

## 一元算术运算符

一元 `+` 与一元 `-` 都只使用一个操作数。先用已经熟悉的 `int` 观察它们的结果：

```cpp
int adjustment{3};

int unchanged{+adjustment}; // 3
int opposite{-adjustment};  // -3
```

在这个示例中，一元 `+` 产生相同的数值，一元 `-` 产生相反数；二者都不修改 `adjustment`，结果类型仍是 `int`。执行后，`adjustment` 仍为 `3`，新对象 `unchanged` 为 `3`，`opposite` 为 `-3`。

相反数也必须能由运算类型表示。有符号整数的负数一侧比正数一侧多一个值，因此 `int` 的最小值没有可由 `int` 表示的正相反数。对它使用一元 `-`，会产生未定义行为（undefined behavior），不能依赖结果回绕。

## 二元算术运算符

二元算术运算符使用两个操作数计算结果。下表用于按符号查阅基本运算，其中的整数结果都在 `int` 范围内：

| 运算符 | 运算 | 示例 | 结果 |
| --- | --- | --- | --- |
| `+` | 加法 | `8 + 4` | `12` |
| `-` | 减法 | `8 - 4` | `4` |
| `*` | 乘法 | `8 * 4` | `32` |
| `/` | 除法 | `8 / 4` | `2` |
| `%` | 取余 | `8 % 3` | `2` |

`+`、`-`、`*` 和 `/` 可以用于整数类型与浮点类型。`%` 只接受整数类型操作数，用于取得整数除法的余数。

## 运算先于结果的使用位置

图形数量记录为 `3`，准备新增 `1` 个图形。先计算新增后的数量：

```cpp
int shape_count{3};
int added_count{1};
int next_count{shape_count + added_count};
```

`shape_count` 与 `added_count` 分别提供 `int` 值 `3`、`1`，加法产生 `int` 值 `4`，用于初始化 `next_count`。原来的两个对象仍分别保存 `3` 和 `1`。

> [!IMPORTANT] 运算类型与接收结果的类型
> **算术表达式根据操作数及相应的类型转换规则确定运算类型，再按该类型的规则求得结果。**初始化或赋值随后使用这个结果；接收对象的类型不能反向决定前面的运算采用整数还是浮点规则。

这里两个 `int` 值相加，结果为 `int`；两个 `double` 值相加，结果则为 `double`。不同算术类型共同参与同一次运算时，需要先确定共同类型，具体规则见[通常算术转换](03-usual-arithmetic-conversions.md#转换的是参与运算的值)。

## 整数除法

当 `/` 的两个操作数在算术转换后采用整数类型时，执行整数除法：

```cpp
int positive_quotient{7 / 3};  // 2
int negative_quotient{-7 / 3}; // -2
```

> [!IMPORTANT] 整数除法向零截断
> **整数除法丢弃数学商的小数部分，结果向零截断（truncation towards zero）。**`7 / 3` 得到 `2`，`-7 / 3` 得到 `-2`；后者没有向下取成 `-3`，也不是按四舍五入选择结果。

数学上的 `-7 / 3` 约为 `-2.333…`。向零截断保留整数部分 `-2`，因此负数例子能够区分向零截断与向下取整。

要看清类型在哪一步影响结果，可以保持接收对象都是 `double`，只改变参与除法的表达式：

```cpp
double integer_result{7 / 3};      // 整数除法后转换，保存 2.0
double floating_result{7.0 / 3.0}; // 采用 double 除法
```

第一行的 `7`、`3` 都是 `int` 值。`7 / 3` 先产生整数 `2`，初始化时再转换为 `double` 值 `2.0`。小数部分已经在整数除法中丢失，存入浮点对象无法恢复它。

第二行的 `7.0`、`3.0` 是 `double` 值，因此执行浮点除法。在常见的二进制浮点实现中，结果是 `2.333…` 附近的可表示值；这仍不意味着可以精确保存无限循环的小数。两行的区别来自除法所用的操作数类型。

## 取余

`%` 得到整数除法的余数（remainder）。把七个图形分成三组，每组两个，剩下的一个就是余数。

用 `a` 表示被除数、`b` 表示除数，则 `a / b` 是整数商，`a % b` 是余数。**除数不为零，并且商能由结果类型表示时，商乘以除数，再加余数，能够还原被除数：**

```text
(a / b) * b + a % b == a
```

这里的 `==` 表示相等判断，整条关系说明左侧与被除数 `a` 相等。代入正、负被除数，可以得到：

- `7 / 3` 得到商 `2`，余数为 `7 - 2 × 3 = 1`。
- `-7 / 3` 向零截断得到商 `-2`，余数为 `-7 - (-2) × 3 = -1`。

对应的 C++ 写法是：

```cpp
int positive_remainder{7 % 3};  // 1
int negative_remainder{-7 % 3}; // -1
```

> [!IMPORTANT] 商与余数的关系
> **除数非零且整数商可表示时，商 × 除数 + 余数 = 被除数。对于有符号整数，非零余数与被除数同号。**这套余数规则与商向零截断相配套；余数不是一律为正，除数的符号也不能单独决定余数的符号。

## 除法与取余的失败边界

> [!IMPORTANT] 除法与取余的有效条件
> **C++23 核心语言要求 `/`、`%` 的除数非零；执行整数除法或取余时，数学商还必须能由结果类型表示。**违反这些条件会产生未定义行为，不能把结果当作一次普通的近似计算。

典型的范围边界是有符号整数类型的最小值除以 `-1`。其数学商正是最小值的相反数，超出了该类型的正数范围；这与前面最小值不能直接取相反数是同一个限制。**即使只求这个最小值除以 `-1` 的余数，也不能忽略整数商是否可表示。**

某些硬件或浮点环境会规定除零得到无穷等结果，但这依赖具体实现与环境，不能替代这里的普遍语言边界。执行除法或取余之前，应当已通过输入约束或判断保证除数与结果范围有效。

## 有符号整数溢出与无符号算术

整数类型的范围直接约束算术表达式。若两个 `int` 操作数执行加法，检查的是这次 `int` 运算能否表示数学结果；接收结果的对象具有更大范围，也不能补救已经发生的运算越界。

> [!IMPORTANT] 运算边界取决于实际运算类型
> **判断整数加、减、乘时，先确定实际执行运算的类型，再检查该类型的规则：**
>
> - 有符号类型不能表示数学结果时，行为未定义，不能依赖回绕。
> - 无符号类型采用以 $2^N$ 为模的运算，$N$ 是该运算类型的位宽。
>
> 运算符不会因为结果可能超出范围，就自动改用更大的类型；接收对象的类型也不会反向扩大前面的运算范围。

无符号模规则与位宽的关系见[无符号算术与模运算](../01-objects-types-and-variables/04-integer-types.md#无符号算术与模运算)。除法与取余仍需另外满足前面的非零及表示范围条件。

### 其他整数类型的一元运算

一元 `+` 与一元 `-` 也需要先确定运算类型。整数操作数会先执行[整数提升](03-usual-arithmetic-conversions.md#整数提升integral-promotions)，因此 `char`、`short` 等较小整数的结果类型不一定仍是源类型。这里检查的是提升后类型的范围，不能只看源对象的类型。

提升后的类型为无符号整数时，一元 `-` 按该类型计算 `0` 减去操作数，并采用无符号模运算，结果仍是无符号整数。提升后的类型为有符号整数时，数学上的相反数必须能由该类型表示，否则行为未定义。

## 浮点运算与舍入

浮点类型只表示有限个离散值。即使操作数能够精确保存，运算的精确数学结果也可能无法表示，需要舍入到某个可表示值。

例如，程序计算一个较大横向坐标向右移动 `0.5` 个绘图单位后的新坐标，再根据两个坐标计算记录下来的位移。**本例假设 `double` 采用 IEEE 754 的 binary64 格式，相关运算与存储都按 binary64 精度就近舍入，不保留额外中间精度：**

```cpp
double position{10000000000000000.0};
double movement{0.5};

double moved_position{position + movement};
double recorded_movement{moved_position - position};
```

在上述前提下：

| 对象 | 保存的值 |
| --- | ---: |
| `position` | `10000000000000000.0` |
| `movement` | `0.5` |
| `moved_position` | `10000000000000000.0` |
| `recorded_movement` | `0.0` |

在这段坐标附近，相邻 binary64 可表示值的间隔为 `2`。数学上的新坐标比原坐标大 `0.5`，无法精确表示，又更接近原坐标，因此舍入回原来的值。随后相减时，两个对象已经保存相同的坐标值，结果只能是 `0.0`，无法恢复原本的 `0.5` 位移。

> [!IMPORTANT] 浮点运算可能逐步舍入
> **操作数可以精确表示，不保证运算的数学结果也能精确表示。运算结果可能发生舍入，后续运算使用的是已经得到的值。**不能把中间运算一律当作无限精度，也不能指望最终接收结果的对象自动恢复此前丢失的信息。

这个例子没有超出数值范围，丢失的是较大坐标附近的小变化。判断浮点计算能否满足需求，既要检查范围，也要检查所需精度与运算中的舍入。

C++ 允许浮点表达式采用更高的中间精度，具体表示与运算精度也依赖实现。因此，上表描述的是已限定的 binary64 求值环境，其他环境中的具体结果应按对应实现与编译配置核对。

浮点加减法怎样对齐指数、乘除法怎样组合有效数与指数、舍入怎样选择相邻可表示值，以及较小数值为何可能被吸收，参见附章：[浮点运算、舍入与误差（Floating-Point Arithmetic, Rounding, and Error）](deep-dives/01-floating-point-arithmetic-and-error.md#浮点运算与误差)。
