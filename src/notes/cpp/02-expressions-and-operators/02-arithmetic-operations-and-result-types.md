# 算术运算与结果类型（Arithmetic Operations and Result Types）

算术运算符使用数值操作数计算新的数值结果。运算符看起来与数学符号相似，但 C++ 中的数值始终具有类型；**操作数类型会参与决定采用哪一种运算规则、结果具有什么类型，以及哪些边界不能越过。**

## 一元算术运算符

本节只讨论一元 `+` 与一元 `-` 作用于算术类型的情形。两者都只使用一个操作数：

```cpp
int adjustment{3};

int unchanged{+adjustment};  // 3
int opposite{-adjustment};   // -3
```

在这个 `int` 示例中，一元 `+` 保留数值，一元 `-` 产生相反数。整数操作数在参与这两个运算符前会先执行[整数提升](03-usual-arithmetic-conversions.md#整数提升integral-promotions)，因此 `char`、`short` 等较小整数的结果类型不一定仍是源类型。

如果提升后的结果类型是无符号整数，一元 `-` 按该类型计算 `0` 减去操作数，并采用无符号模运算；结果不会因此变成负数。如果结果类型是有符号整数，而数学上的相反数无法表示，行为未定义。典型边界是对该类型的最小可表示值应用一元 `-`。

## 二元算术运算符

本章使用五种基本二元算术运算符：

| 运算符 | 运算 | 示例 | 结果 |
| --- | --- | --- | --- |
| `+` | 加法 | `8 + 4` | `12` |
| `-` | 减法 | `8 - 4` | `4` |
| `*` | 乘法 | `8 * 4` | `32` |
| `/` | 除法 | `8 / 4` | `2` |
| `%` | 取余 | `8 % 3` | `2` |

`+`、`-`、`*` 和 `/` 可以用于整数类型与浮点类型。`%` 只接受整数类型操作数，用于取得整数除法的余数。

## 运算先于结果的使用位置

下面的加法使用两个 `int` 对象：

```cpp
int front_count{2};
int rear_count{2};
int wheel_count{front_count + rear_count};
```

求值 `front_count + rear_count` 时，两个名称表达式分别提供 `int` 值 `2`，加法产生 `int` 值 `4`，这个结果才用于初始化 `wheel_count`。

相同原则也适用于浮点运算：

```cpp
double front_pressure{2.5};
double rear_pressure{2.75};
double total_pressure{front_pressure + rear_pressure};
```

这里的两个操作数采用 `double`，加法结果也是 `double`。**表达式先根据操作数和运算符完成求值，初始化器或赋值目标随后才使用结果；接收结果的对象不能反向决定前面的运算采用整数还是浮点规则。**

不同算术类型共同参与同一次运算时，需要先确定共同类型；这套规则见[通常算术转换](03-usual-arithmetic-conversions.md)。

## 整数除法

当 `/` 的两个操作数在算术转换后采用整数类型时，执行整数除法：

```cpp
int positive_quotient{7 / 3};   // 2
int negative_quotient{-7 / 3};  // -2
```

**整数除法的数学商如果带有小数部分，结果向零截断（truncation towards zero），不是向下取整，也不是四舍五入。**因此 `7 / 3` 得到 `2`，`-7 / 3` 得到 `-2`。

小数部分一旦在整数除法中丢失，之后再把结果存入浮点对象，也不能恢复原来的数学商。是否执行整数除法，在 `/` 求值时就已经由操作数类型确定。

## 取余

运算符 `%` 得到同一次整数除法的余数。当商能够由结果类型表示时，商与余数满足：

```text
(a / b) * b + a % b == a
```

```cpp
int positive_remainder{7 % 3};   // 1
int negative_remainder{-7 % 3};  // -1
```

对于有符号整数，非零余数与被除数具有相同符号。因此 `-7 / 3` 得到 `-2`，相应的 `-7 % 3` 得到 `-1`，二者仍满足前面的关系。

## 除法与取余的失败边界

**`/` 的第二操作数为零时，C++23 核心语言规定行为未定义（undefined behavior）；只适用于整数的 `%` 也具有相同边界。**常见硬件或浮点环境可能表现出无穷等结果，但这不是这里可以依赖的普遍语言保证。

此外，如果整数除法的数学商无法由结果类型表示，`/` 与 `%` 同样产生未定义行为；典型边界是某个有符号整数类型的最小值除以 `-1`。

这些情况不是“得到一个不准确的结果”，而是语言不再规定程序必须怎样表现。执行除法或取余之前，程序必须已经通过输入约束或判断保证除数与结果范围有效。

## 有符号整数溢出与无符号算术

第一章已经区分两类整数边界：

- 有符号整数运算的数学结果超出结果类型范围时，行为未定义；
- 无符号整数按照该类型可表示值数量进行模运算，跨越端点时得到确定结果。

这些规则直接约束算术表达式。**运算符不会自动扩大结果类型，也不会因为赋值目标具有更大范围，就先在更大类型中完成运算。**如果两个 `int` 操作数执行加法，数学结果必须能由这次运算采用的 `int` 类型表示。

## 浮点运算与舍入

浮点算术同样先依据操作数类型完成求值。由于浮点类型只表示有限个离散值，精确数学结果不一定能够由结果类型表示，运算过程中可能发生舍入。

**每一步浮点运算都可能需要把精确数学结果映射为相应类型允许的可表示值；不能把舍入理解成只在最终存入对象时统一发生一次。**连续多次运算可能连续产生误差，运算顺序也可能影响最终可表示值。

浮点加减法怎样对齐指数、乘除法怎样组合有效数与指数、舍入怎样选择相邻可表示值，以及较小数值为何可能被吸收，参见附章：[浮点运算、舍入与误差（Floating-Point Arithmetic, Rounding, and Error）](deep-dives/01-floating-point-arithmetic-and-error.md)。

相关语言规则可参阅 C++23 工作草案中的[乘法类运算符](https://eel.is/c%2B%2Bdraft/expr.mul)与[加法类运算符](https://eel.is/c%2B%2Bdraft/expr.add)。
