# 表达式的分组与求值（Expression Grouping and Evaluation）

## 子表达式与括号

表达式可以作为另一个表达式的操作数，由此逐层组成更大的表达式：

```cpp
int result{2 + 3 * 4};
```

整个 `2 + 3 * 4` 是一个表达式，其中的 `3 * 4` 也是表达式。**包含在另一个表达式中的表达式称为子表达式（subexpression）。**

括号可以明确指定某一部分构成独立的子表达式：

```cpp
int first{2 + (3 * 4)};   // 14
int second{(2 + 3) * 4};  // 20
```

第一种写法将 `3 * 4` 作为加法的右操作数；第二种写法则让 `2 + 3` 的结果成为乘法的左操作数。**括号由此改变了整个表达式的语法分组。**

被括号包围的表达式仍然具有原表达式的类型和结果：

```cpp
int value{3};
bool positive{(value > 0)};
```

`(value > 0)` 与 `value > 0` 都产生相同的 `bool` 结果。**括号本身不会执行类型转换，也不会修改表达式的值。**

**括号决定表达式怎样分组，但不能单独用来推断不同子表达式在运行时的求值顺序。**求值顺序由各运算符的语言规则另行规定。相关规则可参阅 [C++ 工作草案中的括号表达式](https://eel.is/c%2B%2Bdraft/expr.prim.paren)。

## 运算符优先级与结合性（Operator Precedence and Associativity）

表达式没有使用括号明确分组时，运算符优先级（operator precedence）决定不同运算符怎样组成子表达式；优先级相同时，结合性（associativity）决定分组方向。下表只列出本章已经涉及的运算符，并按优先级由高到低排列。

| 优先级 | 运算符 | 结合性 |
|---:|---|---|
| 1 | 后置 `value++`、`value--` | 从左向右 |
| 2 | 前置 `++value`、`--value`、一元 `+`、一元 `-`、`!` | 从右向左 |
| 3 | `*`、`/`、`%` | 从左向右 |
| 4 | 二元 `+`、二元 `-` | 从左向右 |
| 5 | `<`、`<=`、`>`、`>=` | 从左向右 |
| 6 | `==`、`!=` | 从左向右 |
| 7 | `&&` | 从左向右 |
| 8 | `\|\|` | 从左向右 |
| 9 | `=`、`+=`、`-=`、`*=`、`/=`、`%=` | 从右向左 |

**优先级和结合性描述语法分组，不等同于运行时求值顺序。**括号可以覆盖默认分组，也可以用于明确表达式结构。

## 表达式的可读性

**优先级表用于准确解释 C++ 怎样解析表达式，不应成为读者理解代码时必须反复查阅的前提。**常见的算术与逻辑关系可以直接使用其自然分组；当表达式混合不同类别的运算符、默认分组容易误读，或者括号能够呈现业务条件的边界时，即使语法上并不需要，也适合显式写出括号。

```cpp
bool inside{
    (position >= 0) && (position < limit)
};
```

这里的括号没有改变默认分组，但清楚表明 `&&` 组合的是两个完整判断。反过来，给每个简单操作数和子表达式机械增加括号，也会制造视觉噪声。

括号能够澄清结构，却不能挽救本身承担了太多工作的表达式。如果阅读一段代码需要同时追踪多次状态修改、数值转换和许多层分组，应将它拆成具有明确含义的步骤；简单而自然的计算也不必机械拆成“一条语句只允许一个运算符”。**表达式是否容易直接理解，比括号数量或运算符数量更重要。**这与 [C++ Core Guidelines ES.40](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#es40-avoid-complicated-expressions) 和 [ES.41](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#es41-if-in-doubt-about-operator-precedence-parenthesize) 的建议一致。
