# 表达式结构与求值顺序（Expression Structure and Evaluation Order）

一个表达式可以成为另一个表达式的操作数，由此逐层形成更大的结构。正确阅读复合表达式需要分别回答两个问题：源代码怎样组成子表达式，以及这些子表达式在运行时具有什么求值顺序。

## 子表达式（Subexpression）

```cpp
int result{2 + 3 * 4};
```

整个 `2 + 3 * 4` 是表达式，其中的 `3 * 4` 也是表达式。**包含在另一个表达式中的表达式称为子表达式（subexpression）。**

运算符把子表达式的结果继续组合起来：在语法结构中，`3 * 4` 构成加法的右操作数。

## 括号与语法分组

括号可以明确指定哪一部分构成独立子表达式：

```cpp
int first{2 + (3 * 4)};   // 14
int second{(2 + 3) * 4};  // 20
```

第一行让 `3 * 4` 成为加法的右操作数；第二行让 `2 + 3` 的结果成为乘法的左操作数。**括号改变或明确的是表达式的语法分组。**

被括号包围的表达式仍然保留自身类型与结果。括号不会执行类型转换，也不会自动创建新的对象。

## 运算符优先级与结合性（Operator Precedence and Associativity）

没有使用括号明确分组时，运算符优先级（operator precedence）决定不同运算符怎样组成子表达式；优先级相同时，结合性（associativity）决定分组方向。

下表只列出本章已经建立的运算符，并按优先级由高到低排列：

| 优先级 | 运算符 | 结合性 |
| ---: | --- | --- |
| 1 | 后置 `value++`、`value--` | 从左向右 |
| 2 | 前置 `++value`、`--value`、一元 `+`、一元 `-`、`!` | 从右向左 |
| 3 | `*`、`/`、`%` | 从左向右 |
| 4 | 二元 `+`、二元 `-` | 从左向右 |
| 5 | `<`、`<=`、`>`、`>=` | 从左向右 |
| 6 | `==`、`!=` | 从左向右 |
| 7 | `&&` | 从左向右 |
| 8 | `\|\|` | 从左向右 |
| 9 | `=`、`+=`、`-=`、`*=`、`/=`、`%=` | 从右向左 |

例如，乘法优先级高于加法，因此：

```cpp
int result{2 + 3 * 4};
```

按照下面的结构分组：

```cpp
int result{2 + (3 * 4)};
```

结合性只在相关运算符处于同一优先级时决定分组。二元减法从左向右结合，因此 `10 - 3 - 2` 表示 `(10 - 3) - 2`；赋值从右向左结合，因此 `first = second = 0` 表示 `first = (second = 0)`。

**优先级与结合性是语法解析规则，不表示操作数一定按照相同方向求值。**“从左向右结合”不能被理解成“运行时一定先求值左操作数”。

## 连续比较不能表达数学区间

数学中可以写 $0 \leq position < limit$，但 C++ 的关系运算符不会把它解释成一个三方关系：

```cpp
int position{3};
int limit{5};

bool inside{0 <= position < limit};
```

关系运算符从左向右结合，因此表达式按照下面的结构分组：

```text
(0 <= position) < limit
```

`0 <= position` 先产生 `bool` 结果，随后 `false` 或 `true` 又以相应整数值参与第二次比较。它没有表达“`position` 同时不小于 `0` 且小于 `limit`”。

正确写法分别建立两个比较，再用逻辑与组合：

```cpp
int position{3};
int limit{5};

bool inside{
    (position >= 0) && (position < limit)
};
```

相等性比较也不能用 `first == second == third` 表示三个值彼此相等。它会先得到一个 `bool`，再把这个布尔结果与第三个操作数比较。每一项关系都应当成为独立比较表达式。

## 分组不等于求值顺序

表达式的语法树确定哪个结果成为哪个运算符的操作数，却不普遍规定兄弟子表达式谁先求值。除非相应运算符具有明确顺序规则，**不能只根据书写位置、优先级、结合性或括号推断操作数一定从左向右求值。**

`&&` 与 `||` 是本章已经建立的明确例外：它们保证先求值左操作数，并根据左侧结果决定是否求值右操作数。普通算术运算符则不能提供同样的短路或先后保证。

括号只改变分组：

```cpp
int left{2};
int right{3};
int scale{4};

int result{(left + right) * scale};
```

这里必须先得到 `left + right` 的结果，才能完成乘法；但括号本身并没有额外规定加法内部的 `left` 与 `right` 谁先求值。当操作数只是读取普通整数对象时，这种差异通常不可观察；一旦操作数包含副作用，顺序就可能影响正确性。

## 完整表达式与求值关系

完整表达式（full-expression）构成一次相对独立的求值边界。在当前已经出现的语法中，表达式语句中的表达式构成一个完整表达式；在单对象声明中，完成对象初始化的整个过程——包括求值初始化器及其子表达式——构成另一个完整表达式。

```cpp
int count{1};       // 初始化器 1 属于一个完整表达式
count += 2;         // count += 2 属于另一个完整表达式
int doubled{count * 2};
```

**前一个完整表达式的值计算与副作用全部先序于（sequenced before）下一个完整表达式的求值。**因此，第二行对 `count` 的修改会在第三行读取 `count` 之前完成。

同一完整表达式内部的子表达式不一定具有固定的求值次序。C++ 使用三种关系描述两项求值之间的约束：

| 求值关系 | 语言保证 |
| --- | --- |
| 先序于（sequenced before） | 前一项必须在后一项之前完成 |
| 顺序不定（indeterminately sequenced） | 两项必有先后，但标准不指定哪一项在前 |
| 未排序（unsequenced） | 两项之间没有先后保证，求值可以交错 |

在本章已经出现的运算符中，`&&` 与 `||` 保证左操作数先序于可能被求值的右操作数；赋值运算保证右操作数先序于左操作数。`+`、`-`、`*`、`/` 与 `%` 这类内建二元算术运算符的两个操作数彼此未排序。

## 同一表达式中的冲突副作用

如果对同一个数值对象的一次修改，与另一次修改或一次读取彼此未排序，程序的行为未定义。下面的加法没有规定两个操作数之间的求值顺序：

```cpp
int count{1};
int result{count++ + count};  // 未定义行为
```

一个操作数通过后置自增修改 `count`，另一个操作数读取 `count`；两项求值之间没有足以避免冲突的顺序关系。添加括号不能修复这个问题：

```cpp
int result{(count++) + count};  // 仍然是未定义行为
```

需要特定顺序时，应当把状态变化拆成独立步骤：

```cpp
int count{1};
int previous_count{count};

++count;
int result{previous_count + count};
```

这些求值分别位于不同的完整表达式中，先后边界清楚，代码不再依赖同一表达式内部未规定的顺序。

## 用结构直接表达意图

优先级表用于准确解释 C++ 怎样解析表达式，不应成为理解业务代码时必须反复推算的谜题。常见算术关系可以保留自然写法；当表达式混合不同类别的运算符、默认分组容易误读，或者括号能够呈现条件边界时，应明确写出括号。

括号也不能挽救承担了太多工作的表达式。如果读者必须同时追踪多次状态修改、类型转换和许多层分组，应使用具有含义的中间对象和独立语句拆分过程。**表达式结构应当帮助读者直接看见计算关系，而不是要求读者证明代码最终碰巧正确。**
