# 表达式结构与求值顺序（Expression Structure and Evaluation Order）

一个表达式可以成为另一个表达式的操作数，由此逐层形成更大的结构。正确阅读复合表达式需要分别回答两个问题：源代码怎样组成子表达式，以及这些子表达式在运行时具有什么求值顺序。

以下讨论本章已介绍的数值类型内建运算与顺序执行的语句。代码片段各自独立，均放在 `main` 函数体内；标明未定义行为的片段用于分析冲突，不用于取得可依赖的运行结果。

## 子表达式（Subexpression）

```cpp
int result{2 + 3 * 4};
```

> [!IMPORTANT] 子表达式提供外层运算需要的结果
> **包含在另一个表达式中的表达式称为子表达式（subexpression）。**运算符使用其操作数的结果，逐层组成更大的表达式；确定每一部分的作用，需要看它在整体中参与哪一次运算。

整个 `2 + 3 * 4` 是表达式，`2`、`3`、`4` 和 `3 * 4` 都是其中的子表达式。`3 * 4` 构成加法的右操作数，提供乘积 `12`；外层加法再把 `2` 与 `12` 相加，得到 `14`。

## 括号与语法分组

括号可以明确指定哪一部分构成独立子表达式：

```cpp
int first{2 + (3 * 4)};  // 14
int second{(2 + 3) * 4}; // 20
```

第一行让 `3 * 4` 成为加法的右操作数；第二行让 `2 + 3` 的结果成为乘法的左操作数。**括号改变或明确的是表达式的语法分组。**

被括号包围的表达式仍然保留自身类型与结果。括号不会执行类型转换，也不会自动创建新的对象。

## 运算符优先级与结合性（Operator Precedence and Associativity）

> [!IMPORTANT] 括号、优先级与结合性决定分组
> **括号直接指定分组；没有用括号明确分组时，运算符优先级（operator precedence）决定不同运算符怎样组成子表达式，结合性（associativity）决定同一优先级运算符的分组方向。**这些规则确定表达式的结构，不规定操作数必定按相同方向求值。

下表用于查阅本章已经建立的运算符，按优先级由高到低排列；序号只表示表内的相对次序。使用时核对需要的运算符即可，不必把整张表当成逐行背诵的任务。关系复杂或默认分组容易误读时，用括号直接说明分组。

| 优先级 | 运算符 | 结合性 |
| ---: | --- | --- |
| 1 | 后置 `value++`、`value--` | 从左向右 |
| 2 | 前置 `++value`、`--value`、一元 `+`、一元 `-`、`!` | 从右向左 |
| 3 | `*`、`/`、`%` | 从左向右 |
| 4 | 二元 `+`、二元 `-` | 从左向右 |
| 5 | `<`、`<=`、`>`、`>=` | 从左向右 |
| 6 | `==`、`!=` | 从左向右 |
| 7 | `&&` | 从左向右 |
| 8 | `\|\|` | 从左向右 |
| 9 | `=`、`+=`、`-=`、`*=`、`/=`、`%=` | 从右向左 |

例如，乘法优先级高于加法，因此：

```cpp
int result{2 + 3 * 4};
```

按照下面的结构分组：

```cpp
int result{2 + (3 * 4)};
```

结合性只在相关运算符处于同一优先级时决定分组。二元减法从左向右结合，因此 `10 - 3 - 2` 表示 `(10 - 3) - 2`，结果是 `5`；改成 `10 - (3 - 2)`，结果则为 `9`。

赋值从右向左结合，因此 `first = second = 0` 表示 `first = (second = 0)`：右侧赋值的结果继续供外层赋值使用。赋值运算本身还具有求值先后保证，这项语义与“怎样分组”需要分别判断。

## 连续比较不能表达数学区间

数学中可以写 $0 \leq position < limit$，但 C++ 的关系运算符不会把它解释成一个三方关系：

```cpp
int position{6};
int limit{5};

bool inside{0 <= position < limit}; // 逻辑错误：不能表达数学区间
```

关系运算符从左向右结合，因此表达式按照下面的结构分组：

```text
(0 <= position) < limit
```

`0 <= position` 先得到 `true`，这个 `bool` 结果提升为整数 `1`，第二次比较实际成为 `1 < 5`，最终得到 `true`。`position` 明明已经超出区间，错误写法却仍然把它判为区间内。它没有表达“`position` 同时不小于 `0` 且小于 `limit`”。

这是能够按 C++ 语法组成的表达式，但没有表达所需的区间条件；编译器可能对这种易错写法给出诊断。正确写法分别建立两个比较，再用逻辑与组合：

```cpp
int position{6};
int limit{5};

bool inside{(position >= 0) && (position < limit)};
```

这里的 `position >= 0` 为 `true`，`position < limit` 为 `false`，逻辑与最终得到 `false`，正确排除了区间外的 `6`。

> [!IMPORTANT] 区间判断分别比较后组合
> **每次比较都产生一个 `bool` 结果，连续写下多个比较运算符，会让这个布尔结果继续参与后一次比较。**表达区间条件时，应分别比较所需的上下界，再用逻辑与组合。
>
> 相等性比较同样不能用 `first == second == third` 表示三个值彼此相等；每一项所需关系都应独立比较后再组合。

## 分组不等于求值顺序

分组确定哪个结果供哪一次运算使用，求值顺序则涉及各项读取、计算和状态修改之间的先后。确定表达式指定的对象、读取对象保存的值、算出加法结果，都属于值计算；自增对对象的写入则是副作用。同一个子表达式中可以同时包含这两种动作。

> [!IMPORTANT] 值的依赖与求值先后分别判断
> **操作数的值计算先于运算符结果的值计算；这不意味着某个操作数的整项求值，包括全部副作用，都必须先于另一个操作数完成。**书写位置、括号、优先级和结合性，都不能代替运算符自身的求值顺序规则。

例如，加法结果成为乘法的一个操作数：

```cpp
int left{2};
int right{3};
int scale{4};

int result{(left + right) * scale};
```

这里的值依赖关系是：

| 需要得到的结果 | 依赖的值 |
| --- | --- |
| 加法结果 `5` | `left` 提供的 `2` 与 `right` 提供的 `3` |
| 乘法结果 `20` | 加法结果 `5` 与 `scale` 提供的 `4` |

先读取 `scale` 得到 `4`，再读取 `left` 和 `right`，最后完成加法与乘法，也符合这些依赖关系。括号没有要求必须先读取其中的对象，再读取括号外的 `scale`；它也没有规定 `left` 与 `right` 谁先读取。

这些操作只是读取普通整数对象，不论采用哪一种允许的读取次序，结果都是 `20`。操作数包含状态修改时，则还需要检查修改与其他读取、修改之间有没有足够的先后保证。

## 完整表达式与求值关系

完整表达式（full-expression）给出当前这些代码中的求值边界。在表达式语句中，整个表达式构成一个完整表达式；在这里的单对象声明中，完整表达式包含初始化器的求值、必要的转换以及完成对象初始化的过程。

```cpp
int count{1};
count += 2;
int doubled{count * 2};
```

这三行分别对应一次初始化、一个独立赋值表达式和另一次初始化。第一行使 `count` 保存 `1`；第二行把它更新为 `3`；第三行读取已经更新的 `3`，使 `doubled` 保存 `6`。

> [!IMPORTANT] 完整表达式建立先后边界
> **在这里顺序执行的代码中，前一个完整表达式的全部值计算与副作用，都在下一个完整表达式求值前完成。**因此，`count += 2` 的写入必须在随后初始化 `doubled` 时读取 `count` 之前完成。

### 三种求值关系

同一完整表达式内部，仍需要按具体规则判断先后。下面用 A、B 表示两项求值动作；先序于（sequenced before）表示其中一项必须在另一项之前完成：

> [!IMPORTANT] 三种求值关系的保证不同
> | 求值关系 | A、B 之间的保证 |
> | --- | --- |
> | A 先序于 B（sequenced before） | A 的求值完成之后，才进行 B |
> | 顺序不定（indeterminately sequenced） | A 完整完成后进行 B，或 B 完整完成后进行 A；不指定哪项在前，但两项不交错 |
> | 未排序（unsequenced） | 既没有 A 先序于 B 的保证，也没有 B 先序于 A 的保证；求值可以交错 |
>
> **顺序不定仍有整项求值的先后保证；未排序没有这种保证。**某次执行看起来先做了 A，再做了 B，不能据此认为语言保证 A 先序于 B。

本章内建 `&&` 与 `||` 保证左侧的值计算和副作用先于可能被求值的右侧；赋值与复合赋值保证右操作数先序于左操作数。普通 `+`、`-`、`*`、`/` 与 `%` 本身不提供这样的左右顺序保证。

未排序本身不等于未定义行为。两个独立对象可以分别提供旧值并完成自增：

```cpp
int left{2};
int right{3};

int result{left++ + right++};
```

左右操作数彼此未排序，但两个自增操作修改的是不同对象。加法使用的旧值分别为 `2`、`3`，因此 `result` 为 `5`；这条声明结束时，`left` 为 `3`，`right` 为 `4`。代码不需要依赖哪一侧先求值。

## 同一表达式中的冲突副作用

> [!IMPORTANT] 同一对象的未排序冲突导致未定义行为
> **对于这里的普通数值对象，如果一次修改与另一次修改，或与读取该对象所保存值的动作彼此未排序，行为未定义。**需要检查的是这些具体动作之间的关系，不能只根据一个名称在表达式中出现了几次判断。

下面这个独立片段中，加法没有为两个操作数建立先后保证：

```cpp
int count{1};
int result{count++ + count}; // 未定义行为：修改与读取彼此未排序
```

`count++` 提供修改前的值，同时还要把 `count` 增加 `1`。提供旧值的值计算，与修改对象的副作用是不同动作；冲突发生在这次修改与右侧 `count` 读取保存值的动作之间。后置形式没有让这两项动作建立先后保证。

下面是另一个独立版本。添加括号只明确分组，不能修复冲突：

```cpp
int count{1};
int result{(count++) + count}; // 仍然是未定义行为
```

编译器可能对这些冲突给出诊断。某次运行得到一个数值，也不能用来证明代码具有可依赖的结果。

如果所需含义是“保留旧数量，增加一个，再把旧值与新值相加”，可以把状态变化拆成独立步骤：

```cpp
int count{1};
int previous_count{count};

++count;
int result{previous_count + count};
```

初始化 `previous_count` 后，它保存旧值 `1`；`++count` 在独立语句中把 `count` 更新为 `2`；最后用 `1 + 2` 初始化 `result`，得到 `3`。完整表达式之间的先后边界保证后续读取发生在更新完成之后。

这段代码表达了一个明确选定的计算意图；它没有为前面具有未定义行为的代码补出某个唯一结果。

### 同一完整表达式内部也可以有先后保证

已建立的 `&&` 可以在同一个完整表达式内部规定先后：

```cpp
int count{1};

bool accepted{(count++ > 0) && (count > 1)};
```

左侧先用旧值 `1` 完成 `1 > 0`，得到 `true`。在右侧开始求值前，左侧包含的自增副作用必须完成，因此右侧读取的 `count` 已是 `2`，`2 > 1` 为 `true`。最后 `accepted` 为 `true`，`count` 为 `2`。

这里的修改与后续读取具有先后保证，不构成前面加法中的未排序冲突。保证来自 `&&` 的语义，括号只是明确两个比较怎样组合；并非只有把操作拆成多个语句，才能获得求值顺序保证。

## 用结构直接表达意图

优先级表用于准确解释 C++ 怎样解析表达式，不应成为理解业务代码时必须反复推算的谜题。常见算术关系可以保留自然写法；当表达式混合不同类别的运算符、默认分组容易误读，或者括号能够呈现条件边界时，应明确写出括号。

> [!PRACTICE] 让分组与状态变化直接可见
> 表达式混合多次状态修改、类型转换和多层分组时，使用有含义的中间对象与独立语句拆分过程。括号表达分组，明确的语句边界表达所需步骤；结构应让计算关系容易核对，减少反复推演副作用的负担。
