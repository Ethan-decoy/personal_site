# 块作用域与名称查找（Block Scope and Name Lookup）

用 `shape_count` 记录图形数量，可以通过这个名称修改相应对象：

以下代码片段各自独立，均放在 `main` 函数体内；各示例的外围没有其他同名声明。

```cpp
{
    int shape_count{3};
    shape_count += 1;
}
```

编译器根据名称在源代码中的使用位置，确定它对应哪条声明，这个过程称为名称查找（name lookup）。这里，`shape_count += 1` 中的名称找到 `int shape_count{3};` 这条声明，因而指定由它定义的对象。执行复合赋值时，这个对象的值从 `3` 变为 `4`。

## 块作用域（Block Scope）

> [!IMPORTANT] 名称查找与块作用域
> **名称查找确定名称的使用对应哪条声明；作用域（scope）描述声明能够在源代码的哪些区域参与查找。复合语句引入覆盖该代码块的块作用域（block scope）。**名称的拼写相同，不保证它在不同位置都能找到同一条声明。

上面的 `shape_count` 声明属于包围它的代码块的块作用域。在这个简单示例中，从声明生效的位置开始，到代码块结束，普通的 `shape_count` 使用都能找到它。

把名称写到声明之前或这个代码块之后，就会出现下面两处编译错误：

```cpp
{
    shape_count += 1; // 错误：这里还找不到 shape_count 的声明

    int shape_count{3};
    shape_count += 1; // 正确：找到上面的声明
}

shape_count += 1; // 错误：这个位置找不到内层代码块中的声明
```

两处错误都是编译期的名称查找失败：在对应的使用位置找不到声明。源文件其他位置出现过同名声明，并不保证当前代码能够使用它。

## 声明的生效位置

声明的生效位置是源代码中的边界，决定从哪里开始可以查找到这条声明；初始化描述执行过程中怎样建立对象的初始状态。

以 `int shape_count{3};` 为例，生效位置在变量名 `shape_count` 之后、初始化器 `{3}` 之前，并不需要等到末尾的分号。

> [!IMPORTANT] 声明生效与初始化完成
> **对于这里的简单变量声明，名称在变量名之后、初始化器之前已经生效。名称能够被查找到，只说明查找选中了相应声明，不保证这个声明所定义的对象已经完成初始化。**

因此，初始化器中如果出现同名变量名，也要依据这个生效位置判断它对应哪条声明。名称查找按源代码位置确定声明；执行到相应定义时，再按照初始化规则建立对象的初始状态。

## 嵌套作用域中的名称查找

内层代码块可以使用外层声明的变量。下面先从总数中减去本次删除的数量，离开内层后，再增加一个图形：

```cpp
{
    int shape_count{3};

    {
        int removed_count{1};
        shape_count -= removed_count;
    }

    shape_count += 1;
}
```

> [!IMPORTANT] 名称查找由内向外进行
> **对于这里的普通变量名，先查找当前最内层块作用域中在该位置已生效的同名声明；找不到才向外层作用域继续，找到后就停止向外查找。**外层的查找也不会进入内层代码块寻找声明。

在 `shape_count -= removed_count` 中，两个名称的查找过程分别是：

| 使用的名称 | 内层的查找结果 | 最终选中的声明 |
| --- | --- | --- |
| `shape_count` | 没有已生效的同名声明，向外查找 | 外层的 `int shape_count{3};` |
| `removed_count` | 找到同名声明，停止向外查找 | 内层的 `int removed_count{1};` |

复合赋值读取外层对象保存的 `3` 与内层对象保存的 `1`，把外层的 `shape_count` 改为 `2`。内层代码块执行完毕后，外层的最后一次加法仍使用这个总数对象，把它改为 `3`。

如果在外层最后一条语句之后再写 `removed_count += 1;`，会在编译时失败：这个位置位于 `removed_count` 所属的代码块之外，查找不会从外层向内进入它寻找声明。

## 名称隐藏（Name Hiding）

内层代码块也可以定义一个与外层变量同名的新变量。下面两个变量都叫 `shape_count`，但两条定义创建的是两个独立的 `int` 对象：

```cpp
{
    int shape_count{3};

    {
        shape_count += 1; // 内层同名声明前，修改外层对象，得到 4

        int shape_count{10};
        shape_count += 1; // 内层同名声明后，修改内层对象，得到 11
    }

    shape_count += 1; // 离开内层后，修改外层对象，得到 5
}
```

> [!IMPORTANT] 名称隐藏与两个独立对象
> **内层的同名定义创建并初始化另一个对象；在这条声明的生效区域内，普通的同名使用找到内层声明，外层声明因而被隐藏（hidden）。**隐藏改变当前名称所选中的声明，不会把两个对象合并，也不会把内层对象的值写回外层对象。

| 使用位置 | 选中的声明 | 被修改的对象与结果 |
| --- | --- | --- |
| 内层同名声明之前 | 外层声明 | 外层对象从 `3` 变为 `4` |
| 内层同名声明之后 | 内层声明 | 内层对象从 `10` 变为 `11` |
| 离开内层代码块之后 | 外层声明 | 外层对象从 `4` 变为 `5` |

内层对象从 `10` 变为 `11` 时，外层对象一直保存着 `4`。最后一次加法读取这份 `4`，得到 `5`。内层声明对名称的隐藏从它的生效位置开始，不会追溯改变同一代码块中较早位置的查找结果。

同一个块作用域中不能用相同名称定义两个不同变量：

```cpp
{
    int shape_count{3};
    int shape_count{10}; // 错误：同一作用域中的声明冲突
}
```

因此需要区分：

| 情况 | 语言结果 |
| --- | --- |
| 同一块作用域中的冲突变量声明 | 程序不合法 |
| 本篇这种普通嵌套代码块重新使用外层名称 | 合法，但内层声明会隐藏外层声明 |

编译器可能对同名隐藏发出警告；这里的普通嵌套写法在语言上仍然合法。

> [!PRACTICE] 让名称的范围与用途对应
> 在前面的删除示例中，`shape_count` 在内层结束后还要继续使用，所以声明在外层；`removed_count` 只用于内层的删除计数，所以将它的声明留在内层。两个名称也直接区分了总数与本次删除数量的角色。
>
> **把名称限制在满足用途的最小合理作用域中，并为不同角色的对象使用能区分用途的名称。**这样可以减少无关位置误用局部数据的机会，也避免为了理解一条语句而持续辨认同一个名称当前指代哪个对象。普通嵌套块中的同名隐藏虽然合法，日常代码仍应尽量避免。
