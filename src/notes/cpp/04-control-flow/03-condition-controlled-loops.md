# 条件驱动的循环（Condition-Controlled Loops）

有 `3` 件物品待包装。每完成 `1` 件，就把剩余数量减去 `1`，再判断是否还有物品；剩余数量为 `0` 时，无需再处理。

选择语句根据条件决定沿哪条路径执行；迭代语句（iteration statement）则允许程序重复执行一条子语句。`while` 在每次执行循环体之前判断，`do-while` 在循环体之后判断，这会改变第一次操作能否被跳过。

以下代码片段各自独立，均放在 `main` 函数体内。包装示例用数量记录包装进度，初始待包装数量非负。

## while 循环

`while` 在每一轮开始前求值条件。条件为 `true` 时执行循环体，循环体正常结束后再回到条件；条件为 `false` 时，整条循环结束：

```cpp
int remaining_items{3};

while (remaining_items > 0) {
    --remaining_items;
}
```

`remaining_items` 保存待包装数量，循环体中的减一表示本轮完成一件包装。第一次求值条件时，`3 > 0` 产生 `true`，循环体把剩余数量改为 `2`。随后程序回到条件，读取同一个对象的新值 `2`，再次判断是否继续：

| 条件检查 | 判断前的 `remaining_items` | `remaining_items > 0` | 是否执行循环体及其后状态 |
| --- | ---: | --- | --- |
| 第 1 次 | `3` | `true` | 执行，减少到 `2` |
| 第 2 次 | `2` | `true` | 执行，减少到 `1` |
| 第 3 次 | `1` | `true` | 执行，减少到 `0` |
| 第 4 次 | `0` | `false` | 跳过，保持 `0`，离开循环 |

循环体执行了 `3` 次，条件却求值了 `4` 次：最后一次检查用来发现已经不应继续。前一轮循环体中的完整表达式已经完成，下一次条件才开始求值，因此条件能够读到刚刚写入的值。

> [!IMPORTANT] 每次执行循环体之前，都重新求值条件
> **`while` 的条件决定是否再执行一次循环体；为 `true` 时进入，为 `false` 时结束循环。**每次重新到达条件，都求值圆括号中的条件表达式，并按语境转换为 `bool`；它不是首次判断后永久保存的结果。循环体沿正常路径完成后，程序回到条件再次判断。

如果第一次求值便产生 `false`，循环体一次也不会进入：

```cpp
int remaining_items{0};

while (remaining_items > 0) {
    --remaining_items;
}
```

没有待包装物品时，不执行减一，`remaining_items` 保持 `0`，程序直接继续循环后面的代码。

## do-while 循环

`do-while` 从循环体开始执行。循环体沿正常路径完成后，程序求值条件；条件为 `true` 时再次进入循环体，为 `false` 时结束循环：

```cpp
int remaining_items{0};

do {
    --remaining_items;
} while (remaining_items > 0);
```

这里仍从没有物品的 `0` 开始。`while` 一次也不执行，`do-while` 却先执行减一，把数量改为 `-1`，随后第一次判断条件才得到 `false`，循环结束。代码可以通过编译，但这次数量更新不符合“有物品才处理”的包装规则。

> [!IMPORTANT] 先进入一次循环体，再判断是否重复
> **只要控制到达一条 `do-while` 语句，循环体就先被进入一次；本轮沿正常路径完成后，才求值条件并按语境转换为 `bool`。**条件为 `true` 时重复，为 `false` 时结束；条件无法阻止已经发生的第一次执行。

右括号后的分号属于 `do-while` 的语法，不能省略。它结束的是整条循环语句，而不是循环体中的某一条语句。

对于“先确认还有物品，才允许处理”的规则，这个 `do-while` 并不合适。两种循环的判断位置不同，必须结合第一次操作是否应当发生来选择。

## 判断位置决定最少执行次数

| 循环 | 正常执行路径中的判断位置 | 循环体最少进入次数 |
| --- | --- | ---: |
| `while` | 每轮循环体之前 | 0 |
| `do-while` | 每轮循环体之后 | 1 |

允许操作一次也不发生时，先判断的 `while` 能够直接表达这一点；第一次操作本来就应当发生时，`do-while` 能把“先处理，再决定是否重复”的关系直接写出来。

例如，计算非负整数的十进制位数时，`305` 有三位，`0` 也有一位。对于非负整数，[整数除法](../02-expressions-and-operators/02-arithmetic-operations-and-result-types.md#整数除法)除以 `10` 会去掉当前的个位；每轮先计入这一位，再除以 `10` 去掉它：

```cpp
int remaining_value{305};
int digit_count{0};

do {
    ++digit_count;
    remaining_value /= 10;
} while (remaining_value != 0);
```

`remaining_value` 保存尚未处理完的数值，`digit_count` 保存已经计入的位数。每轮先计入当前这一位，再去掉个位，最后判断是否还有剩余数值：

| 本轮处理前的 `remaining_value` | 计数后的 `digit_count` | 除以 `10` 后的 `remaining_value` | 是否继续 |
| ---: | ---: | ---: | --- |
| `305` | `1` | `30` | `true` |
| `30` | `2` | `3` | `true` |
| `3` | `3` | `0` | `false` |

初值改为 `0` 时，循环仍先计入这一位，使 `digit_count` 变为 `1`；`0 / 10` 仍为 `0`，随后条件为 `false`，循环结束。如果先用 `while (remaining_value != 0)` 判断，初值为 `0` 时就会跳过全部计数，得到不符合要求的 `0` 位。

包装示例要求先确认是否还有物品，位数示例则要求至少计入一位；判断位置应当表达这种实际差别。

## 循环体中的局部对象

现在改为分箱包装，每箱最多装 `3` 件，最后一箱可以不足 `3` 件。如果仍只判断“是否还有物品”，然后每轮固定把数量减少 `3`，就会出现错误记录：

```cpp
int remaining_items{5};

while (remaining_items > 0) {
    remaining_items -= 3; // 含义错误：未限制本箱实际装入数量
}
```

剩余数量先从 `5` 变为 `2`；`2 > 0` 仍为 `true`，于是再次减少 `3`，得到 `-1`。下一次条件虽然为 `false`，循环也确实结束了，但数量记录已经不符合要求。

> [!IMPORTANT] 继续条件不会限制本轮处理数量
> **`remaining_items > 0` 只表示还有物品，不保证剩余数量足够本轮固定处理 `3` 件。**循环条件不会自动减少本轮处理量，也不会把负结果修正为 `0`；更新剩余数量之前，需要先确定本箱实际装入的数量。

用局部对象 `packed_count` 保存本箱装入数量：先按一箱 `3` 件准备，剩余不足时再改为全部剩余数量。下面从 `7` 件开始：

```cpp
int remaining_items{7};

while (remaining_items > 0) {
    int packed_count{3};

    if (remaining_items < packed_count) {
        packed_count = remaining_items;
    }

    remaining_items -= packed_count;
}
```

每轮都会执行 `int packed_count{3};`，为本箱创建一个新的局部对象，先让它保存 `3`。前两轮分别装入 `3` 件；第三轮只剩 `1` 件，`if` 把本箱数量改为 `1`，再从剩余数量中扣减。

`packed_count` 是具有自动存储期的普通局部 `int` 对象。实际执行到定义、完成初始化后，它的生命周期开始；本轮离开循环体时结束，早于下一次条件求值。

| 执行位置 | 判断时的 `remaining_items` | 本箱实际装入的 `packed_count` | 本轮结束后的 `remaining_items` | 本轮局部对象 |
| --- | ---: | ---: | ---: | --- |
| 第 1 轮 | `7` | `3` | `4` | 离开循环体时生命周期结束 |
| 第 2 轮 | `4` | `3` | `1` | 离开循环体时生命周期结束 |
| 第 3 轮 | `1` | `1` | `0` | 离开循环体时生命周期结束 |
| 最后一次判断 | `0` | 未创建 | `0` | 条件为 `false`，不进入循环体 |

> [!IMPORTANT] 外层对象持续存在，循环体内的对象每轮创建
> **对于这里具有自动存储期的循环体内局部对象，每次实际执行到定义并完成初始化，都开始一个新的对象生命周期；离开本轮代码块时结束。**`remaining_items` 定义在循环外，各轮始终读取和修改同一个对象；`packed_count` 每轮重新创建，用于记录当前这一箱的数量。

如果初始待包装数量为 `0`，第一次条件便为 `false`，`packed_count` 一次也不会创建。整条 `while` 之后也找不到这个名称的声明，因为它属于循环体的块作用域。

## 终止条件与状态变化

当继续条件为 `true` 时，要让后续某次判断变为 `false`，就需要改变条件所读取的状态。单件包装每轮减去 `1`，分箱包装每轮减去已经确定的本箱数量，位数示例每轮把剩余数值除以 `10`；它们都修改了下一次条件将要读取的同一个对象。

> [!IMPORTANT] 条件退出需要真实的状态推进
> **对于这里仅比较数值的条件，如果判断结果已经为 `true`，反复比较未改变的状态仍会得到 `true`；要依靠后续条件结束重复处理，就需要实际执行的更新在有限次处理后使条件不再成立。**应当把初始状态、条件读取的对象和每轮执行的更新联系起来判断，不能只看循环体是否执行了某些操作。

下面是遗漏状态变化的错误片段：

```cpp
int remaining_items{3};

while (remaining_items > 0) {
    // 错误示例：没有改变条件读取的状态
}
```

初始待包装数量为 `3`，第一次比较为 `true`。循环体没有语句改变它，下一次比较读取的仍是 `3`，条件也仍为 `true`。现有代码既不能通过状态变化使条件不成立，也没有其他退出路径。

> [!WARNING] 缺少前向进展的无限执行具有未定义行为
> **在 C++23 中，上例的无限执行不满足前向进展（forward progress）要求，具有未定义行为。**标准允许实现假定执行最终会终止，或执行标准库输入输出等认可的进展操作；反复读取或修改普通局部对象本身不满足这项要求。不能依赖上例在实际程序中永远重复检查条件，也不能用某次运行结果证明它的行为可靠。

状态不必在所有问题中单调变化，但预期的终止机制必须与条件观察的状态具有可解释的关系。条件写在哪里、它读取哪个对象、该对象何时变化，共同决定了循环是否按要求继续或结束。
