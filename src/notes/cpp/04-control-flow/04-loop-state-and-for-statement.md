# 循环状态与 for 语句（Loop State and the for Statement）

有 `3` 只箱子，编号依次为 `1`、`2`、`3`，每箱装 `3` 件物品。记录装箱进度时，程序需要知道当前处理哪一箱，并在完成本箱记录后转到下一箱。

开始前确定箱号，每轮开始前判断是否仍在处理范围内，每轮结束后推进箱号。`for` 语句把初始化语句（init-statement）、条件、循环体和迭代表达式（iteration expression）组织在同一结构中。

以下代码片段各自独立，均放在 `main` 函数体内，使用具有自动存储期的普通局部 `int` 对象。

## for 的执行顺序

用 `box_number` 保存当前箱号，用 `packed_count` 保存本箱装入数量，用 `packed_items` 累计已经记录的总件数。沿用 `while`，可以这样组织：

```cpp
int packed_items{0};
int box_number{1};

while (box_number <= 3) {
    int packed_count{3};
    packed_items += packed_count;
    ++box_number;
}
```

这里的箱号初始化、继续条件和推进步骤共同描述同一个控制关系。用 `for` 可以把这三部分集中在循环开头，保留循环体中的本箱记录：

```cpp
int packed_items{0};

for (int box_number{1}; box_number <= 3; ++box_number) {
    int packed_count{3};
    packed_items += packed_count;
}
```

圆括号中最后写出的 `++box_number` 不会先于循环体执行。沿正常路径，这条循环按以下顺序运行：

1. 执行初始化语句 `int box_number{1};`，创建并初始化箱号对象；
2. 求值条件 `box_number <= 3`；
3. 条件为 `true` 时执行循环体；
4. 循环体正常结束后，求值迭代表达式 `++box_number`；
5. 回到条件，重复第二步；
6. 条件为 `false` 时结束整条 `for`。

把当前箱号与累计件数放进这个顺序，可以得到：

| 判断时的 `box_number` | `box_number <= 3` | 本轮装入数量 | 本轮之后的 `packed_items` | 推进后的箱号 |
| ---: | --- | ---: | ---: | --- |
| `1` | `true` | `3` | `3` | `2` |
| `2` | `true` | `3` | `6` | `3` |
| `3` | `true` | `3` | `9` | `4` |
| `4` | `false` | 不执行 | 保持 `9` | 不执行推进 |

两段代码都依次记录三箱，共 `9` 件。对于这里的 `for`，初始化执行 `1` 次，条件求值 `4` 次，循环体与迭代表达式各执行 `3` 次；最后一次条件读取到箱号 `4`，使循环结束。

> [!IMPORTANT] 初始化一次，随后按判断、执行、推进的顺序重复
> **执行到 `for` 时，先执行一次初始化语句；之后先判断条件，再执行循环体，循环体沿正常路径完成后才求值迭代表达式，随后回到条件。**条件为 `false` 时，既不进入本轮循环体，也不执行本轮推进。

## 控制部分的职责

`for` 圆括号中的源码靠得很近，却分别属于不同执行时点，并承担不同职责：

| 部分 | 正常路径中的执行时点 | 通常承担的职责 |
| --- | --- | --- |
| `int box_number{1};` | 进入循环时一次 | 确定起始箱号 |
| `box_number <= 3` | 每轮循环体之前 | 判断是否仍在处理范围内 |
| `++box_number` | 每轮循环体正常结束之后 | 转到下一箱 |

第一个分号属于初始化语句，第二个分号分隔条件与迭代表达式。条件与前面的 `while` 一样，求值结果按语境转换为 `bool`；这里的比较表达式已经直接产生 `bool` 结果。

迭代表达式不必是自增，也不保证一定把某个整数增加一；它是位于循环体之后、下一次条件之前的一项表达式。本例从 `1` 开始、每轮增加 `1`，是因为箱号这样编号，并非 `for` 的固定要求。

如果把起始箱号改为 `4`，范围内已经没有需要处理的箱子：

```cpp
int packed_items{0};

for (int box_number{4}; box_number <= 3; ++box_number) {
    int packed_count{3};
    packed_items += packed_count;
}
```

程序仍先创建保存 `4` 的箱号对象，再检查 `4 <= 3`。结果为 `false`，循环体与迭代表达式都不执行，累计件数保持为 `0`，随后整条 `for` 结束。

> [!IMPORTANT] 不进入循环体，也会先完成初始化
> **第一次条件为 `false`，只会阻止循环体与迭代表达式，不会取消已经完成的初始化。**本例的箱号对象已经创建，但循环体内的 `packed_count` 一次也没有创建；程序离开 `for` 时，箱号对象的生命周期结束。

## 循环变量的作用域与生命周期

初始化语句中定义的循环变量（loop variable）`box_number` 可以由条件、循环体和迭代表达式找到，却不能通过这条声明在整条 `for` 之后继续使用。下面是一个独立的错误片段：

```cpp
int packed_items{0};

for (int box_number{1}; box_number <= 3; ++box_number) {
    int packed_count{3};
    packed_items += packed_count;
}

box_number = 1; // 错误：这里已经找不到 box_number 的声明
```

循环体内的 `packed_count` 也不能在循环体之外通过这条声明找到；外层的 `packed_items` 则可以在 `for` 结束后继续使用。回到开篇正常处理三箱的 `for`，三个对象的生命周期不同：

| 对象 | 完成初始化的位置 | 本次运行的创建次数 | 生命周期结束的位置 |
| --- | --- | ---: | --- |
| `packed_items` | `for` 之前 | `1` | 离开它所属的外层代码块时 |
| `box_number` | 初始化语句中 | `1` | 离开整条 `for` 时 |
| `packed_count` | 每次进入循环体、执行到定义时 | `3` | 每轮离开循环体时，早于迭代表达式求值 |

> [!IMPORTANT] 初始化变量贯穿各轮，循环体内对象每轮创建
> **对于这里具有自动存储期的普通局部对象，初始化语句中的 `box_number` 只创建一次，各轮都修改同一个对象；循环体中的 `packed_count` 则在每次实际执行到定义并完成初始化时开始新的生命周期。**本轮 `packed_count` 的生命周期先结束，随后才执行 `++box_number`；外层累计对象继续存在。

开篇的 `while` 把 `box_number` 定义在循环外，因此循环结束后仍可读取它；这里的 `for` 把箱号声明放在初始化语句中，将这个名称的可用范围限定在整条循环内。相同的装箱结果，并不表示所有声明都有相同的作用域与生命周期。

## 可以省略的控制部分

这里的 `for` 圆括号中始终保留初始化语句的位置；不需要在这里执行初始化操作时，可以用一个单独的分号，也就是空语句，占据这个位置。条件和迭代表达式也可以省略，但圆括号中的两个分号始终保留：

```cpp
int packed_items{0};
int box_number{1};

for (; box_number <= 3;) {
    int packed_count{3};
    packed_items += packed_count;
    ++box_number;
}
```

这段代码在循环外建立箱号的初始状态，把推进过程写在循环体中，没有独立的迭代表达式。它仍记录三箱共 `9` 件，但组织方式已经与开篇的 `while` 相近；循环结束后，外层箱号仍可读取，保存 `4`。

> [!IMPORTANT] 控制内容可以留空，分号与默认条件规则保留
> **不需要初始化操作时，用空语句占据初始化位置；条件与迭代表达式可以省略，但这里的两个分号始终保留。**省略条件相当于条件为 `true`，循环不会再因为条件产生 `false` 而结束。

当三个位置都不提供实际操作时，写作 `for (;;)`。它仍可能通过其他控制路径结束；省略条件本身不保证无限执行具有可靠行为，仍需遵守[终止条件与状态变化](03-condition-controlled-loops.md#终止条件与状态变化)中说明的 C++23 边界。

## 让推进过程集中可见

箱号已经在迭代表达式中推进时，再在循环体中增加一次相同修改，就会改变实际处理范围。下面只比开篇的 `for` 多写一次 `++box_number`：

```cpp
int packed_items{0};

for (int box_number{1}; box_number <= 3; ++box_number) {
    int packed_count{3};
    packed_items += packed_count;
    ++box_number; // 含义错误：本轮把箱号推进了两次
}
```

第一轮记录第 `1` 箱，循环体内先把箱号改为 `2`，迭代表达式又把它改为 `3`；下一轮直接处理第 `3` 箱。之后箱号在循环体内变为 `4`，再由迭代表达式变为 `5`，下一次条件为 `false`。

| 写法 | 实际处理的箱号 | 最终的 `packed_items` |
| --- | --- | ---: |
| 只在迭代表达式中推进 | `1`、`2`、`3` | `9` |
| 循环体内又推进一次 | `1`、`3` | `6` |

> [!WARNING] 重复推进会跳过待处理项
> **上面的代码能够编译，也没有因这些小整数运算产生未定义行为，但它漏掉了第 `2` 箱。**语言允许在循环体中修改循环变量；若本意是统一推进，就不应再惯性地增加第二处修改。编译器可能对这种重复推进发出警告。

> [!PRACTICE] 按控制关系选择循环形式
> 初始化、继续条件和统一推进步骤自然成组时，用 `for` 集中呈现；像“还有物品才处理”这样的状态判断，用 `while` 可以直接表达；第一次处理本来就应发生、之后再决定是否重复时，用 `do-while`。
>
> `for` 不限于已知执行次数，也不要求从 `0` 开始。选择循环形式，应看开始、判断、处理和推进的关系怎样写得更清楚。
