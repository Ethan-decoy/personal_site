# 循环状态与 for 语句（Loop State and the for Statement）

有些循环由一组明确关系共同控制：开始前建立循环状态，每轮开始前判断是否继续，每轮结束后推进状态。`for` 语句把初始化语句（init-statement）、条件、循环体和迭代表达式（iteration expression）组织在同一结构中。

## for 的执行顺序

```cpp
int completed_laps{0};

for (int lap{0}; lap < 3; ++lap) {
    ++completed_laps;
}
```

这条循环按照固定顺序执行：

1. 执行初始化语句 `int lap{0};`，创建并初始化 `lap`；
2. 求值条件 `lap < 3`；
3. 条件为 `true` 时执行循环体；
4. 循环体正常结束后求值迭代表达式 `++lap`；
5. 回到条件并重复第二步；
6. 条件为 `false` 时结束整条 `for`。

因此，循环体依次在 `lap` 保存 `0`、`1` 和 `2` 时执行三次。第三次循环体结束后，`++lap` 将它修改为 `3`；下一次条件得到 `false`，循环结束，`completed_laps` 最终保存 `3`。

**初始化语句只执行一次，条件可能求值多次；循环体沿正常路径完成后，迭代表达式随即求值。**条件在第一次求值时已经为 `false`，循环体和迭代表达式都不会执行。

## 控制部分的职责

`for` 圆括号中的源码靠得很近，却分别属于不同执行时点，并承担不同职责：

| 部分 | 正常路径中的执行时点 | 通常承担的职责 |
| --- | --- | --- |
| `int lap{0};` | 进入循环时一次 | 建立循环状态 |
| `lap < 3` | 每轮循环体之前 | 判断是否继续 |
| `++lap` | 每轮循环体之后 | 推进循环状态 |

迭代表达式不必是自增，也不保证一定把某个整数增加一；它只是位于循环体之后、下一次条件之前的一项表达式。把初始化、判断和推进写进 `for`，应当是因为它们共同描述同一个循环控制关系。

## 循环变量的作用域与生命周期

初始化语句中定义的循环变量（loop variable）`lap` 可以由条件、循环体和迭代表达式找到，却不能在整条 `for` 之后继续使用：

```cpp
int completed_laps{0};

for (int lap{0}; lap < 3; ++lap) {
    completed_laps += lap;
}

lap = 0; // 错误：这里已经找不到 lap 的声明
```

`lap` 在初始化语句中只创建一次。所有轮次中的条件、循环体和迭代表达式始终指代同一个对象；它的值随迭代表达式变化，类型和对象身份没有改变。整条 `for` 结束时，`lap` 的生命周期结束。

即使第一次条件求值便得到 `false`，初始化语句仍然已经执行，`lap` 对象也已经创建；程序随后离开 `for` 并销毁它。**是否执行循环体，不会反过来取消已经完成的循环初始化。**

这与循环体内每轮重新创建的局部对象不同：初始化语句中的对象贯穿所有轮次，循环体中的对象只属于某一次实际进入循环体的执行。两个生命周期边界不能仅凭名称在源码中的距离判断。

## 可以省略的控制部分

`for` 圆括号中始终保留初始化语句的位置；不需要初始化时，可以用一个单独的分号，也就是空语句，占据这个位置。条件和迭代表达式也可以省略，但圆括号中的两个分号始终保留：

```cpp
int lap{0};

for (; lap < 3;) {
    ++lap;
}
```

这段代码没有在 `for` 内建立初始状态，也没有独立的迭代表达式；推进过程写在循环体中。它虽然合法，结构却更接近 `while`。

当三个控制部分都不提供实际内容时，写作 `for (;;)`。其中缺失的条件等价于 `true`；无论初始化语句与迭代表达式是否还包含内容，只要省略条件，循环就不会因为条件产生 `false` 而结束。这并不排除其他控制路径结束循环，只表示正常循环判断不再提供终止条件。

## 让推进过程集中可见

循环变量已经在迭代表达式中推进时，不应再惯性地在循环体中修改同一个对象：

```cpp
int completed_laps{0};

for (int lap{0}; lap < 6; ++lap) {
    ++completed_laps;
    ++lap;
}
```

这段代码每轮把 `lap` 修改两次，循环体实际只在 `0`、`2` 和 `4` 时执行。代码没有未定义行为，但读者已经无法只看 `for` 的开头判断推进方式。

**当初始化、判断和一个统一的推进步骤自然成组时，使用 `for`；是否继续主要取决于某个状态，且状态变化没有单一固定位置时，使用 `while`；第一次操作必然发生时，才使用 `do-while`。**选择不同循环形式的目的，是让开始、继续、推进和结束的关系直接呈现在结构中。
