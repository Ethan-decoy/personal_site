# 调用栈与栈帧（Call Stack and Stack Frames）

C++ 的语言语义要求嵌套调用各自保有仍需继续使用的状态，并在内层调用正常返回后回到对应的调用位置。调用栈（call stack）与栈帧（stack frame）是实现这种关系的常见方式，但不是 C++ 抽象机规定的固定物理结构。

## 嵌套调用呈现后进先出关系

假设一次调用中又发生两层调用：

```text
调用者
└── calculate_operating_pressure_kpa
    └── calculate_pressure_with_margin_kpa
```

进入顺序从外向内；对于正常返回的嵌套调用，返回顺序从内向外。内层调用尚未结束时，外层不能越过当前调用表达式继续执行。

这种后进先出关系与栈（stack）的操作方式一致，因此实现通常用调用栈管理仍处于活动状态的调用。只从概念上观察某一时刻，可以画成：

```text
栈顶：最后进入的调用
┌────────────────────────────────────────┐
│ calculate_pressure_with_margin_kpa     │
├────────────────────────────────────────┤
│ calculate_operating_pressure_kpa       │
├────────────────────────────────────────┤
│ 更早进入且尚未完成的调用               │
└────────────────────────────────────────┘
栈底：更早进入的调用
```

这张图表达调用的嵌套次序，不规定真实内存必须具有相同方向、形状或布局。

## 栈帧承载一次活动调用的实现状态

实现通常为一次活动调用维护一组恢复执行所需的信息，这组信息常称为栈帧，也称活动记录（activation record）。它可能包含：

- 调用结束后需要返回的位置；
- 实现选择保留的寄存器状态；
- 没有放入寄存器的参数或局部数据；
- 为求值过程和平台布局要求保留的空间。

具体内容由编译器、目标平台的应用二进制接口（Application Binary Interface，ABI）和优化共同决定。ABI 是独立编译的程序片段必须共同遵守的二进制契约；它为什么存在、约束哪些边界，见附章[应用二进制接口：编译产物之间的契约](02-application-binary-interface.md)。不同函数的栈帧大小可以不同，同一段源码在不同构建配置下也可能得到完全不同的机器布局。

**栈帧不是由 C++ 代码显式创建的对象，也不存在一套适用于所有平台的标准字段顺序。**语言只规定程序必须呈现怎样的可观察行为，实现负责选择机器层面的承载方式。

## 自动存储期不等于物理栈

普通局部对象经常被口语化地称为“栈变量”，因为许多实现确实把它们放入当前调用的栈帧。但自动存储期（automatic storage duration）描述的是对象生命周期与代码块进入、离开的关系，不是一个强制存储地址类别。

```cpp
int calculate_pressure_kpa(int measured_pressure_kpa) {
    int margin_kpa{5};
    return measured_pressure_kpa + margin_kpa;
}
```

语言语义要求 `measured_pressure_kpa` 和 `margin_kpa` 在需要时产生正确结果，却不要求两者一定占据调用栈中的真实字节。编译器可以把值保存在寄存器中，也可以在不改变程序可观察行为时直接把计算化简为 `measured_pressure_kpa + 5`。

像 `margin_kpa` 这样的普通块作用域局部对象，会在离开相应代码块时结束生命周期；实现随后可以复用承载它的资源。不能反过来把对象销毁解释成“栈帧弹出造成的附带结果”。

## 源码调用不保证对应真实栈帧

C++ 允许实现按照如同规则（as-if rule）改变程序的内部执行方式，只要保留标准要求的可观察行为。编译器可能把短小函数的机器指令直接并入调用位置，使源码中的调用不再对应独立栈帧；某些条件下，也可能让一个调用复用当前调用的资源。

因此，下面三层源码调用建立的是可靠的语义关系：

```text
外层调用暂停 -> 内层调用执行 -> 内层正常返回 -> 外层继续
```

“机器中一定同时存在三个具有固定布局的栈帧”则不是可移植保证。调试器通常会尽力还原调用关系，但经过优化的程序可能无法完整呈现与源码逐行对应的帧和局部状态。

## 递归会受到实现资源限制

递归使同一个函数产生多层尚未结束的调用。当实现为活动调用保留独立栈帧时，递归会持续消耗有限的实现资源；是否能够省去或复用某些栈帧，取决于实现与优化。

**调用栈适合解释常见实现怎样承载嵌套调用；判断程序语义时，仍应以每次调用的独立状态、作用域和生命周期规则为准。**
