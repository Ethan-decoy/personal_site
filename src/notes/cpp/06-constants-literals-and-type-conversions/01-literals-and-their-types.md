# 字面量及其类型（Literals and Their Types）

## 写在源代码中的值

值可以从已有对象中读取，也可以直接写在源代码中，为对象提供初值。下面的片段放在 `main` 函数体内；本篇各代码片段彼此独立：

```cpp
int count{4};
double value{2.4};
char letter{'A'};
bool enabled{true};
```

其中的 `4`、`2.4`、`'A'` 和 `true` 都是**字面量（literal）**，即源代码中直接表示值的记号。`count` 等名称用于访问对象，字面量则直接提供相应的值，不需要从某个已有的具名对象中读取。

## 字面量本身也有类型

字面量也有自己的类型。把同样的 `4` 分别用于初始化 `int` 和 `double` 对象：

```cpp
int count{4};
double value{4};
```

两处 `4` 都是 `int` 类型的整数字面量。第一行直接使用这个 `int` 值初始化 `count`；第二行先把 `int` 值 `4` 转换为 `double` 值，再初始化 `value`。两个对象保存的数值都是 4，但对象类型分别为 `int` 和 `double`。

> [!IMPORTANT] 字面量类型与目标对象类型
> **字面量按自身写法所对应的语言规则确定类型，目标对象的类型不会倒过来改变字面量类型。**初始化、运算或函数调用等使用语境，再按相应规则判断是否需要转换。判断代码时，应先分清字面量提供什么类型的值，以及当前使用位置要求什么类型。

## 整数字面量的进制

整数字面量（integer literal）可以使用二进制、八进制、十进制或十六进制书写。同一个整数 12 有下面几种写法：

| 进制 | 前缀与数码 | 示例 | 表示的十进制值 |
| --- | --- | --- | ---: |
| 二进制 | `0b` 或 `0B`，数码为 `0～1` | `0b1100` | 12 |
| 八进制 | 前导 `0`，数码为 `0～7` | `014` | 12 |
| 十进制 | 非零值以 `1～9` 开头，数码为 `0～9` | `12` | 12 |
| 十六进制 | `0x` 或 `0X`，数码为 `0～9`、`a～f` 或 `A～F` | `0xC` | 12 |

十六进制中的 `A～F` 分别表示十进制的 10～15，因此 `0xC` 表示 12。进制决定怎样解释整段数码：八进制的 `012` 表示 $1 \times 8 + 2 = 10$，与十进制的 `12` 不同。

> [!WARNING] 前导零会改变整数的进制
> `0b`、`0B`、`0x`、`0X` 分别引入二进制或十六进制；没有这些前缀、以 `0` 开头的整数字面量按八进制解释。八进制数码只允许 `0～7`，因此 `08` 是不合法的整数字面量，编译器必须诊断。除非确实需要八进制，不给十进制整数添加装饰性的前导零。

下面的片段展示这个错误：

```cpp
int count{08}; // 错误：八进制数码不能包含 8
```

较长的数字可以在数码之间加入单引号，作为数字分隔符：

```cpp
int limit{12'000};
long value{0xFF'00'7A};
```

这里的 `12'000` 与 `12000` 等价，`0xFF'00'7A` 与 `0xFF007A` 等价。分隔符只改善阅读，不改变字面量的值或类型。

## 整数字面量的类型选择

整数的数字之后还可以附加后缀（suffix），例如 `42U` 中的 `U`、`42L` 中的 `L`。这些字母是字面量写法的一部分，参与确定类型。

> [!IMPORTANT] 整数字面量按候选顺序选择类型
> **进制类别和后缀决定有序的候选类型列表，再按目标实现的取值范围，选择第一个能够表示该值的类型。**后缀参与这个选择，不是对一个已经确定类型的值再做转换。相同的数学值，可能因进制写法、后缀或实现的类型范围不同而具有不同类型。

### 没有后缀时的候选顺序

对于无后缀的写法，标准整数类型的候选如下：

- 十进制：依次检查 `int`、`long int`、`long long int`。
- 二进制、八进制或十六进制：依次检查 `int`、`unsigned int`、`long int`、`unsigned long int`、`long long int`、`unsigned long long int`。

例如，**假设 `int` 的位宽为 32、`long` 的位宽为 64**。`int` 的最大值为 $2^{31}-1$，`unsigned int` 的最大值为 $2^{32}-1$。下面两种写法都表示 $2^{31}$，但候选顺序不同：

| 写法 | 前几个候选及范围检查 | 最先成功的类型 |
| --- | --- | --- |
| `2147483648` | `int` 不能表示，接着尝试的 `long` 能表示 | `long` |
| `0x80000000` | `int` 不能表示，接着尝试的 `unsigned int` 能表示 | `unsigned int` |

编译器直接按各自的候选列表确定字面量类型，没有先产生一个装不下该值的 `int` 再转换。这里的十进制写法跳过了不能表示该值的 `int`，选中 `long`；十六进制写法则在 `unsigned int` 处就能停止。后续使用这两个字面量时，必须分别从 `long` 与 `unsigned int` 出发判断运算和转换。

这组数值用于展示选择过程，无需逐项记忆具体端点。接近类型边界时，应先核对目标实现的[整数类型范围](../01-objects-types-and-variables/04-integer-types.md#标准整数类型)；不能把上述类型结果照搬到所有实现。

### 常用后缀限定候选类型

`U` 把候选限定为无符号整数类型，`L` 与 `LL` 改变候选的起点，它们也可以组合使用。以能由各自首个候选表示的 42 为例：

| 示例 | 当前字面量的类型 |
| --- | --- |
| `42` | `int` |
| `42U` | `unsigned int` |
| `42L` | `long int` |
| `42LL` | `long long int` |
| `42ULL` | `unsigned long long int` |

这个表展示的是 42 对应的结果，不能由 `42L` 推出所有带 `L` 的整数都是 `long`。对于带 `L` 的十进制整数字面量，先检查 `long int`，放不下时再检查 `long long int`。

**当 `long` 的位宽为 32、`long long` 的位宽为 64 时**，两种大小的十进制字面量会得到不同结果：

| 写法 | 候选检查 | 类型 |
| --- | --- | --- |
| `42L` | `long` 能表示 42，选中首个候选 | `long` |
| `2147483648L` | `long` 最大只能表示 2147483647，继续检查的 `long long` 能表示该值 | `long long` |

`L` 并不要求先把超出范围的值放进 `long`，而是让类型选择从 `long` 开始。在 `long` 位宽为 64 的实现中，`2147483648L` 就能在首个候选处选中 `long`。这些常用后缀也可以写成相应的小写形式，例如 `u`、`l` 或 `ll`；本笔记使用大写 `L`，避免小写 `l` 与数字 `1` 混淆。

完整的后缀组合供使用时查阅，不必把每个候选列表都当作记忆清单。使用不熟悉的后缀，或数值超出上述标准候选的范围时，应核对[整数字面量条款的候选表与扩展类型规则](https://timsong-cpp.github.io/cppwp/n4950/lex.icon#3)。如果没有该写法允许的整数类型能够表示这个值，程序不合法，编译器必须诊断。

## 负号不属于整数字面量

`-42` 看起来像一个负整数字面量，但词法上只有 `42` 是整数字面量；前面的 `-` 是一元负号运算符：

```cpp
int value{-42};
```

花括号中的内容是表达式 `-42`。`42` 是 `int` 字面量，对它应用一元负号，得到 `int` 值 `-42`，再初始化 `value`。

> [!IMPORTANT] 先确定字面量类型，再执行取负
> **前置负号是运算符，不属于整数字面量。先按字面量写法确定类型，再按一元负号的规则求值；取负后的数值不会参与字面量类型的重新选择。**分析这样的表达式时，不能把前置负号和数字合成一个新的整数字面量。

这条区别会影响负数的类型判断。**在 `int` 位宽为 32、`long` 位宽为 64 的实现中**，表达式 `-2147483648` 的判断过程是：

1. `2147483648` 超出 `int` 的正数范围，但能由 `long` 表示，因此这个无后缀十进制字面量的类型是 `long`。
2. 对这个 `long` 值应用一元负号，得到 `long` 值 `-2147483648`。

虽然最终数值恰好能由 32 位 `int` 表示，表达式的类型仍是 `long`。前面的负号不会让编译器跳过正数字面量的类型选择，也不会按最终的负数数值重新选择 `int`。

## 浮点、字符与布尔字面量

浮点字面量（floating-point literal）的类型也由写法确定。小数点和指数部分用于表达数值，常用后缀则按下面的对应关系确定类型：

> [!IMPORTANT] 常用浮点字面量的类型
>
> | 写法 | 类型 |
> | --- | --- |
> | 无后缀，例如 `2.4` | `double` |
> | 后缀为 `f` 或 `F`，例如 `2.4F` | `float` |
> | 后缀为 `l` 或 `L`，例如 `2.4L` | `long double` |
>
> **先辨认字面量属于整数还是浮点形式，再解释后缀。**`42L` 从整数候选中选择类型，`2.4L` 则直接是 `long double`。

科学计数法中的 `e` 或 `E` 引入十进制指数。例如，`2.4e2` 表示 $2.4 \times 10^2 = 240.0$；它没有后缀，类型仍是 `double`。有指数部分时也可以省略小数点：`24e1` 同样表示 $24 \times 10^1 = 240.0$，类型也是 `double`，而 `240` 是 `int` 字面量。

确定了浮点类型，还要区分数学上的数值与该类型实际能够表示的值。在常见二进制浮点实现中，`2.4` 不能精确表示，字面量提供的是附近的可表示值；具体的范围、精度与舍入关系见[浮点类型](../01-objects-types-and-variables/07-floating-point-types.md#可表示值与舍入)。

> [!IMPORTANT] 普通字符与布尔字面量的类型
> **`'A'` 这类由单个基本字符组成、不带额外前缀的字符字面量（character literal）具有 `char` 类型；布尔字面量（boolean literal）`true` 与 `false` 具有 `bool` 类型。**

例如，`4` 的类型是 `int`，表示整数 4；`'4'` 的类型是 `char`，表示字符 `4` 所对应的编码单元值。`true` 与整数 `1` 也属于不同类型。后续初始化或运算即使允许转换，也不会使这些字面量原本的类型相同。
