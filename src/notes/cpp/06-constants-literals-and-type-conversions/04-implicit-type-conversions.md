# 隐式类型转换（Implicit Type Conversions）

## 语境要求另一种类型

赋值右侧提供的值，可能与左侧对象的类型不同。下面用 `double` 保存源值，再把它赋给一个 `int` 对象：

除完整程序外，以下片段均放在 `main` 函数体内；各片段彼此独立。

```cpp
const double source{-3.8};
int target{0};

target = source;
```

求值右侧时，读取 `source`，得到它保存的 `double` 值。左侧对象要求 `int` 值，因此这次使用需要进行从 `double` 到 `int` 的转换。

浮点数转换为非 `bool` 整数时，向零丢弃小数部分。本例得到整数 `-3`，再把它写入 `target`，不会四舍五入为 `-4`。这个结果能由 `int` 表示，满足本次转换的范围要求。

代码没有显式写出转换请求，语言根据使用位置完成这项工作，称为**隐式类型转换（implicit type conversion）**。本篇讨论的数值转换由语言直接规定，属于标准转换（standard conversion）。

转换后，`source` 仍是原来的 `const double` 对象，保留原来的浮点值；`target` 仍是 `int` 对象，只是当前值由 0 变为 `-3`。

> [!IMPORTANT] 转换作用于当前使用的值
> **这里的数值转换产生目标类型的值，不会把被读取的源对象改造成另一种类型，也不会自行修改源对象的值。**随后是否写入对象，由赋值、初始化等外围操作决定。判断时应分开追踪源对象、转换结果和接收结果的对象。

使用位置还会限制转换能否成立。例如，保留源对象声明，把后面的目标对象定义和赋值合并为 `int target{source};`，就会因浮点数到整数的窄化转换而不合法。相应的静态检查规则见[列表初始化与窄化](05-list-initialization-and-narrowing.md#花括号会检查当前初始化边界)；普通赋值不会自动获得相同的花括号检查。

## 转换会出现在哪里

同一种“当前位置要求另一种类型”的关系，也出现在初始化、运算、函数调用和条件判断中：

| 使用位置 | 如何确定当前需要的类型 |
| --- | --- |
| 运算符的操作数 | 由该运算符的规则决定；例如 `int` 与 `double` 相加时，按通常算术转换采用 `double` |
| 对象初始化 | 被初始化对象的类型 |
| 赋值 | 左侧对象的类型 |
| 按值传参 | 对应形参对象的类型 |
| 普通按值返回函数的 `return` 表达式 | 函数规定的返回类型 |
| `if`、`while`、`for` 等的条件 | 按条件语境转换为 `bool` |

并非所有运算符都要求操作数采用共同类型。相应二元算术运算如何寻找共同类型，见[通常算术转换](../02-expressions-and-operators/03-usual-arithmetic-conversions.md#转换的是参与运算的值)；`if` 等条件中的零与非零判断，则使用布尔转换规则。

按值传参时，实参表达式用于初始化形参对象；`return` 表达式用于建立返回结果。下面的完整程序把输入值除以 2，再按整数返回，用来观察这两个位置各自发生的转换：

```cpp
#include <iostream>

int half_as_integer(const double value) {
    return value / 2.0;
}

int main() {
    const long source{7L};
    const int target{half_as_integer(source)};

    std::cout << source << ' ' << target << '\n'; // 7 3
    return 0;
}
```

形参 `value` 是按值接收的独立对象，类型为 `const double`，函数体只读取它。一次调用的过程为：

| 位置 | 使用的值与转换结果 |
| --- | --- |
| 初始化形参 | 从 `source` 读取 `long` 值 7，转换为 `double` 值 7.0，再初始化 `value` |
| 执行除法 | 两个操作数都是 `double`，得到 `double` 值 3.5 |
| 建立返回结果 | 函数返回类型是 `int`，将 3.5 向零截断为可表示的整数 3，调用因此提供 `int` 结果 |
| 初始化 `target` | 收到的已经是 `int` 值 3，这里不再发生数值类型转换 |

> [!IMPORTANT] 每个转换位置分别检查类型要求
> **形参初始化、函数返回和外围对象初始化是不同的位置，各自按相应规则决定是否转换。**返回类型不会倒过来改变函数体内除法的类型；外层花括号也不会回头检查函数内部已经完成的转换。先找到转换发生在哪里，再判断结果和边界。

这里没有给“返回类型”赋值，也没有给一个早已存在的形参补写数值。调用先初始化本次形参，再执行函数体；返回时建立 `int` 结果。整个过程中，源对象 `source` 仍保存 7。

## 当前数值类型的转换结果

转换结果由源类型与目标类型共同决定。下表用于按转换方向查阅结果和边界；浮点数的范围与舍入说明针对有限值：

| 转换方向 | 结果与边界 |
| --- | --- |
| 整数 → 非 `bool` 整数 | 值能表示时保持不变；否则得到目标类型中与源值模 $2^N$ 同余的唯一值，$N$ 是目标类型的位宽 |
| 浮点数 → 非 `bool` 整数 | 丢弃小数部分，向零截断；截断后的值无法由目标类型表示时，行为未定义 |
| 整数 → 浮点数 | 能精确表示时保持原值；范围内但无法精确表示时，由实现选择相邻的较低或较高可表示值；超出目标范围时，行为未定义 |
| 标准浮点数 → 另一标准浮点类型 | 能精确表示时保持原值；源值位于两个相邻目标值之间时，由实现选择其中一个；否则行为未定义。`float` 到 `double` 的提升保持原值 |
| 算术类型 → `bool` | 零转换为 `false`，其他值转换为 `true` |

### 转换为整数时，来源决定越界规则

**假设 `short` 的位宽为 16**，其取值范围为 `−32768～32767`。整数值 32768 转换为 `short` 时，按模 $2^{16}$ 得到 `−32768`：

```cpp
const long source{32768L};
short target{0};

target = source;
```

转换前后的两个整数相差 $65536$，因此模 $2^{16}$ 同余。这个结果由 C++23 的整数转换规则规定，并不表示它符合原本希望保留正数的用途。

如果来源改为浮点值 `32768.0`，截断后的整数仍是 32768，不能由这个 `short` 表示，转换就会产生未定义行为。相反，`32767.9` 向零截断为 32767，可以满足该范围要求。检查的是**截断后的整数是否可表示**，不能直接套用整数来源的模规则。

> [!IMPORTANT] 整数越界转换与浮点截断的边界不同
> **目标是非 `bool` 整数时，整数来源的越界转换采用模 $2^N$ 的结果，$N$ 是目标类型的位宽；浮点来源先向零截断，截断后的值必须能由目标类型表示，否则行为未定义。**这些规则不提供自动饱和或失败返回值。无穷和 NaN 也不能安全地转换为这里的非 `bool` 整数。

这些具体端点依赖给定的位宽，无需逐项记忆。接近边界或更换目标类型时，应先核对实现的[整数类型范围](../01-objects-types-and-variables/04-integer-types.md#标准整数类型)，再按源类型应用相应规则。

### 转换为浮点数时，范围与精度分别检查

一个整数即使处于目标浮点类型的范围内，也可能不能精确表示。**假设 `float` 使用 binary32、具有 24 位二进制有效精度，且这里的整数到 `float` 转换采用就近取偶**：

```cpp
const long source{16'777'217L};
float target{0.0F};

target = source;
const double widened{target};
```

在这些前提下，源整数 16777217 位于 binary32 的两个相邻可表示值 16777216 和 16777218 之间；就近取偶选择 16777216，因此 `target` 保存 16777216。随后从 `float` 提升为 `double` 保持这个已有值，`widened` 仍是 16777216.0，无法恢复转换时已经丢失的差值。源整数对象则保留 16777217。

> [!IMPORTANT] 范围允许不等于能够精确保值
> **转换为浮点类型时，需要分别核对取值范围和表示精度。**范围内的值仍可能需要舍入，之后使用更宽的接收类型也不会恢复已经丢失的信息。整数到浮点数超出目标范围时，在 C++23 中会产生未定义行为，不能一概当作普通舍入。

上面的数值用于说明精度损失，结果依赖所列格式与舍入前提。实际依赖保值转换之前，应核对目标实现的[浮点格式与精度规格](../01-objects-types-and-variables/07-floating-point-types.md#标准保证与实现规格)，不能只比较类型名称或存储字节数。

### 转换为 bool 时直接判断零与非零

目标为 `bool` 时，使用单独的布尔转换规则，不先经过一次普通整数截断：

```cpp
const double source{0.5};
bool enabled{false};

enabled = source;
const int marker{enabled};
```

`source` 非零，因此 `enabled` 得到 `true`；再把这个布尔值转换为 `int`，`marker` 得到 1。如果误以为要先把 0.5 截断为整数 0，再转为 `bool`，就会把第一步结果判断成 `false`。

> [!IMPORTANT] 转入 bool 与从 bool 转出
> **算术值转换为 `bool` 时，零得到 `false`，非零得到 `true`。浮点值也直接应用这条规则。**反方向把 `bool` 转换为整数或标准浮点类型时，`false` 提供 0，`true` 提供 1；这描述的是转换结果，不是布尔对象的内部存储表示。

## 能转换不等于应该转换

语言能够按规则进行转换，不保证得到的值符合数据的用途。若必须保留小数，目标采用整数就不合适；若必须精确保留一个大整数，范围足够大的浮点类型也未必能满足要求。

布尔转换同样只表达零与非零。如果 `remaining_attempts` 可能为负，`if (remaining_attempts)` 仍会将负数当作 `true`；`if (remaining_attempts > 0)` 才是在判断是否还剩正数次尝试。

> [!PRACTICE] 在转换前确认允许丢失什么信息
> 先按数据职责选择目标类型，再核对范围、精度和逻辑含义。确实允许截去小数或改变精度时，应让意图容易辨认；不能依靠隐式转换替代取值检查，也不能因为代码能够编译，就认定原值已被完整保留。

编译器可能对合法的截断或精度变化发出警告。警告有助于发现需要审查的转换，但是否把警告作为构建错误属于项目策略；语境是否允许转换、转换执行时是否具有定义行为，仍要分别按语言规则判断。
