# 列表初始化与窄化（List Initialization and Narrowing）

## 花括号会检查当前初始化边界

同一个数值转换，在普通赋值中可以成立，在花括号初始化中却可能被拒绝。花括号为所在位置引入列表初始化（list-initialization），并检查这里是否需要窄化转换。

除完整程序外，以下片段均放在 `main` 函数体内；注明替换时沿用所指程序，其余片段彼此独立。

先看三种都能用整数 3 定义对象的写法：

```cpp
const int direct{3};
const int copy_list = {3};
const int copy = 3;
```

第一行是直接列表初始化（direct-list-initialization）；第二行是复制列表初始化（copy-list-initialization）。二者都使用花括号，属于列表初始化。第三行是未使用列表的复制初始化（copy-initialization）。带有 `=` 的两行也都在创建对象并提供初值，不是在给已经存在的对象赋值。

保留这些初始化形式，把提供初值的整数 3 换成 `double` 字面量 `3.8`，结果就不同：

```cpp
const int direct{3.8};       // 错误：列表初始化需要窄化转换
const int copy_list = {3.8}; // 错误：复制列表初始化同样拒绝窄化
const int copy = 3.8;        // 合法：普通复制初始化得到 3
```

浮点数到整数属于标准规定的窄化转换（narrowing conversion），因此前两行不合法。第三行按普通隐式转换规则向零截断，再初始化 `copy`，可以得到 3。

> [!IMPORTANT] 列表初始化拒绝窄化转换
> **对这里的数值对象进行列表初始化时，若该处需要标准规定的窄化转换，程序不合法，编译器必须诊断。**带有 `=` 的定义也可能是列表初始化，判断时要看初始化器是否使用花括号。

编译器也可能对第三行的合法截断发出警告。如果项目把警告作为错误处理，这行代码仍可能无法构建；这属于项目的诊断策略，与语言把前两行判为不合法是不同的原因。

## 窄化是标准定义的分类

C++ 按源类型、目标类型和常量表达式条件定义窄化，不能只凭某次数值是否改变判断。先辨认转换类别，再核对该类别是否具有例外；下表列出当前基本数值类型的相关规则，浮点降级例外先按有限值讨论：

| 转换 | 列表初始化中的判定 |
| --- | --- |
| 浮点数 → 整数（包括 `bool`） | 始终是窄化，没有常量表达式例外 |
| 较高浮点转换等级 → 较低等级 | 通常是窄化；对于有限的常量表达式，只要转换结果没有超出目标范围，就不算窄化 |
| 整数 → 浮点数 | 通常是窄化；常量表达式能够由目标类型表示，并且转回原整数类型仍得到原值时除外 |
| 整数 → 不能覆盖源类型全部取值的整数类型 | 通常是窄化；常量表达式的实际值能够由目标类型表示时除外 |

表中的浮点转换等级（floating-point conversion rank）是语言规定的类型次序。三种标准浮点类型按 `float`、`double`、`long double` 依次升高；它与某个实现中的具体字节数、精度规格需要分开判断。

例如，即使浮点值没有小数部分，也不能通过列表初始化转为整数：

```cpp
const int target{3.0}; // 错误：浮点数到整数仍属于窄化
```

> [!IMPORTANT] 窄化由转换类别与例外条件决定
> **窄化不等同于“这一次一定丢失信息”。**浮点值 `3.0` 能以整数 3 表示，浮点数到整数的列表转换仍被拒绝；另一方面，C++23 的某些浮点常量转换可以在发生舍入时通过检查。必须依据转换类别及其例外判断。

## 常量表达式例外检查实际值

### 整数目标需要检查数值范围

**假设 `int` 的位宽为 32、`short` 的位宽为 16**。`short` 无法覆盖 `int` 的全部取值，但下面的常量表达式例外可以成立：

```cpp
constexpr int source{4};
const short target{source}; // 合法：常量值 4 能由 short 表示
```

`source` 可用于这里的常量表达式，实际值 4 又能由目标类型表示，因此初始化合法。把源改成保存相同数值的普通可修改对象：

```cpp
int source{4};
const short target{source}; // 错误：普通对象的当前值不能触发常量表达式例外
```

虽然当前值仍为 4，读取普通 `int` 对象不满足这里的常量表达式条件，无法使用这项例外。相反，在当前同一作用域中使用 `const int source{4};`，其值也可用于常量表达式；判断依据并不只是声明中有没有 `constexpr`。

数值本身也必须满足范围要求。仍在上述位宽前提下：

```cpp
constexpr int source{32768};
const short target{source}; // 错误：常量值超出 16 位 short 的范围
```

即使 `source` 已经声明为 `constexpr`，值 32768 仍超出 `short` 的最大值 32767。列表初始化会拒绝这次转换，不会按普通整数转换规则接受一个回绕后的结果。

> [!IMPORTANT] 常量表达式例外还要检查数值条件
> **具有常量表达式例外的转换，必须同时满足源表达式的常量求值条件和该类别对数值的额外要求。**整数到整数的例外要求实际值能由目标类型表示；整数到浮点数的例外还要求转换并转回后保留原值。使用 `constexpr` 不能取消这些条件。

### 浮点目标需要检查精确保值条件

整数到浮点数的列表转换通常属于窄化，常量表达式例外还要求结果能够精确保留原整数：

```cpp
const float exact{7}; // 合法：常量整数 7 能被精确表示

int source{7};
const float target{source}; // 错误：读取普通对象不满足常量表达式条件
```

现在**假设 `float` 使用 binary32，具有 24 位二进制有效精度**。即使改用常量表达式，更大的整数也可能无法通过检查：

```cpp
constexpr long source{16'777'217L};
const float target{source}; // 错误：binary32 不能精确表示这个整数
```

16777217 处于 binary32 的有限范围内，但位于两个相邻可表示值 16777216 与 16777218 之间。转换会改变原整数，因而不满足这项例外。具体边界取决于浮点格式，使用时应核对[浮点精度规格](../01-objects-types-and-variables/07-floating-point-types.md#标准保证与实现规格)，无需记忆这组具体数值。

## C++23 的浮点降级边界

浮点数到浮点数的例外，与整数到浮点数的精确保值条件不同。`double` 的浮点转换等级高于 `float`；在 C++23 中，有限的常量表达式从较高等级转换到较低等级时，符合目标范围条件即可适用例外，允许结果经过舍入。

例如，**假设 `float` 使用 binary32，`double` 使用 binary64**：

```cpp
const float target{0.1}; // C++23：合法，转换会发生舍入
```

字面量 `0.1` 的类型为 `double`。在这些格式前提下，将它提供的 binary64 值转换为 binary32，不能精确保留原值，但这次列表初始化仍然合法。这与整数 16777217 转换为 binary32 时因不满足精确保值条件而被拒绝，属于两种不同的例外规则。

如果改为从普通 `double` 对象读取初值：

```cpp
double source{0.1};
const float target{source}; // 错误：源表达式不是常量表达式
```

这个读取不符合例外要求，因此仍被判为窄化。数值看起来相同，并不能代替常量表达式条件。

> [!IMPORTANT] 浮点降级与整数转浮点采用不同例外
> **C++23 中，这里的有限浮点常量降级转换在符合范围条件时可以发生舍入；整数到浮点数的常量表达式例外则要求保留原整数。**不能把某一类转换的精度条件套用到另一类，也不能把花括号概括为拒绝所有数值变化。

## 初始化时的花括号不会约束以后

对象定义中的花括号只检查那一次初始化。它不会改变对象后续普通赋值的规则：

```cpp
int target{0};
target = 6.9; // 合法：普通赋值后得到 6
```

`target` 创建时以 0 初始化，之后的赋值仍按普通隐式转换规则截去小数。如果保留 `target` 的定义，把赋值行替换为：

```cpp
target = {6.9}; // 错误：右侧列表按目标 int 类型检查，发生窄化
```

这次赋值的右侧使用了花括号列表。对于当前的数值对象，列表元素要按左侧目标类型接受初始化检查，因此不能从 `double` 转为 `int`。

> [!IMPORTANT] 花括号检查所在的那一次转换
> **对象创建时使用花括号，不会使它以后的普通赋值自动拒绝窄化。**当前标量对象的某次赋值若在右侧使用花括号列表，则在这次列表转换位置应用相应检查。判断时应看花括号放在哪里，而不是只看对象最初怎样定义。

## 花括号不会追踪表达式内部

外层列表初始化接收的是整个初始化表达式提供的值。表达式内部的传参、返回等转换仍按各自位置的规则进行。下面是一个语言上合法的完整程序，辅助函数定义在 `main` 之前：

```cpp
#include <iostream>

int keep_count(const int count) {
    return count;
}

int main() {
    const int target{keep_count(3.8)};
    std::cout << target << '\n'; // 3
    return 0;
}
```

这次调用中的值依次经过三个位置：

| 位置 | 当前处理与结果 |
| --- | --- |
| 初始化形参 `count` | 普通实参 `3.8` 隐式转换为 `int` 值 3，再初始化只读的形参对象 |
| 返回调用结果 | 函数读取形参，返回 `int` 值 3 |
| 初始化 `target` | 外层花括号收到的已经是 `int`，不需要发生窄化转换 |

因此，外层花括号没有拒绝传参时的小数丢失。如果要让形参初始化处也进行列表初始化检查，保留函数定义，将 `main` 中定义 `target` 的那一行替换为：

```cpp
const int target{keep_count({3.8})}; // 错误：实参列表初始化 int 形参时发生窄化
```

`keep_count({3.8})` 的圆括号仍然表示函数调用，内部的 `{3.8}` 在实参位置用于列表初始化形参，因此会拒绝浮点数到整数的转换。把这个调用改成 `keep_count({3})` 则合法，形参和返回结果都为 3。

> [!IMPORTANT] 检查实际发生转换的位置
> **外层列表初始化不会自动把内部的传参、返回等过程也改为列表初始化。**判断某次转换是否受到窄化检查，应找到源值变为目标类型的具体位置，再确认那里采用了什么初始化形式。

> [!PRACTICE] 用花括号明确当前检查边界
> 默认使用花括号初始化，可以尽早暴露一类类型问题；同时仍需追踪值经过哪些转换。如果数值需要保留小数，整数形参本身就不符合该用途；即使外层初始化合法，也应继续核对内部转换的范围、精度和允许的信息损失。
