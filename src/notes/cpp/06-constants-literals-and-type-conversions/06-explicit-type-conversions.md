# 显式类型转换（Explicit Type Conversions）

## 把转换意图写进表达式

浮点数到整数的隐式转换会被列表初始化拒绝。如果程序确实需要截去小数部分，可以在表达式中明确写出转换请求，这称为**显式类型转换（explicit type conversion）**。这里讨论算术类型之间的数值转换，使用 C++ 的具名转换运算符 `static_cast`。

以下片段均放在 `main` 函数体内；注明替换时沿用所指片段，其余片段彼此独立。

先看直接用浮点值初始化整数对象的写法：

```cpp
const double source{21.8};
const int target{source}; // 错误：列表初始化拒绝浮点数到整数的窄化
```

保留 `source` 的定义，把 `target` 的定义替换为：

```cpp
const int target{static_cast<int>(source)}; // 合法：得到 21
```

`static_cast<目标类型>(表达式)` 是语言运算符，不需要包含头文件，也不加 `std::`。这里的 `<int>` 指定目标类型，圆括号里的 `source` 提供待转换的值。求值时先读取源对象，向零截断得到 `int` 值 21，再用这个结果初始化 `target`。

外层花括号接收到的已经是 `int` 值，因此该处不再需要从 `double` 转为 `int`。数值转换发生在 `static_cast` 表达式内部，仍须满足这次转换自身的数值条件。源对象 `source` 则保持原来的 `const double` 类型与保存的值。

> [!IMPORTANT] 显式转换产生目标类型的值
> **这里的算术类型转换产生目标类型的值，不会自行改变被读取的源对象的类型或值。**转换结果随后供外围运算、初始化或赋值使用；外层花括号按收到的结果检查，不会回头替内部的显式转换验证安全性。

## 数值规则没有改变

对同一种算术转换，`static_cast` 沿用相应的数值规则。浮点数转换为非 `bool` 的整数类型时，仍然向零截断：

```cpp
const int positive{static_cast<int>(7.9)};  // 7
const int negative{static_cast<int>(-7.9)}; // -7
```

7.9 转换为 7，−7.9 转换为 −7；这不是四舍五入，也不是自动选择最接近的整数。

如果截断后的值无法由目标整数类型表示，转换会产生未定义行为。无穷、NaN 以及远超目标整数范围的有限浮点值同样不能安全地转换为该整数类型。

下面**假设 `int` 为 32 位，`double` 的取值范围足以容纳 `1.0e100`**：

```cpp
const double source{1.0e100};
const int target{static_cast<int>(source)}; // 执行到这里会产生未定义行为
```

这里的类型关系允许写出转换，但这个值远超目标整数范围，执行转换仍会产生未定义行为。不能根据某次运行得到的值推断它会回绕、饱和或稳定地产生某个结果。

> [!IMPORTANT] 显式转换不会增加范围保证
> **浮点数转换为非 `bool` 的整数类型时，截断后的值必须能由目标类型表示；写出 `static_cast` 不会取消这一条件。**它本身不执行运行时范围检查，不会自动饱和到类型边界，也不提供失败返回值。转换前仍须确认实际值满足要求。

这些具体范围依赖目标类型与实现。接近边界时，应核对[整数类型的范围](../01-objects-types-and-variables/04-integer-types.md#标准整数类型)，再判断截断后的值是否能够表示。

## 转换位置决定运算类型

同样是把整数转换为 `double`，转换操作数与转换运算结果会得到不同的计算过程：

```cpp
const int total{9};
const int count{4};

const double after{static_cast<double>(total / count)};
const double before{static_cast<double>(total) / count};
```

两行都初始化 `double` 对象，但 `static_cast` 圆括号包住的表达式不同：

| 对象 | 除法与转换的过程 | 保存的结果 |
| --- | --- | --- |
| `after` | 先计算 `int` 值 9 除以 `int` 值 4，得到整数商 2，再把 2 转为 `double` | 2.0 |
| `before` | 先把 `total` 的值转为 `double` 值 9.0，再按浮点除法计算 | 2.25 |

第二行中，一个操作数已经是 `double`，另一个操作数 `count` 的值便按通常算术转换转为 `double` 值 4.0，除法因此用 9.0 与 4.0 计算。第一行的整数商则在转换之前已经形成，丢弃的小数部分无法通过后续转换恢复。

> [!IMPORTANT] 转换位置影响参与运算的类型
> **运算采用什么类型，由操作数及该运算的规则决定，接收结果的对象类型不会倒过来改变运算。**显式转换放在操作数处，可以影响随后运算采用的类型；放在整数除法外侧，则只能转换已经得到的整数商，无法恢复被丢弃的小数部分。

## 显式不等于合理

上面两种转换位置都可以合法，也可能分别符合不同用途。如果需要带小数的商，就要在整数除法发生前使操作数采用浮点类型；如果需要整数商，再把它用于浮点计算，先除后转可以符合目的。转换位置应由需要保留哪一种计算结果决定。

> [!PRACTICE] 按所需结果选择类型与转换位置
> 显式转换使代码审阅者能够看见转换意图，合理性仍需结合数据与计算目的判断。进行算术类型转换前，应确认：
>
> - 目标类型是否符合数据接下来的职责；
> - 当前值是否满足该转换具有定义行为所需的条件；
> - 精度或小数部分的丢失是否符合用途；
> - 转换位置是否使运算按预期类型进行。
>
> 如果源类型与目标类型本来就一致，不需要为了显得明确而添加 `static_cast`。如果转换本身暴露了数据模型不匹配，也不应使用显式转换掩盖设计问题。
