# 对象、存储与地址

此前已经从类型、值和生命周期认识对象。对象能够在一段时间内持续保存状态，还依赖另一个基础条件：程序必须为它提供能够容纳其表示的存储区域。

```cpp
int engine_temperature{78};
engine_temperature = 81;
```

初始化完成后，程序中存在一个名为 `engine_temperature` 的 `int` 对象。赋值把它保存的值从 `78` 改为 `81`，但没有创建第二个对象，也没有让原对象迁移到另一处存储。对象仍然是同一个对象，只是存储区域中表示的状态发生了变化。

## 对象与存储区域

存储区域（region of storage）是一段可用于保存对象表示的连续存储。对象则是具有类型和生命周期的程序实体。两者密切相关，但不是同一个概念：

- 存储区域回答“哪些存储位置可供使用”；
- 对象回答“当前有什么类型的实体在这段存储中存在”；
- 对象的值回答“这个实体当前表示什么状态”。

单独观察一串原始 bytes，通常不能由 bytes 自身判断其中是否存在对象、对象是什么类型，以及对象的生命周期是否已经开始。C++ 也不要求每个对象旁边都额外保存一份运行时类型标签。编译器根据声明、初始化、生命周期和类型规则解释源码中的对象访问。

对于当前讨论的普通局部对象，可以先建立下面的关系：

```text
取得大小与对齐都合适的存储
              ↓
完成对象初始化
              ↓
对象的生命周期开始
              ↓
对象在该存储区域中保存状态
```

存储位置本身并不能永久证明某个对象仍然存在。对象生命周期结束以后，即使相同的存储位置仍然存在，原对象也已经不能继续作为那个类型的对象访问。

## 字节与内存地址

现代通用计算机通常按字节寻址（byte-addressable）。在当前使用的主流平台模型中，一个 byte 包含 8 bits；每个可寻址 byte 位置都有一个用于定位它的编号，这个编号称为内存地址（memory address）。

可以把一小段存储抽象为连续排列的 byte 位置：

```text
地址       0x1000    0x1001    0x1002    0x1003
          ┌────────┬────────┬────────┬────────┐
byte 位置 │ byte 0 │ byte 1 │ byte 2 │ byte 3 │
          └────────┴────────┴────────┴────────┘
```

相邻 byte 的地址相差 `1`。地址 `0x1000` 标识第一个位置，`0x1001` 标识紧随其后的下一个位置。地址回答“存储位置在哪里”，该位置中的 bit pattern 则回答“这里当前保存了什么”。

地址不是额外存放在对应 byte 旁边的一份数据。它是处理器、运行环境和程序用来定位存储位置的编号；编号的含义还依赖它所属的地址空间。

## 地址的文本表示

地址本身没有十六进制或十进制格式。机器进行寻址时处理的是二进制表示；调试器、反汇编器和日志工具需要展示地址时，通常选择十六进制，因为一位十六进制数字恰好对应 4 bits：

```text
二进制：    0001 0010 1010 1111
十六进制：  0x12AF
```

因此，`0x00007FF6A12FF9C0` 只是某个地址值的人类可读文本。采用十六进制是工具与工程表达的惯例，不是 Windows、Linux 或内存硬件规定地址必须具有的书写格式。同一个地址值也可以写成十进制，只是通常更难观察 bits 的分组和边界。

## 对象占用的存储

对象通常不只占用一个 byte。对象为保存自身状态而占用的全部 bytes 构成对象表示（object representation）。假设当前实现中的 `int` 占用 4 bytes，并且 `engine_temperature` 从地址 `0x1000` 开始存放：

```text
地址                  0x1000    0x1001    0x1002    0x1003
                     ┌────────┬────────┬────────┬────────┐
engine_temperature   │ byte 0 │ byte 1 │ byte 2 │ byte 3 │
                     └────────┴────────┴────────┴────────┘
                       ↑
                       对象起始地址
```

这四个连续 bytes 共同构成该对象的存储区域。各 byte 中具体保存怎样的 bit pattern，取决于 `int` 的值表示以及平台规则；对象的起始地址是其对象表示中第一个 byte 的地址，在当前假设中为 `0x1000`。

对象名称、类型、当前值、存储范围和地址分别表达不同信息：

| 信息 | 当前示例 |
| --- | --- |
| 名称 | `engine_temperature` |
| 类型 | `int` |
| 当前值 | `81` |
| 存储范围 | 假设为 `0x1000`～`0x1003` |
| 起始地址 | 假设为 `0x1000` |

名称让源码能够直接指定对象，类型决定程序怎样解释和操作对象表示，值描述对象当前状态，地址则定位对象所占存储的起点。只知道地址数值，不能反推出其位置当前必然存在 `int` 对象，也不能证明那个对象仍处于生命周期内。

## 大小与对齐

类型不仅决定对象需要多少存储，还可以提出对齐要求（alignment requirement）。对齐规定对象允许从哪些地址开始放置；一段存储即使 byte 数量足够，起始地址不满足类型的对齐要求，也不适合在该位置放置这种对象。

假设某个实现中的 `int` 占用 4 bytes，并要求按 4-byte 边界对齐：

```text
地址       能否作为该 int 对象的起点
0x1000     可以
0x1001     不可以
0x1002     不可以
0x1003     不可以
0x1004     可以
```

这只是一个具体实现下的示例。C++ 不要求所有类型的大小等于对齐要求，也不能从“某类型占用 4 bytes”直接推出它一定要求按 4-byte 边界对齐。大小回答需要多少连续存储，对齐回答起始位置必须满足什么边界，两者应分别理解。

对齐既服务于处理器访问要求，也会影响对象之间的空隙和复合对象的整体布局。原始地址数值看起来位于已映射内存中，仍不代表它满足任意对象类型的大小、对齐和生命周期条件。

## 地址空间

一组可用于定位存储的地址及其组织方式构成地址空间（address space）。地址数值只有放在相应地址空间中才具有完整含义；同一个数值出现在不同地址空间中，不必表示同一处存储。

地址空间也不表示其中每个可能的编号都能被程序访问。运行环境可以让一部分范围映射到实际存储，让另一部分范围保持未映射，或为不同范围设置不同访问权限。仅仅写出一个处于数值范围内的地址，不会使那里自动出现可访问对象。

## 虚拟地址与物理地址

在现代桌面和服务器操作系统中，普通进程观察到的通常是虚拟地址（virtual address），而不是内存芯片直接使用的物理地址（physical address）。处理器的内存管理单元（Memory Management Unit, MMU）结合操作系统维护的页表，把进程中的虚拟地址转换到相应的物理存储：

```text
C++ 对象使用的存储
          ↓
当前进程中的虚拟地址
          ↓
MMU 与页表
          ↓
物理存储位置
```

这层映射使不同进程能够拥有彼此隔离的地址空间，也使连续的虚拟地址可以对应分散的物理存储。操作系统还可以按页控制读、写和执行权限，并在真正需要页面时再准备物理资源。

因此，两个进程中数值相同的虚拟地址通常不会发生冲突：地址转换还使用当前进程的地址空间上下文，它们可以映射到完全不同的物理位置。反过来，操作系统也可以受控地让不同虚拟地址映射同一份物理存储，从而实现共享。

C++ 标准不要求实现采用虚拟内存。虚拟地址、页表和 MMU 属于现代托管系统的常见实现；运行在没有这套机制的平台上的 C++ 程序仍然遵循语言关于对象和存储的规则。

## 栈与堆不是两种地址

栈（stack）和堆（heap）描述常见实现中采用不同管理方式的存储区域，不是两种不同格式的地址。它们通常都位于进程的虚拟地址空间中，其中的 byte 仍然通过普通地址定位。

普通局部对象经常使用调用栈中的存储，动态管理的对象通常使用被称为堆的区域，但这不是判断地址含义的规则。编译器优化、运行库和具体平台可以采用不同实现，只要程序表现符合 C++ 规定的行为。

因此，一个地址数值本身不会携带“这是栈地址”或“这是堆地址”的语言标签。栈与堆影响存储怎样取得、持续多久以及由谁管理，不改变“地址用于定位存储位置”这一基础概念。

## 语言模型与实际机器

前面的存储图是用来解释 C++ 程序行为的模型，不保证编译后的程序一定在 RAM 中逐字节保留完全相同的布局。C++ 主要规定程序应呈现什么可观察行为，而不是编译器必须执行哪些机器指令。

如果程序无法观察某个对象的独立存储，编译器可以把它的值保存在寄存器中、合并计算，甚至完全消除这份物理存储。只要程序开始观察对象之间的地址关系，实现仍必须让结果与语言模型保持一致。优化改变的是实现方式，不应改变源码能够观察到的对象、值和地址关系。

这一区分避免两个相反误解：对象不是脱离存储存在的纯名称，但源码中的每个对象也不必机械对应一块始终驻留在物理内存芯片中的区域。

## 核心结论

- 对象具有类型、生命周期和当前值，并在生命周期内使用满足大小与对齐要求的存储。
- 地址用于定位某个地址空间中的 byte 位置；地址不是对象当前保存的值，也不携带对象类型。
- 对象通常占用多个连续 bytes，其起始地址是对象表示中第一个 byte 的地址。
- 十六进制只是地址的常用文本表示，不是地址在内存中的固有格式。
- 现代操作系统通常向进程提供虚拟地址；物理地址转换、栈和堆属于实现层面的存储组织。
- 地址数值本身不能证明相应位置存在某种类型的对象，也不能证明对象生命周期仍在继续。
