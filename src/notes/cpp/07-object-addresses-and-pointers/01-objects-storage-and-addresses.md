# 对象存储与地址（Object Storage and Addresses）

## 对象的值之外，还有位置

两个对象当前保存相同的数值，并不意味着它们共用同一片存储。下面的两条定义分别创建一个对象，初值都是 7：

这里讨论代码块中独立创建、已经初始化的基本类型对象。以下片段均放在 `main` 函数体内；注明接续时保留对应定义，其余片段彼此独立。

```cpp
int value{7};
const int other{7};
```

`value` 的类型是 `int`，可以在后续赋值；`other` 的类型是 `const int`，初始化后只供读取。两个名称分别用于访问两个对象，每个对象都占据自己的存储（storage）。要描述它们各自位于哪里，还需要地址。

## 地址描述存储位置

C++ 抽象机（abstract machine）把程序可用的内存描述为一个或多个连续的字节（byte）序列，每个字节都有唯一的地址（address）。字节是存储计量的基本单位，一个字节至少包含 8 个比特，具体位数由实现规定。

> [!IMPORTANT] 对象地址标识所占存储的起点
> **对于这里的独立基本类型对象，对象占据一段连续字节，对象地址是它所占第一个字节的地址。**地址描述存储位置，当前值描述保存的内容，名称则让代码能够指代对象；三者需要分别判断。

下面**假设目标实现中的 `int` 对象占 4 个 C++ 字节**，用 A 与 B 分别标记开篇两个对象的首字节地址。A、B 只是示意标签，不是代码中的变量或实际地址数字；两行图形不表示这两段存储必然相邻，也不规定它们的排列顺序。

```text
value（int，当前值 7）
地址 A ──► [ byte ][ byte ][ byte ][ byte ]
           <-------- 对象所占存储 -------->

other（const int，当前值 7）
地址 B ──► [ byte ][ byte ][ byte ][ byte ]
           <-------- 对象所占存储 -------->
```

每个方格表示一个字节的位置，当前值 7 是整个对象按类型规则解释的结果，不是每个字节各自保存一个整数 7。这里的四个方格只用于展示“对象占据一段存储，地址标记它的起点”的关系；实际字节数应核对目标实现的[整数类型规格](../01-objects-types-and-variables/04-integer-types.md#标准整数类型)，无需把 4 当成所有实现的固定值。

在开篇的两条定义之后继续执行：

```cpp
value = 9;
```

这次赋值改变 `value` 保存的值，没有创建另一个对象，也没有改变它所占存储的位置：

| 对象 | 赋值前的值 | 赋值后的值 | 这段生命周期内的地址 |
| --- | --- | --- | --- |
| `value` | 7 | 9 | 始终为 A |
| `other` | 7 | 7 | 始终为 B |

> [!IMPORTANT] 修改当前值不会改变对象地址
> **在这里同一个对象的生命周期内，赋值改变当前值，不改变对象的身份与地址。**同时存活的两个独立基本类型对象占据不同存储、具有不同地址，即使保存的数值相同。仅凭一个数值，不能确定它来自哪个对象。

## 地址与存储管理方式

地址回答“位于哪里”，存储期（storage duration）描述相应存储按照什么时间规则保持可用，生命周期（lifetime）则描述对象何时实际存在。

把开篇的两条定义和赋值放入内层代码块，得到下面的独立片段：

```cpp
{
    int value{7};
    const int other{7};

    value = 9;
} // 两个局部对象的生命周期结束
```

这里的两个对象具有自动存储期，相应存储按代码块的执行规则管理。取得满足类型要求的存储并完成初始化后，各自的生命周期开始；执行离开这个代码块时，各自的生命周期结束。更完整的初始化与退出条件见[局部数值对象的生命周期](../03-blocks-scope-and-lifetime/03-automatic-storage-duration-and-local-object-lifetime.md#生命周期的开始与结束)。

在这个独立片段中，仍用 A 表示 `value` 对象的地址。该对象结束后，原来的存储位置可能被后续对象复用；如果发生复用，可以出现下面的过程：

| 阶段 | 地址 A 所对应的位置 |
| --- | --- |
| `value` 仍在生命周期内 | 由 `value` 占据，赋值后保存 9 |
| `value` 的生命周期结束 | 原对象已经不存在，旧内容不要求立即被清零 |
| 后续对象复用这片存储 | 由另一个对象占据，新对象具有自己的身份、类型和值 |

这是允许出现的复用关系，不保证某两个局部对象实际获得相同地址。即使后来观察到相同地址，也不能因此把新对象认作原来的 `value`。

> [!IMPORTANT] 地址不能代替生命周期判断
> **取得或记住地址，不会延长对象的生命周期；同一地址在不同时刻也不保证对应同一个对象。**原对象结束后，不能只凭地址记录继续把这片存储当作原对象读写。位置是否相同与原对象是否仍然存在，需要分别判断。

## 语言地址与系统地址

C++ 规定程序能够观察到的对象、存储和地址关系，具体实现负责用实际机器资源保持这些关系。这不要求每个源代码对象都在物理内存里保留一个固定格子；在保持程序可观察行为的前提下，实现可以把值留在寄存器中，或省去不必要的存取。

调试器常把地址显示成 `0x` 开头的十六进制文本。这是一种显示方式，不能据此把对象地址当作普通整数。现代桌面操作系统通常还会让程序使用虚拟地址（virtual address），再由操作系统与处理器共同完成到物理地址（physical address）的转换。

> [!IMPORTANT] 语言地址与机器实现分开判断
> **对象占据存储、地址标识位置，是这里采用的语言模型；具体机器表示以及与物理存储的对应关系由实现承担。**看到十六进制地址，不等于看到了物理内存编号，也不能只凭显示的地址判断对象是否仍然存活。

附章[《虚拟内存与地址转换》](deep-dives/01-virtual-memory-and-address-translation.md#页面页表与-mmu)解释常见系统怎样实现这层映射。图中的 A、B 则只用于表达当前对象与存储位置的关系，不依赖某个系统的实际地址布局。
