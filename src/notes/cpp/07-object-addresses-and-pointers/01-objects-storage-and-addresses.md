# 对象存储与地址（Object Storage and Addresses）

## 对象的值之外，还有位置

对象在生命周期内具有类型、身份和当前值，也占据一片存储区域。两个对象即使类型相同、当前值也相同，仍然是彼此独立的实体：

```cpp
double front_left_pressure_bar{2.4};
double front_right_pressure_bar{2.4};
```

修改其中一个对象，不会修改另一个对象。它们各自拥有独立身份，也各自占据存储：

```cpp
front_left_pressure_bar = 2.2;
```

这次赋值改变的是 `front_left_pressure_bar` 保存的值。对象本身仍是原来的对象，`front_right_pressure_bar` 也仍然保存 `2.4`。

## 地址描述存储位置

C++ 抽象机（abstract machine）把程序可用的内存描述为一个或多个连续 byte 序列，每个 byte 都有唯一的地址（address）。对于本章使用的独立基本类型对象，对象地址就是它所占第一个 byte 的地址。

地址回答的是“这个对象位于哪一片存储”，而对象的值回答的是“这个对象当前保存什么”。两者不能混为一谈：

- 两个对象可以保存相同的值，却位于不同地址；
- 同一个对象可以改变当前值，而身份和地址仍然不变；
- 知道一个数值，并不能据此找到保存它的某个特定对象。

**对象地址描述对象所占存储的位置，不是对象保存的业务值，也不是对象名称的另一种写法。**

## 地址与存储管理方式

地址描述对象所在的位置，存储期描述相应存储按照怎样的时间规则保持可用，具体实现则可以选择不同的机器资源承载它们。这些不是同一个分类维度。

```cpp
{
    int engine_temperature_c{78};
}
```

`engine_temperature_c` 在其生命周期内占据存储并具有地址。离开代码块后，它的生命周期结束；曾经知道这片存储位于哪里，也不能让对象继续存在。**地址描述位置，但不控制对象的生命周期。**

## 语言地址与系统地址

C++ 规定程序能够观察到的对象、存储和地址关系，但没有把对象地址规定为普通整数，也没有要求它直接等于物理内存编号。

调试器常把地址显示成 `0x` 开头的十六进制文本，这是一种便于阅读的表示方式，不是地址在语言中的本质。现代桌面操作系统通常还会让程序使用虚拟地址，再由操作系统与处理器共同完成到物理存储的转换。

附章[《虚拟内存与地址转换》](deep-dives/01-virtual-memory-and-address-translation.md)解释常见系统怎样实现这层地址关系。C++ 主线采用语言层面的契约：对象占据存储，地址标识对象所在的位置。
