# 空指针、悬空指针与有效性（Null Pointers, Dangling Pointers, and Validity）

## 明确表示没有目标

尚未选定目标，或者某次操作没有找到目标时，程序需要明确表示“当前没有目标”。指针字面量（pointer literal）`nullptr` 可以转换为相应指针类型的空指针值（null pointer value），用来表达这种状态。

以下代码片段均位于 `main` 函数体内；未注明接续或替换时，各片段彼此独立：

```cpp
int* target{nullptr};
```

`target` 是已经初始化的 `int*` 对象，保存一个确定的空指针值。`nullptr` 自身的类型是 `std::nullptr_t`，这是独立的类型，不属于指针类型；用它初始化 `int*` 时，会发生空指针转换，得到 `int*` 类型的空指针值。

空指针值表达的是语言层面的“没有目标”，具体表示由实现决定，不能把它等同于某个固定的整数地址格式。

> [!IMPORTANT] 空指针的含义与使用边界
> **空指针具有确定的值，明确表示当前没有目标。**它可以被保存、复制、赋值，并与 `nullptr` 比较，但不能用于间接访问对象。

## 四种需要分开的状态

空指针具有确定值；未初始化的自动存储期指针具有不确定值（indeterminate value）。曾经指向某个对象、后来失去可访问的原目标，且没有重新建立有效指向的指针，通常称为悬空指针（dangling pointer）。

下面只比较当前普通 `int*` 示例会遇到的四种状态，不穷举标准中的全部指针值类别。悬空一行限定为原局部对象离开其代码块、自动存储期已经结束的情形：

| 指针状态 | 复制指针值或与 `nullptr` 比较 | 通过指针读取或修改对象 |
| --- | --- | --- |
| 指向仍在生命周期内的对象 | 可以 | 须符合类型与访问限制；读取 `int` 还要求目标具有确定值，修改则要求该路径允许修改 |
| 空指针 | 可以 | 没有目标，不能间接访问对象 |
| 悬空：原局部目标的自动存储期已结束 | 对旧指针值的这些使用具有实现定义的行为，不能作为可移植的检查办法 | 对旧指针值执行间接访问会产生未定义行为 |
| 未初始化的自动存储期指针 | 求取其不确定值会产生未定义行为 | 不能使用其不确定值进行间接访问 |

复制或比较指针值，需要先读取指针对象保存的值；间接访问则进一步依赖目标对象的状态。函数体内具有自动存储期的指针对象如果没有初始化，不会自动成为空指针。下面是独立的错误示例：

```cpp
int* target;
const bool has_target{target != nullptr}; // 未定义行为：读取不确定值
```

`int* target;` 定义了指针对象，但没有为它设置确定值。这条定义本身是良构的，也尚未求取其中的不确定值；错误发生在比较需要读取这个指针值时。

> [!IMPORTANT] 空指针与未初始化指针
> **“明确没有目标”和“尚未设置可用的指针值”是两种不同状态。**在 C++23 中，未初始化的自动存储期指针在其不确定值被有效赋值替换前，不能通过求取这个值来检查、复制或间接访问；与 `nullptr` 比较也需要求取指针值。

## 指针存在不等于目标存在

外层指针可以保存内层对象的地址，但这不会改变两者各自的生命周期。下面是另一个独立的错误示例：

```cpp
int* target{nullptr};

{
    int value{7};
    target = &value;

    *target = 9;
}

const int saved{*target}; // 未定义行为：value 的生命周期和存储期均已结束
```

在内层代码块中，`value` 仍然存活，`target` 也确实指向它，因此 `*target = 9;` 可以修改这个对象。离开代码块时，`value` 的生命周期和关联存储期结束。外层的 `target` 仍然存在，也没有自动变成空指针，但它已经失去原来的活对象目标，成为悬空指针。

> [!IMPORTANT] 指针对象与目标的独立生命周期
> **保存或复制对象地址，不会延长目标对象的生命周期；目标的生命周期结束，也不会自动把指针改为空指针。**指针对象仍然存活、曾经正确初始化，都不足以保证现在可以访问原目标。

> [!WARNING]
> 在这个局部对象离块的例子中，指针值还因为所指存储期结束而成为标准所说的无效指针值（invalid pointer value）。对这个旧值执行间接访问本身就会产生未定义行为；C++23 对这个旧值的复制和比较只给出实现定义的行为。因此，不能靠读取旧值并与 `nullptr` 比较来可移植地检查是否悬空。

“悬空”描述已经失去可访问原目标的关系；上面警告中的“无效指针值”则由所指存储期结束这一条件决定。当前例子同时满足两者，但不能把所有悬空情形都直接等同于这条存储期规则。

如果把上例最后一行的错误读取替换为下面这条赋值，情况就不同：

```cpp
target = nullptr;
```

此时 `target` 自身仍在生命周期内，也允许赋值。这条语句把新的空指针值写入 `target`，不需要读取它先前保存的值，也不访问已经结束生命周期的 `value`。赋值后，可以正常将 `target` 与 `nullptr` 比较。

> [!IMPORTANT] 读取旧值与为指针赋新值
> **直接给仍存活、允许赋值的指针对象赋予 `nullptr`，不需要读取它先前保存的值。**这与读取、复制或比较旧指针值是不同的操作；给一个指针赋为空值也不会改写其他指针副本保存的值。

## 空值检查的能力边界

空值检查适用于目标可能明确不存在的关系。下面这个独立示例先把 `target` 初始化为空指针：

```cpp
int value{7};
int* target{nullptr};

if (target != nullptr) {
    *target = 9;
}
```

这里条件为 `false`，赋值不执行，`value` 保持为 `7`。如果只把第二行替换为 `int* target{&value};`，其他代码保持原样，检查结果和执行行为就会改变：

| `target` 的初值 | 条件 `target != nullptr` | 执行后的 `value` |
| --- | --- | --- |
| 空指针值 | `false`，跳过赋值 | `7` |
| 指向 `value` 的指针值 | `true`，执行赋值 | `9` |

两种情况中的指针值都可以正常读取和比较。第二种情况还通过代码中的对象关系保证：`value` 在检查和赋值期间一直存活，并允许通过这里的 `int*` 修改。空值检查只负责区分这两种初值，不负责建立这些额外保证。

> [!IMPORTANT] 空值检查与目标有效性
> **在指针值可以正常读取和比较的前提下，空值检查只区分“空”与“非空”，不会验证目标的生命周期。**通过非空分支访问对象，还必须有目标存活、类型与访问权限相符的独立依据。普通指针值不会自动追踪目标的生死。

当前范围内，安全的使用约束可以归结为：

- 在定义位置为指针设置明确初值，使用可用目标的指针值或 `nullptr`；
- 每次通过指针访问目标时，保证目标的生命周期覆盖此次访问，并符合类型、可读值与修改权限的相应要求；
- 原目标失效后，不再读取旧指针值来检查目标；仍需使用的可赋值指针对象，可以直接接受 `nullptr` 或指向另一个可用目标的值。
