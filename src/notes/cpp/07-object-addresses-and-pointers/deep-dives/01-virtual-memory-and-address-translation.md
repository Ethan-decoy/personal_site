# 虚拟内存与地址转换（Virtual Memory and Address Translation）

## C++ 地址与平台实现

C++ 抽象机规定对象占据存储、byte 具有地址，指针值能够表示相应对象的地址。它没有要求指针采用某种固定 bit pattern，也没有要求程序观察到的地址直接等于物理内存编号；指针类型的值表示由具体实现决定。

现代 Windows 与 Linux 系统通常让进程（process）使用虚拟地址（virtual address）。程序执行内存访问时，处理器与操作系统维护的映射会把虚拟地址转换为物理地址（physical address），再访问实际机器资源。

**虚拟地址转换是常见平台实现 C++ 可观察行为的机制，不是 C++ 指针语义本身。**

## 为什么需要虚拟地址

物理内存是整台机器共享且不断变化的资源。如果每个程序都直接依赖物理位置，程序将不得不处理其他进程占用了什么区域、数据能否暂时移出内存，以及哪些位置允许读写。

虚拟地址空间（virtual address space）在程序与物理资源之间增加一层映射，主要带来几项能力：

- **隔离**：不同进程拥有各自的地址转换上下文，不能仅凭一个本进程地址访问另一进程的私有存储；
- **保护**：映射可以附带可读、可写、可执行等权限；
- **布局灵活性**：程序使用与物理页位置解耦的虚拟地址布局；在相应映射保持期间，底层物理页可以由系统安排在不同位置；
- **按需提供资源**：虚拟范围可以先建立，实际物理存储在访问需要时再准备；
- **受控共享**：多个虚拟映射可以在操作系统安排下指向同一底层存储。

因此，虚拟内存不只是“物理内存不够时使用磁盘”。它首先建立隔离、保护与映射抽象，换页只是这套机制可以支持的一种资源管理方式。

## 页面、页表与 MMU

常见系统按页面（page）与页框（page frame）这一离散粒度管理虚拟地址空间和物理内存；一个平台可以支持一种或多种页面大小。这些大小由平台决定，不属于 C++ 语言保证。

虚拟地址可以概念性地拆成虚拟页号和页内偏移：

```text
虚拟地址  = [ 虚拟页号 | 页内偏移 ]
                   │
                   │  当前进程的页表
                   ▼
物理地址  = [ 物理页框 | 相同偏移 ]
```

页表（page table）记录虚拟页到物理页框的映射以及访问权限。内存管理单元（Memory Management Unit，MMU）是负责执行地址转换与权限检查的硬件部件。页表通常采用多级结构，避免为虚拟地址空间中的大片空洞预先保存完整映射。

一次内存访问的大致关系是：

```text
程序使用虚拟地址
        ↓
当前进程的地址转换上下文
        ↓
查询地址转换缓存；必要时完成页表查询
        ↓
得到物理页框与访问权限
        ↓
访问目标存储
```

虚拟地址中的页内偏移通常原样保留；页表转换的是它所处的虚拟页。一个虚拟地址存在于数值范围内，并不自动表示当前已经有可访问映射。

## 相同虚拟地址为什么不会冲突

每个进程具有自己的虚拟地址空间和相应地址转换上下文。同一个数值形式的虚拟地址，在两个进程中可以通过不同页表映射到不同物理页框：

```text
进程 A：虚拟页  ──A 的页表──> 物理页框 X
进程 B：虚拟页  ──B 的页表──> 物理页框 Y
```

两个进程使用相同虚拟地址并不意味着访问同一对象，也不会因为地址数字相同而彼此覆盖。

操作系统也可以有意让多个虚拟页映射到同一个物理页框。共享映射（shared mapping）中的各方访问的是同一底层存储；如果映射允许共享写入，对同一 bytes 的修改可以经其他映射被观察到。这不是“两个副本自动同步”，而是底层并不存在两份独立数据。多个执行主体如何协调并发读写，仍是另一项独立约束。

写时复制（copy-on-write，COW）采用另一种关系：多个映射最初共享同一物理页并限制直接写入；某一方首次尝试修改时触发异常处理，操作系统为它复制页面并更新映射。虚拟地址可以保持不变，但写入方随后访问的是自己的物理副本。

## TLB 未命中、缺页与缓存未命中

地址转换和数据访问各有自己的缓存与异常路径，几个常见术语不能混为一谈：

| 现象 | 缺少什么 | 常见后续动作 |
| --- | --- | --- |
| TLB 未命中（TLB miss） | 转换后备缓冲器中没有现成地址映射 | 查询页表并缓存转换结果 |
| 缺页异常（page fault） | 当前访问需要操作系统处理映射、驻留状态或权限 | 建立页面、完成 COW、载入数据，或拒绝访问 |
| CPU 缓存未命中（CPU cache miss） | 数据缓存中没有目标缓存行（cache line） | 从更低层缓存或内存层级取得数据 |

转换后备缓冲器（Translation Lookaside Buffer，TLB）缓存近期虚拟页到物理页框的转换。TLB miss 通常只意味着需要重新查询页表，不等于访问非法，也不等于数据必须从磁盘读取。页表查询可以由硬件页表遍历器（page-table walker）完成，也可以由操作系统参与，具体方式取决于体系结构。

page fault 同样不必然是程序错误：按需分配、数据尚未驻留和 COW 都可能正常触发它。若地址没有合法映射或访问违反权限，操作系统才会拒绝此次访问，并可能终止进程。CPU cache miss 关注的是数据是否位于处理器缓存，与地址转换是否已有缓存是不同问题。

## 回到 C++ 对象生命周期

系统仍保留某个虚拟映射，不代表某个 C++ 对象仍在生命周期内。对象生命周期是语言语义；页面是否映射、物理 bytes 是否还保留旧内容，则是平台资源状态。

因此，通过悬空指针访问对象产生未定义行为，不保证一定触发 page fault 或以“段错误”结束。旧地址可能仍映射到可读写页面，错误访问也可能暂时看似成功，甚至破坏后来占用同一存储的其他数据。

调试器把指针显示为十六进制数时，在这些常见系统上通常展示的是进程语境中的虚拟地址形式。它便于定位和比较当前调试状态，但不能把指针降格成普通整数，也不能代替 C++ 对类型、对象身份和生命周期的判断。
