# 引用的语言语义与实现模型（Reference Semantics and Implementation Models）

C++ 规定引用绑定哪个对象、通过引用名称访问哪个对象；实现再选择怎样定位目标。实现可能保存目标地址，也可能直接利用编译时已知的绑定关系。语言中的引用与机器中用于定位目标的信息，需要分开理解。

## 语言规定绑定关系

下面的局部片段位于 `main` 的函数体内，后面的取地址示例沿用其中的对象：

```cpp
int value{7};
int& alias{value};

alias = 9;
```

`alias` 是引用变量，绑定到已有的 `value` 对象。名称表达式 `alias` 是指定 `value` 的 `int` lvalue，因此赋值把 `value` 改为 `9`。引用没有创建另一份整数状态，绑定也没有因赋值而改变。

这些语言规则已经确定了程序访问哪个对象、修改后的值是什么。生成代码需要完成这些行为，但不必为每个源码名称安排一个单独的机器存储位置。

### 局部绑定可以采用不同表示

标准没有规定引用是否需要存储。对开篇的局部代码，编译器在分析初始化时就知道：`alias` 与 `value` 指定同一个对象。完成赋值可以采用不同的实现思路。

一种思路是直接利用已知目标，生成修改 `value` 的操作，无须额外保存一份目标地址。另一种思路是保留一个地址槽，即用于保存目标地址的机器存储位置，后续操作再根据这份记录找到目标。

下面是两种实现思路的对照，不指定某个编译器必然生成哪一种：

| 实现思路 | 初始化绑定怎样体现 | 执行 `alias = 9;` 时怎样找到目标 |
| --- | --- | --- |
| 直接使用已知目标 | 编译分析中确定两个名称对应同一个对象 | 直接生成对 `value` 的操作 |
| 保留目标地址 | 在地址槽中记录 `value` 的地址 | 取得记录的地址，向对应的整数存储位置写入 `9` |

两种思路都要使通过 `value` 或 `alias` 进行的访问落到同一个对象上。第二种思路中额外保存的是定位目标的信息，整数状态仍属于 `value`；这份实现记录不会成为源码中的另一个引用对象。

> [!IMPORTANT] 引用实体与实现存储
> **引用不是对象，描述的是 C++ 中的实体种类；实现是否为它保存目标地址，是表示方式的问题。**标准不规定引用是否需要存储。实现即使保留地址记录，也不会因此让引用成为可由源码独立操作的对象。

## 源代码不能取得引用自身的对象地址

接续开篇的局部片段，对两个名称分别取地址：

```cpp
const bool same_address{&alias == &value}; // true
```

`alias` 作为表达式时指定 `value`，因此 `&alias` 和 `&value` 都是指向同一个整数对象的 `int*` 值。若实现保留了地址槽，槽中记录的是 `value` 的地址；`&alias` 的结果仍是这个目标地址，而不是地址槽的位置。

这与指针对象不同：

```cpp
int* target{&value};
int** const pointer_address{&target};

*pointer_address = nullptr;
```

这里的 `int**` 表示指向 `int*` 对象的指针。`pointer_address` 保存指针对象 `target` 自身的地址，`*pointer_address` 因而指定 `target`。最后一行把 `target` 改为空指针；`value` 仍保存 `9`，`alias` 仍绑定到 `value`。

`target` 是源码中的独立对象，取地址和后续访问都能落到它自身。对引用名称取地址则落到被绑定对象，普通 C++ 取地址运算不会暴露用于实现绑定的地址槽。

> [!IMPORTANT] 引用名称取地址的目标
> **对引用名称取地址，得到被绑定对象的地址。**这项表达式语义不会因实现保存了额外的目标地址而改变。对指针对象取地址则取得指针对象自身的地址，引用没有与之对应的独立“引用对象地址”。

## 优化可以消除具体表示

下面是独立的函数定义，放在 `main` 之前。它使用与开篇相同的局部绑定，并按值返回整数结果：

```cpp
int local_result() {
    int value{7};
    int& alias{value};

    alias = 9;
    return value;
}
```

调用结果总是整数 `9`。编译器能够确定两名称对应同一个对象，也能确定赋值后的值，因此可以直接生成返回 `9` 的代码，不再为这次计算保留对象的实际访存步骤或额外的目标地址记录。

源码分析中仍然存在 `value` 对象和 `alias` 的绑定关系，语言规则也仍然约束程序的合法性。被化简的是完成计算所需的机器操作。

在某些便于调试的构建中，实现也可能保留 `value` 的位置和用于记录绑定目标的地址槽。是否保留这些位置，由编译器、目标平台和具体选项共同决定，不能只凭“调试构建”或“优化构建”的名称确定。

> [!IMPORTANT] 优化保留行为，允许改变表示
> **优化必须保持源程序在相应语境中的可观察行为，不要求逐一保留源码中的存储和操作形式。**局部引用可以没有独立的运行期地址记录，相关对象也可能无需实际访存；这些变化不改变源码中的对象身份和引用绑定规则。

## 引用不是隐藏指针

地址槽的实现思路可以帮助理解编译器怎样定位目标。把引用直接等同于“自动执行间接访问的 `int* const` 对象”，会把语言实体与实现记录混在一起。

上面的 `target` 是指针对象，其指针值可以通过源码赋值改写，`&target` 也能取得它自身的地址。`alias` 的名称表达式则直接指定整数对象 `value`：`alias = 9;` 修改的是该整数，`&alias` 取得的也是该整数的地址。

即使把指针本身限定为 `const`，它仍然是对象，对它取地址仍会取得这个指针对象的地址。固定指针值与固定引用绑定，不会消除上述表达式语义的区别。

源码中给引用名称赋值，指定的是目标对象，引用仍绑定原目标。实现用地址记录它，也不为源码增加一份可改写的绑定状态；引用没有表示“未绑定”的正常空状态。

> [!IMPORTANT] 实现模型服从语言契约
> **实现可以借助地址完成引用访问，源码仍按引用的语言规则解释。**引用名称可以用于赋值，赋值修改被绑定对象；引用不能在初始化后重新绑定，也没有表示“未绑定”的正常空状态。实现采用指针不改变这些约束。

## 常见 ABI 使用对象地址传递引用

本节及后面的接口判断需要先明确[引用形参访问调用者对象](../05-reference-parameters-and-caller-objects.md#函数调用初始化引用参数)和[引用返回保留对象身份](../06-reference-returns-and-lifetime-boundaries.md#引用返回保留已有对象身份)。前面的局部表示与优化只依赖引用绑定，不需要函数引用关系。

应用二进制接口（Application Binary Interface，ABI）让分别编译的调用方与实现方采用一致的交接规则。这里沿用[ABI 对分别编译边界的约束](../../05-functions/deep-dives/02-application-binary-interface.md#abi-固定分别编译边界)，以 Itanium C++ ABI 为例：引用参数通过指向被绑定对象的指针传递，引用返回也以指向目标对象的指针形式返回。

下面是一个独立的两文件程序。`increment.cpp` 提供函数定义：

```cpp
int& increment(int& target) {
    ++target;
    return target;
}
```

`main.cpp` 在调用前声明该函数，并使用返回的引用：

```cpp
#include <iostream>

int& increment(int& target);

int main() {
    int value{7};
    int& alias{increment(value)};
    std::cout << value << '\n'; // 8

    alias = 9;
    std::cout << value << '\n'; // 9
    return 0;
}
```

调用时，形参 `target` 绑定到调用方的 `value`。`++target` 把这个对象从 `7` 改为 `8`；`return target;` 保留该对象的身份，使调用方的 `alias` 继续绑定到 `value`。随后通过 `alias` 赋值，把 `value` 改为 `9`，所以程序依次输出 `8` 和 `9`。目标对象一直存在于调用方，函数返回不会销毁它。

先按两个文件分别编译、不进行跨文件联合优化并保留独立调用理解。在采用上述 ABI 规则时，源码步骤与实现交接可以对应起来：

| 源码步骤 | 实现中的交接与访问 |
| --- | --- |
| 调用 `increment(value)` | 调用方传入指向 `value` 的指针，提供目标位置 |
| 函数内执行 `++target` | 被调方利用收到的地址定位 `value`，修改该整数 |
| 执行 `return target;` | 被调方返回指向同一个 `value` 的指针 |
| 初始化调用方的 `alias` | 调用方根据返回的目标位置建立引用绑定 |

交接的是定位目标的信息，整数状态仍属于调用方的 `value`。地址放在哪个寄存器或栈位置，需要结合目标平台的基础调用约定确定；上述引用规则本身不指定通用于所有平台的位置。

> [!IMPORTANT] ABI 约定引用的传递方式
> **在采用这里的 Itanium C++ ABI 规则时，引用参数通过指向目标的指针传递，引用结果也以指向目标的指针返回。**这是二进制边界规则；源码中的引用仍按引用的绑定、赋值与生命周期规则使用。

如果构建允许编译器联合分析调用方与实现方，它还可能把 `increment` 的工作合并进调用位置，不再为这一次调用实际交接指针。但仍需向独立使用方提供的函数接口，必须维持约定的参数与返回规则。

> [!IMPORTANT] 优化不取消仍需保留的 ABI 边界
> **局部绑定或内部调用可以化简，独立编译产物之间仍需保留的协作边界必须遵守 ABI。**某次调用省去了地址传递，不表示对外接口可以随意改变；局部引用没有地址槽，也不表示独立调用可以省去必需的目标信息。

## 工程判断建立在语义之上

选择引用时，应依据接口是否要求必有目标、是否保留对象身份以及是否允许经这条路径修改对象。需要独立的小整数输入时，按值传递本来就能直接表达意图；需要访问已有对象时，再根据修改与可选性要求选择引用或指针。

判断正确性时，核对绑定对象、目标生命周期和访问约束。源码中的按值与引用关系由语言规则判断；实际保留了多少复制、寻址与访存操作，则要结合具体生成代码和实际类型、目标平台、调用路径下的测量结果判断。

> [!TIP] 查阅与核对实现时的条件
> 需要确认引用有无额外存储、地址怎样传递或调用是否保留时，先记录编译器版本、编译目标、所用 ABI、优化与链接选项，再结合 ABI 文档、实际生成代码和调试信息核对。具体寄存器、存储位置与指令随构建查用；需要理解的是这些实现怎样满足同一套绑定与访问规则。
