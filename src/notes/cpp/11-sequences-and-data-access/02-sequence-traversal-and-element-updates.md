# 序列遍历与元素修改（Sequence Traversal and Element Updates）

一批物品的称重读数保存在序列中，单位为克。求这些读数的总和，需要依次读取每个元素；若已确认每条读数都比实际值少了 5 克，则需要逐个修正保存的数值。

依次访问序列中的元素，称为遍历（traversal）。当操作只需要元素本身，下标没有额外用途时，可以直接让循环面向元素。

## 每轮取得一个元素

范围 for 语句（range-based for statement）使用 `for (声明 : 序列)` 的形式。冒号右侧给出要遍历的序列，左侧声明本轮使用的变量。对 `std::vector<double>`，循环按下标递增的顺序访问已有元素，并用当前元素初始化本轮变量。

下面的完整程序只读取称重记录，所以容器声明为 `const`。`weights_g` 保存各项读数，`total_g` 累计它们的总和：

```cpp
#include <iostream>
#include <vector>

int main() {
    const std::vector<double> weights_g{240.0, 250.0, 245.0};
    double total_g{0.0};

    for (const double value : weights_g) {
        total_g += value;
    }

    std::cout << total_g << '\n';
}
```

三轮的 `value` 依次保存 `240.0`、`250.0` 和 `245.0`。每一轮都会创建一个新的局部 `const double` 对象，本轮结束后该对象的生命周期结束。`total_g` 声明在循环之前，整个循环共用这一个累计对象，它从 `0.0` 依次变为 `240.0`、`490.0` 和 `735.0`，程序输出 `735`。

> [!IMPORTANT] 范围 for 怎样使用容器与元素
> **对这里的具名 `std::vector<double>`，范围 for 直接使用原容器，并在每轮用当前元素初始化本轮变量。**它不会先复制整份容器。按值声明本轮变量时，复制的是本轮访问的那个 `double`。
>
> 元素按序列顺序提供，本轮变量怎样使用元素，则由冒号左侧的声明决定。

## 局部值的修改不会写回序列

读数修正需要让原序列的每个元素增加 `5.0`。将本轮变量从 `const double value` 改为 `double value`，允许修改本轮局部对象，但没有建立对原元素的引用。

保留开篇的头文件，把 `main` 的函数体替换为下面的独立片段。这个片段中的容器和本轮变量都允许修改：

```cpp
std::vector<double> weights_g{240.0, 250.0, 245.0};

for (double value : weights_g) {
    value += 5.0;
    std::cout << value << '\n';
}

std::cout << weights_g[0] << ' ' << weights_g[1] << ' ' << weights_g[2] << '\n';
```

前三行依次输出 `245`、`255`、`250`，说明每轮局部对象的值已经增加。最后一行却输出 `240 250 245`：原序列仍保存旧读数。`double value` 从当前元素读取初值，随后 `value += 5.0` 修改的是这个独立副本，没有向原元素赋值。

容器的 `const` 与本轮变量的 `const` 也约束不同对象。`const std::vector<double>` 限制通过该容器修改原元素，`const double value` 限制修改本轮副本。即使从只读容器中复制元素值，`double value` 建立的新副本仍然允许修改。

## 通过引用修改原元素

要保存修正后的读数，可以让本轮变量直接绑定原元素。保留头文件，再把 `main` 的函数体替换为下面的片段。它从相同的初始读数开始，与前一个片段相比，仅把循环声明改为 `double& value`：

```cpp
std::vector<double> weights_g{240.0, 250.0, 245.0};

for (double& value : weights_g) {
    value += 5.0;
    std::cout << value << '\n';
}

std::cout << weights_g[0] << ' ' << weights_g[1] << ' ' << weights_g[2] << '\n';
```

前三行仍然输出 `245`、`255`、`250`，最后一行则变为 `245 255 250`。`value` 引用当前元素，`value += 5.0` 直接修改该元素，因此循环结束后原序列保留修正结果。

第一轮的 `value` 绑定 `weights_g[0]`，这一轮结束后，该局部引用的生命周期结束；第二轮重新执行引用声明，建立绑定 `weights_g[1]` 的新引用。各轮使用相同的名称，并不是把同一个引用改绑到另一个元素。引用结束也不会销毁它所绑定的元素，元素仍由容器管理。

> [!IMPORTANT] 副本与引用决定修改落在哪里
> 对这里的 `std::vector<double>`，**按值声明创建本轮的独立对象，修改它不会写回原元素；引用声明绑定原元素，通过可修改的引用赋值会直接改变该元素。**每轮都会重新初始化本轮变量：按值时创建新的对象，按引用时建立新的绑定。
>
> 能否通过本轮名称修改对象，还要看相应的 `const` 约束。去掉副本的 `const` 只会让副本可修改，不会把它变成原元素的引用。

对这里的 `std::vector<double>`，常见声明分别表示：

| 本轮声明 | 与原元素的关系及访问约束 |
| --- | --- |
| `const double value` | 创建只读副本，不能修改这个副本 |
| `double value` | 创建可修改副本，修改它不会写回原元素 |
| `const double& value` | 引用原元素，只能通过该引用读取，不能通过它修改 |
| `double& value` | 引用原元素，可以通过该引用修改；要求原元素允许修改 |

只读取这里的 `double` 时，复制一个小值已经足够，开篇求和循环可以直接按值读取。引用用于保留与原元素的访问关系，不必为了“避免复制”而把所有本轮变量统一改为引用。

> [!TIP] 核对修改是否落在原元素上
> 先看本轮变量的声明，辨认副本、引用及其 `const` 约束，再看循环体中的赋值实际作用于哪个对象。`double&` 提供可写路径，但循环体只读取时不会因此改变元素；若还通过其他名称访问原序列，也要分别追踪。
>
> 要核对是否写回，可以像上述对照一样，在循环结束后读取原序列。循环内打印的局部值已经改变，本身不能证明原元素已经改变。

## 遍历期间保留有效的元素范围

范围 for 进入循环时，取得并保存遍历的起始位置与结束位置。对这里的 `std::vector<double>`，结束位置表示最后一个元素之后的边界，不是一个可以读取的元素。循环按下面的关系推进：

1. 先判断当前位置是否已经到达保存的结束位置；若已经到达，循环结束。
2. 否则，用当前元素初始化本轮变量，执行循环体。
3. 本轮正常结束后，推进到下一个位置，再作结束判断。

空序列的起始位置与结束位置相同，因此不会初始化本轮变量，也不会执行循环体。当 `break` 或 `continue` 的目标是这个范围 for 时，`break` 直接结束循环，不再推进或判断；`continue` 跳过本轮剩余语句，仍会推进位置并进行结束判断，可能进入下一轮，也可能结束循环。

遍历期间，容器、当前元素以及后续仍要使用的遍历位置都必须保持有效。给已有 `double` 元素赋新值，只改变元素的值，不改变元素数量或存储位置，因此上面的修正循环能够继续使用原来的遍历状态。

> [!WARNING] 元素仍有效不等于遍历状态仍有效
> 向正在遍历的 `std::vector` 成功追加元素后，原来的结束位置会失效；即使没有重新分配元素存储，也存在这一问题。若发生重新分配，指向原元素的引用和遍历位置也会失效。
>
> 随后再使用这些失效的位置推进或作结束判断，行为未定义。不能把“当前元素的引用还有效”当作原范围 for 可以继续的依据，也不能期待循环自动改用新的结束位置。

需要追加、删除元素或更换元素存储时，应重新安排遍历与修改的先后关系，并按具体操作核对有效性。追加操作与重新分配的条件见[序列存储与引用有效性](04-sequence-storage-and-reference-validity.md#追加元素怎样影响引用)。仅仅读取或更新已有元素，可以直接使用原序列，无需为此先复制整份数据。
