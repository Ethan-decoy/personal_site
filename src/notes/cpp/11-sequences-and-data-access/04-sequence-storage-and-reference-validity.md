# 序列存储与引用有效性（Sequence Storage and Reference Validity）

压力采样值不断到来，需要向记录中追加元素。容器能够管理更多数据，但之前取得的元素引用是否还能使用，取决于追加怎样改变元素存储。容器对象仍然存在，并不保证原来的元素引用仍然有效。

以下采样值的单位为千帕（kPa）。容器对象管理一组元素，元素引用则访问其中的某一项。一次末尾追加是否需要更换存储，要比较追加前的元素数量和容量。

## 在末尾追加一个元素

初始化时可以用花括号给出一组采样值；新的采样值在运行过程中到来时，需要向已有序列继续添加元素。

`push_back` 是 `std::vector` 提供的公开成员函数，用来在序列末尾追加一个元素。调用写作 `samples.push_back(value)`，其中 `samples` 是要修改的容器，`value` 表示要追加的数值。

下面是包含 `<vector>` 后可放入函数体的独立片段：

```cpp
std::vector<double> samples{240.0, 245.0};
samples.push_back(250.0);
```

成功调用后，序列由两个元素变为三个元素，依次保存 `240.0`、`245.0` 和 `250.0`，新元素可以通过 `samples[2]` 访问。`push_back` 的返回类型为 `void`；它直接修改调用它的容器，不能通过 `const` 对象或只读引用调用。

给已有元素赋值只改变该元素的值，元素数量保持不变；追加则建立一个新元素，让 `size()` 增加一。不能通过给越界下标赋值来追加元素。

## 容器对象与连续元素存储

`std::vector<double>` 将元素按照下标顺序连续存放。容器负责取得保存这些元素所需的存储，并在正常销毁时清理元素、释放自己管理的存储；调用者不需要另外逐项执行清理操作。

名称 `samples` 指定容器对象，`samples[0]` 指定它管理的一个 `double` 元素。元素增加时，容器可能更换保存元素的存储区域；即使名称 `samples` 仍指定原来的容器对象，旧元素的引用也可能已经失效。

元素数量（size）与容量（capacity）分别描述两件事：

| 操作 | 返回值的含义 | 能否据此访问元素 |
| --- | --- | --- |
| `samples.size()` | 当前已经存在的元素数量 | 有效下标小于这个数量 |
| `samples.capacity()` | 无需重新分配存储就能容纳的元素总数 | 预留空间不等于已有元素，仍须检查 `size()` |

`capacity()` 与 `size()` 返回相同的数量类型，容量不小于当前元素数量。

> [!IMPORTANT] 元素数量与容量约束不同的操作
> **对 `std::vector<double>`，`size()` 表示已经存在的元素数量，`capacity()` 表示当前存储无需重新分配就能容纳的元素总数。**有效下标由 `size()` 决定，容量余量不属于已有元素，不能通过下标访问它。
>
> 即使容量大于零，只要 `size() == 0`，容器中仍没有任何可以读取或修改的元素。

## 追加元素怎样影响引用

若原存储容纳不下追加后的全部元素，容器需要取得足够的新存储，在其中保留已有元素的数值，并释放原来的元素存储。这个过程称为重新分配（reallocation）。改变的是容器管理的元素存储，名称 `samples` 仍指定原来的容器对象。

> [!IMPORTANT] 末尾追加何时保留元素引用
> **对 `std::vector<double>`，一次末尾追加成功后，已有元素引用是否保留，取决于追加前的数量和容量：**
>
> - 追加前 `size() < capacity()`：存储足够，不发生重新分配，指向已有元素的指针和引用保持有效。
> - 追加前 `size() == capacity()`：需要重新分配，原有元素的指针和引用全部失效，不会自动跟随同一下标找到当前元素。

> [!WARNING] 旧引用不能继续访问重新分配后的元素
> 重新分配后，再通过旧引用读取或修改原元素，行为未定义。容器仍然存在、同一下标仍保存相同数值，都不能证明旧引用仍可使用。
>
> 需要继续访问时，应从仍然有效的容器通过合法下标重新取得元素，建立新的访问关系。引用不能重新绑定，给旧引用赋值也不能修复它。

前述保留结论针对已有元素。末尾追加会使原结束位置失效，即使没有重新分配也是如此；不能把元素引用仍有效推导成可以继续使用原来的范围 for。结束位置怎样参与遍历，见[遍历期间保留有效的元素范围](02-sequence-traversal-and-element-updates.md#遍历期间保留有效的元素范围)。

容量的具体增长幅度由实现选择。花括号给出三个元素，不保证容量恰好为三；一次追加也不保证容量按某个固定倍数增长。判断引用是否保留，应当依据操作及容量条件。

## 已知数量时预留容量

`samples.reserve(count)` 调用成员函数 `reserve`，请求容器预留至少能容纳 `count` 个元素的容量，返回类型为 `void`。正常返回后，元素数量和已有元素的数值不变：请求数量大于原容量时，发生重新分配，新容量至少达到请求值；原容量已经足够时，不重新分配，容量也保持不变。

因此，`reserve` 即使不改变元素数量，也可能使已有元素引用失效。计划保留元素引用时，应先完成所需的预留，再取得引用；之后仍须按具体修改操作判断有效性。

下面的程序在取得元素引用之前，为三次采样预留空间：

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<double> samples{};
    samples.reserve(3);

    samples.push_back(240.0);
    const double& first{samples[0]};

    samples.push_back(245.0);
    samples.push_back(250.0);

    std::cout << first << '\n';
    std::cout << samples.size() << '\n';
}
```

这段程序中的状态依次变化：

| 执行完成的位置 | 元素数量 | 容量条件 | `first` 的状态 |
| --- | ---: | --- | --- |
| `reserve(3)` 后 | `0` | 至少为 `3` | 尚未声明，也没有元素可绑定 |
| 首次追加并初始化 `first` 后 | `1` | 与预留后相同 | 绑定下标为 `0` 的元素 |
| 第二次追加后 | `2` | 保持不变 | 仍然有效 |
| 第三次追加后 | `3` | 保持不变 | 仍然有效，读取值为 `240.0` |

三次 `push_back` 才依次建立三个元素。它们没有超过预留后的容量，因此没有重新分配，`first` 始终访问有效的第一个元素。程序输出 `240` 和 `3`，不依赖容量恰好等于三。

> [!WARNING] 预留空间没有建立可访问的元素
> 对空的 `std::vector<double>` 对象 `samples` 调用 `reserve(3)` 后，`size()` 仍为 `0`。此时访问 `samples[0]` 仍然越界，通过它读取或写入都具有未定义行为。容量足够，不等于相应下标已有元素；`reserve` 也不会自动建立三个值为零的 `double`。
>
> 当前示例通过三次 `push_back` 建立元素，只有已经建立的那些元素才能按有效下标访问。

> [!PRACTICE] 按预计数量预留容量
> 当业务已经知道将保存的大致数量时，可以提前预留容量，减少增长过程中更换存储的工作。预留会提前取得相应存储，估计过大时可能保留尚不需要的容量。
>
> 数量不明确时，可以让容器随追加管理增长，不必每次追加前都调用 `reserve`。反复按很小的增量请求容量，可能增加已有元素的迁移工作。预留后若增长超过实际容量，仍会重新分配，不能把估计数量当作永久的引用有效性保证。

这些正常路径结论以操作成功为前提。存储或长度请求无法满足时，操作可能通过异常（exception）报告失败：它不会正常返回并继续执行调用点之后的语句，而是转向相应的异常处理；没有处理者时，程序会终止。对这里的 `std::vector<double>`，`push_back` 或 `reserve` 抛出异常时，原容器保持不变。

## 借用不能维持容器的生命周期

正常离开局部容器所在的作用域时，容器会销毁它管理的元素并释放相应存储。元素引用不会因此拥有另一份数据，也不会让这些元素继续存在。

下面是放在源文件作用域、例如 `main` 之前的独立函数定义片段，用来分析错误的返回关系：

```cpp
#include <vector>

const double& first_pressure_kpa() {
    const std::vector<double> samples{240.0, 245.0, 250.0};
    return samples[0];
}
```

返回表达式指定局部容器中的第一个元素。求值时这个元素仍然存在，但返回的是引用关系，没有复制出独立数值；离开函数时，局部容器会销毁它管理的元素。

> [!WARNING] const 引用不能保留局部容器的元素
> 返回局部容器元素的引用，不会延长容器或元素的生命周期。函数结束后，调用者得到的是悬空引用；之后再通过它读取元素，行为未定义。返回类型中的 `const` 只限制访问权限，不提供目标继续存活的保证。
>
> 编译器可能对这个定义给出警告；能够通过编译，也不能证明返回的引用可供调用者使用。

如果调用者只需要这个采样数值，可以把返回类型改为 `double`。返回时读取元素值并建立独立结果，局部序列随后销毁，不会破坏这个结果。

> [!IMPORTANT] 元素借用的有效条件
> **对这里的 `std::vector<double>`，借用元素时，既要保证管理目标的容器及目标元素仍然有效，也要保证相关操作没有使原访问关系失效。**容器仍在，不能替代对元素引用有效性的判断。
>
> 在元素有效时取得独立的 `double` 值，可以让该副本脱离原容器的生命周期；保存元素引用则需要继续维护访问条件。
