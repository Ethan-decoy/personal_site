# 右值引用与将亡值（Rvalue References and Xvalues）

## 为什么复制之外还需要移动

对于[保存采样值的 `std::vector<double>`](../11-sequences-and-data-access/03-sequence-copying-and-function-access.md#参数形式表达需要怎样的数据关系)，只读取现有记录时，可以通过 `const` 引用访问原序列，无需复制元素；需要一份可独立修改的记录时，则可以复制序列，保留两组彼此独立的元素。

还有一种需求：接收方需要自己的序列对象，调用方却已经不再需要原来的采样记录。单纯保留引用仍然依赖源序列继续管理数据，复制则会为这次交接重新建立一组元素。如果让接收方接管已有的元素存储，源序列放弃对这份存储的管理，就可以省去复制整组元素的工作。

**移动（move）**让接收方在类型允许改变源状态的前提下，利用源对象已有状态完成构造或赋值。对于这类序列，移动可以转交存储的管理责任；对于校准登记，移动可以转交不能重复承担的解除责任。源对象仍然存在，操作后的可用状态由类型约定。

为了让接口区分保留源值与允许改变源状态这两种使用意图，C++ 提供了右值引用与相应的表达式类别。普通左值表达式只指定一个已有对象，本身不表示调用方愿意放弃它的原有状态。

## 右值引用怎样绑定对象

右值引用（rvalue reference）使用 `T&&` 声明。这里的 `T` 表示某个具体对象类型；例如，`int&&` 是对 `int` 的右值引用，声明中的 `&&` 不是逻辑与运算符。

本文两段 C++ 片段分别放在各自独立的 `main` 函数体内，分开使用。第一段中的注释行是错误变体，只对这段代码单独解除注释考察：

```cpp
int&& value{240};
int& alias{value};

alias = 245;

// int&& other{value}; // 错误：这里的初始化表达式是左值
```

纯右值 `240` 在引用绑定时物化为一个临时 `int` 对象。局部引用 `value` 直接绑定这个临时对象，将其生命周期延长到该局部引用的生命周期结束；右值引用并没有获得一份独立的整数副本。

> [!IMPORTANT] 引用类型与表达式类别分别判断
> **引用的声明类型与引用名称表达式的值类别是两个问题。**本例中，`value` 声明为 `int&&`，表达式 `value` 却是指定所绑定临时对象的左值，因此能用来初始化 `int&`。

执行 `alias = 245;` 后，两条引用所指的同一个临时对象存储 `245`。注释中的 `int&& other{value};` 则不能成立，因为它试图用这里的同类型左值初始化右值引用。

## 将亡值保留对象身份

一个已有对象也可以通过另一种表达式提供给右值引用。下面是第二个独立片段，仍放在 `main` 的函数体内：

```cpp
int value{240};
int&& alias{static_cast<int&&>(value)};

alias = 245;
```

`static_cast<int&&>(value)` 的转换结果仍然表示原来的对象，但表达式类别是将亡值（xvalue, expiring value）。

> [!IMPORTANT] 将亡值的对象身份与复用含义
> **将亡值保留对象身份，同时允许这个对象作为可复用状态的来源参与后续操作。**这里的转换不创建新对象，不转移资源，也不改变原对象的存储期或销毁时刻。接收方是否修改源对象，以及修改成什么状态，由实际执行的操作决定。

“将亡”不表示对象立即销毁，也不保证它很快离开作用域。在这段代码中，`alias` 绑定到原来的 `value`；赋值后，`value` 保存 `245`，仍按照局部对象原有的规则销毁。

## 三种值类别与引用绑定

> [!IMPORTANT] 三种基本值类别与两组统称
> **每个表达式恰好属于左值（lvalue）、将亡值（xvalue）、纯右值（prvalue）三种基本类别之一。**在这里的对象表达式范围内，左值与将亡值都能表示具有身份的对象，统称泛左值（glvalue）；将亡值与纯右值统称右值（rvalue）。

对于本篇的整数引用初始化，将亡值直接指定已有对象，纯右值则在需要可绑定目标时物化临时对象。引用是否能接收这些来源，还要结合被引用类型与访问限定判断。

对于下面这些同为 `int`、不涉及额外类型转换的初始化表达式，绑定关系是确定的：

| 引用类型 | 左值 `value` | 将亡值 `static_cast<int&&>(value)` | 纯右值 `240` |
| --- | --- | --- | --- |
| `int&` | 可以 | 不可以 | 不可以 |
| `const int&` | 可以 | 可以 | 可以，绑定物化出的临时对象 |
| `int&&` | 不可以 | 可以 | 可以，绑定物化出的临时对象 |

`const int&` 能只读地接收已有对象和临时对象；`int&&` 则让接口可以把右值与普通左值输入区分开。右值引用不是“只能引用临时对象”的引用，也不是会自动消耗目标对象的新存储方式。

这些类别不决定对象是否具有 `const` 限定。一个 `const int` 对象仍然不能绑定到允许修改它的 `int&&`；把表达式变成右值，不会取消对象原有的可修改性约束。
