# 用谓词批量删除元素（Removing Elements with Predicates）

从一组绝对压力样本中剔除负值，需要对每个元素作出判断，并让保留的样本重新组成连续序列。逐个调用 `vector` 的 `erase` 可以完成删除，但反复让后继补位，可能产生随样本数量按平方增长的工作量。

谓词可以把“哪些样本需要删除”单独表达出来，再交给容器对应的批量删除接口。本篇讨论可修改的 `std::vector<double>`，以及正常完成的删除操作。

## 容器提供存储，谓词指定删除条件

头文件 `<vector>` 提供适用于 `vector` 的非成员函数 `std::erase_if`。调用 `std::erase_if(samples, pred)`，把容器作为第一个实参，把谓词作为第二个实参，直接修改 `samples` 自身。

算法逐个用元素调用谓词：**结果为 `true` 的元素被删除，结果为 `false` 的元素被保留**。成功返回后，保留元素的相对次序不变，`samples.size()` 减少实际删除的数量。

返回值就是删除数量，其类型为容器的 `size_type`；对本篇的容器，是 `std::vector<double>::size_type`。它不是删除后的位置，也不是剩余元素数量。

下面仍以相邻的两个负值和末尾的负值为输入，先打印删除数量、剩余数量，再打印保留的样本：

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<double> samples{240.0, -2.0, -3.0, 245.0, -4.0};
    const auto is_negative = [](double value) -> bool { return value < 0.0; };

    const std::vector<double>::size_type removed{std::erase_if(samples, is_negative)};

    std::cout << removed << '\n';
    std::cout << samples.size() << '\n';
    for (const double value : samples) {
        std::cout << value << '\n';
    }
}
```

输出：

```text
3
2
240
245
```

`is_negative` 只负责比较当前值与零。遍历、整理元素和更新容器大小由 `erase_if` 完成，因此调用方无需维护删除后的迭代器，也不会因为连续匹配而漏掉第二个负值。

| 输入情况 | 返回的删除数量 | 调用后的容器 |
| --- | --- | --- |
| 容器为空 | `0` | 仍为空，不调用谓词 |
| 没有元素满足删除条件 | `0` | 所有元素保留，大小不变 |
| 所有元素满足删除条件 | 调用前的元素数量 | 为空，`size()` 为 `0` |
| 部分元素满足删除条件 | 满足条件的元素数量 | 只保留其余元素，相对次序不变 |

同一个谓词交给 `find_if` 时，`true` 表示找到了目标；交给 `erase_if` 时，`true` 表示删除目标。谓词提供判断，接收它的接口决定如何处理满足条件的元素。

## 集中补齐，避免反复移动后继

对 `vector` 的批量删除，可以按两个阶段理解：先让保留的值向前补齐，再结束多余尾部元素的生命周期，缩小容器。

在示例中，`240.0` 已在正确位置。遇到两个负值后，不必分别移动它们后面的整段序列；读到需要保留的 `245.0` 时，把它放到紧随 `240.0` 的位置即可。所有值判断完毕，保留的序列占据前两个位置，最后移除多余尾部。

这个整理模型中，每个保留元素至多向前补位一次，而不是每遇到一个待删除元素，就重新移动整个后继区间。它解释了批量处理的成本优势，并不要求标准库内部使用某一种固定的循环写法。

对调用前含有 `n` 个元素的容器，`erase_if` 恰好进行 `n` 次谓词调用。这里的 `double` 赋值和负值判断成本固定，批量整理只需随 `n` 线性增长的工作量。若改为处理复杂对象或昂贵的判断，总成本还要计入元素赋值、销毁和谓词本身的工作。

> [!IMPORTANT]
> 对 `vector`，按条件删除的关键是把保留元素集中整理，再缩小尾部。相较于反复单项删除，它避免让同一段后继一次次补位；保留次序不变，容器大小也在调用结束时完成更新。

## 删除完成后，重新取得需要借用的元素

批量删除仍然会改变位置与元素之间的对应关系。在示例中，原来保存 `-2.0` 的位置后来保存 `245.0`；原来位于后部的 `245.0` 已经补到前面。一个旧位置即使仍能访问，也不代表它仍保存原来的样本。

确有删除时，最终移除的尾部使这些位置上的旧迭代器、指针和引用失效，旧的 `end()` 也失效。剩余前缀的位置可以继续存在，但其中的值可能已经在补齐过程中改变。此前建立的 `span` 也不会自动缩短：若仍保留原长度，它可能覆盖已经结束生命周期的尾部。

> [!WARNING]
> 按条件删除之后，既要检查借用是否仍然有效，也要检查它是否仍指向原本想处理的数据。需要继续查找、遍历或建立视图时，从修改后的容器重新取得位置和范围，不要把原下标或旧视图当作稳定的样本身份。

这一变化也会影响谓词借用的配置。例如，若用 `const double& limit{samples[1]}` 借用容器内的一个值，再通过 `[&limit]` 把它作为判断上限，前面的补位就可能改写这个位置，让同一次删除过程中的判断上限发生变化。若规则需要固定上限，应在调用前把该数值复制为独立的 `double`，再按值捕获它。

## 谓词只判断，不接管删除过程

谓词不能通过参数修改被判断的元素，这是算法对谓词的要求；本例按值接收 `double`，天然只处理读数副本。谓词内部也不能破坏算法正在使用的遍历区间。例如，对同一个 `vector` 再执行 `push_back` 或 `erase`，会使保存的位置或结束边界失效，无法继续满足算法的前提。

`erase_if` 按值接收谓词，其内部操作也允许复制谓词。把删除次数累加到函数对象自己的成员里，再从传入的原对象读取，不会得到可靠保证；需要删除数量时，直接使用接口返回值。

> [!PRACTICE]
> 目标是“按规则清理当前序列”时，优先使用 `std::erase_if`，让谓词只读取元素和稳定配置。这是便于理解和维护的组织方式，不意味着 C++ 禁止所有带副作用的可调用对象。若必须保留原序列，则应另建结果容器；原地清理与保留输入是不同的存储选择。
