# 比较器与严格弱序（Comparators and Strict Weak Ordering）

同一组压力读数既可以从低到高展示，也可以从高到低展示。排序的重排任务没有变，改变的是“两个元素之间，谁应排在前面”的判断。

提供这种判断的对象称为比较器（comparator）。它是接收两个元素的谓词：`comp(a, b)` 为 `true`，表示 **`a` 应排在 `b` 前面**。这个结果不表示“这两个元素现在需要交换”，也不是通过正数、零、负数编码三种关系。

## 把先后规则交给排序算法

`<algorithm>` 中的 `std::sort(first, last, comp)` 接收一个比较器，按它定义的先后关系重排 `[first, last)`。区间仍须满足[可随机访问且元素可重排的要求](01-sorting-and-element-positions.md#排序需要怎样的区间)，函数仍返回 `void`；额外要求是比较器必须为参与排序的值建立本篇所说的严格弱序。

下面的 Lambda 对两个整数返回 `left > right`，因此数值更大的读数排在前面：

```cpp
#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    std::vector<int> samples{245, 240, 250};
    const auto before{[](int left, int right) { return left > right; }};

    std::sort(samples.begin(), samples.end(), before);

    for (const int value : samples) {
        std::cout << value << '\n';
    }
}
```

输出依次为 `250`、`245`、`240`。例如，`before(250, 245)` 为真，要求 `250` 在 `245` 前；`before(245, 250)` 为假，表示没有相反的先后要求。

算法自行选择比较哪些元素、以什么顺序调用比较器。比较器只描述值之间的关系，不能要求算法恰好按某个预想的交换步骤调用它。

## 比较等价不要求值完全相同

只得到 `comp(a, b) == false`，还不能判断两个元素是否属于同一组：也可能是 `b` 应排在 `a` 前面。必须再看反方向。

| 两个方向的结果 | 关系 |
| --- | --- |
| `comp(a, b)` 为真，`comp(b, a)` 为假 | `a` 排在 `b` 前 |
| `comp(a, b)` 为假，`comp(b, a)` 为真 | `b` 排在 `a` 前 |
| 两个方向都为假 | 这条比较规则把它们视为等价 |
| 两个方向都为真 | 先后要求冲突，不是有效的排序关系 |

这里的等价（equivalence）由 `!comp(a, b) && !comp(b, a)` 定义。它只说明比较器没有区分这两个值的先后，**不要求整个对象的 `==` 为真**。

整数用 `<` 或 `>` 排序时，这种等价恰好对应数值相等。对于包含传感器编号和压力值的记录，如果只比较压力，编号不同但压力相同的记录也会被视为等价；排序规则没有对编号提出要求。

## 严格弱序让局部判断形成一致的次序

排序算法依据多次两两比较整理整个序列。若这些判断彼此矛盾，算法便不能依赖它们排除候选位置或决定排列。因此，比较器需要建立严格弱序（strict weak ordering）：可以把值划分为若干等价组，组与组之间有一致的先后。

这具体要求以下关系在参与排序的值域上成立：

- 一个值不能排在自身之前：`comp(a, a)` 必须为假；若 `a` 在 `b` 前，`b` 就不能同时在 `a` 前。
- 先后关系具有传递性：若 `a` 在 `b` 前，`b` 在 `c` 前，那么 `a` 也必须在 `c` 前。
- 比较等价也具有传递性：若 `a` 与 `b` 等价，`b` 与 `c` 等价，那么 `a` 与 `c` 也必须等价。

第一项中的“自身之前为假”解释了为什么不能把整数排序的 `<` 随手改成 `<=`。`245 <= 245` 为真，等于要求一个值排在自身之前；两个相等值也会互相要求排在对方前面。降序的 `>=` 存在同样的问题。

“弱”允许多个不同的值属于同一等价组，不是允许规则偶尔矛盾。“严格”排除了自己在自己之前，也排除了双方同时在前。

> [!WARNING]
> 比较器违反严格弱序，就违反了 `sort` 的使用前提，可能导致未定义行为。不能把后果理解成“只是排得不稳定”，也不能用某次看似正确的排序输出证明比较器有效。

## 浮点特殊值与变化的判断规则

即使用的是 `<`，仍需检查它在实际数据范围内是否满足关系要求。[NaN 的有序比较都为假](../02-expressions-and-operators/05-comparison-and-logical-operations.md#浮点比较的含义)，因此包含 NaN 的一般浮点值域不能直接依靠 `<` 建立上述等价分组。

以 `240.0`、NaN、`250.0` 为例：

- `240.0` 与 NaN 的两个方向 `<` 都为假，按该比较器会被视为等价。
- NaN 与 `250.0` 的两个方向 `<` 也都为假，同样被视为等价。
- 但 `240.0 < 250.0` 为真，两个普通读数并不等价。

这违反了等价的传递性。若浮点数据可能含有 NaN，就需要先明确特殊值的处理规则，不能直接把整数示例换成任意 `double` 输入。此处的问题来自比较关系，不是通常所说的舍入误差。

比较规则还应在整个排序期间保持一致。算法可以[复制传入的函数对象](../23-callable-objects-and-lambda-expressions/02-predicates-and-conditional-search.md#算法接收对象但不保证使用原对象)，也会反复搬移元素；不能根据第几次调用、元素当时位于哪个地址或随时变化的外部配置，改变同一对值的先后判断。比较器也不能通过参数修改参与比较的元素。

> [!PRACTICE]
> 把比较器写成“只读取两个元素和固定配置，回答谁在前”的操作。检查它时，除了普通不同值，还要考虑同值、同键记录以及数据中允许出现的特殊值；这些边界决定规则能否用于整个输入范围。
