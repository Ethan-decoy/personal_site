# 二分查找与有序前提（Binary Search and Ordering Preconditions）

在无序序列中查找一个数值，可能需要逐个检查全部元素。若读数已经按升序排列，比较中间位置的值，就能判断目标应当落在哪一侧，不必继续检查另一半。

二分查找（binary search）利用这种关系逐步缩小范围。它减少比较的依据来自输入满足的顺序条件；调用方必须维持这些条件，算法不会先替输入排序。

## 查找的是分界位置

头文件 `<algorithm>` 提供 `std::lower_bound`。调用 `std::lower_bound(first, last, target)`，在有效半开区间 `[first, last)` 中定位**第一个不小于 `target` 的元素**，返回该位置；若所有元素都小于目标，则返回传入的 `last`。两个端点使用同一种迭代器类型，返回值也具有该类型。

本篇使用整数及默认的 `<` 比较。除端点必须组成[合法区间](../22-iterators-ranges-and-algorithms/01-iterator-positions-and-half-open-ranges.md#两个位置组成半开区间)外，输入还必须满足：使 `element < target` 为真的元素全部在前，使它为假的元素全部在后。两部分都允许为空。这种相对于一个判断条件分成前后两段的关系称为分区（partitioning）。

完整的升序排列能够保证对每个整数目标都满足这个条件。例如，在 `240, 245, 245, 250` 中查找 `246`，前三个元素都小于目标，最后一个不小于目标，边界就在 `250` 的位置。

分区要求比整体排序更弱。例如，`245, 240, 250, 248` 对目标 `246` 仍满足“真、真、假、假”，因而可以完成这一次边界查找；但换成目标 `242`，判断变成“假、真、假、假”，前提便不再成立。**对一个目标满足分区，不表示可以对任意目标继续查询。**

> [!IMPORTANT]
> 按同一比较规则排序，是建立可反复查询的顺序关系的一种可靠方式；`lower_bound` 的最低前提则是针对本次目标的分区。输入不必实际调用过排序函数，但必须已经满足查找所需的关系。

接口要求前向迭代器（forward iterator）：位置能够复制、比较和向前推进，并支持多遍遍历（multi-pass traversal）。这里的关键是，在区间保持有效时，推进一个位置副本，不会使另一个副本失去再次遍历原来那段元素的能力。算法需要保存位置、计算范围并从保留的位置继续，只有一次性向前读取的能力并不足够。

本篇的 `vector` 迭代器满足这些要求。查找只读取元素，因此可以使用 `cbegin()`、`cend()` 从 `const` 容器取得只读位置，不需要修改容器或复制整段元素。

## 有边界不等于有匹配

`lower_bound` 与[按值查找的 find](../22-iterators-ranges-and-algorithms/03-finding-elements-in-iterator-ranges.md#查找返回位置缺失返回区间终点)返回相同形式的位置，但回答的问题不同：`find` 找到第一个相等值；`lower_bound` 找到“小于目标”的前缀结束在哪里。

下面在同一个升序序列中分别查询不存在的 `246` 和存在的 `245`：

```cpp
#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    const std::vector<int> samples{240, 245, 245, 250};
    const int target{246};
    const auto position{std::lower_bound(samples.cbegin(), samples.cend(), target)};

    if (position != samples.cend()) {
        std::cout << *position << '\n';
    }
    std::cout << (position != samples.cend() && *position == target) << '\n';

    const auto match{std::lower_bound(samples.cbegin(), samples.cend(), 245)};
    std::cout << (match != samples.cend() && *match == 245) << '\n';
}
```

输出为 `250`、`0`、`1`。查询 `246` 时，`250` 是第一个不小于目标的值，所以返回位置可以解引用，但并没有找到相等值。查询 `245` 时，返回的是两个 `245` 中的第一个。

在这里的整体升序整数序列中，判断是否包含目标，需要同时满足“结果不等于本次终点”和“该位置的值等于目标”。`&&` 的短路保证先检查边界，只有位置位于区间内时才读取元素。

| 输入与目标的关系 | 返回位置 | 是否找到相等值 |
| --- | --- | --- |
| 区间为空 | `last`，也等于 `first` | 没有 |
| 目标小于所有元素 | `first` | 没有，首元素也大于目标 |
| 目标位于相邻数值之间 | 第一个大于目标的位置 | 没有 |
| 区间内存在目标值 | 第一个相等元素的位置 | 有 |
| 目标大于所有元素 | `last` | 没有 |

除第一行外，表中均假定区间非空且按整数升序排列。如果只对本次目标满足分区，后半段内部可能没有排序；这时边界仍能定位，却不能再用“边界处不相等”推断后面也不存在相等值。

> [!WARNING]
> `position != last` 只说明返回位置落在本次区间内，不说明它与目标相等。对一个子区间查询时，还必须使用传入的 `last` 判断边界，不能擅自换成整个容器的 `end()`。

## 每次比较为什么能排除半段

在 `240, 245, 245, 250` 中定位第一个不小于 `245` 的值，可以按下面的过程缩小待检查范围。下标只用于展示范围变化；这是一个可行的二分过程，不是标准规定的逐次访问轨迹。待检查元素用半开区间表示，右端虽然不再参与比较，仍可以保留为最终的结果边界。

| 仍需比较的下标区间 | 检查的中间值 | 根据判断缩小范围 |
| --- | --- | --- |
| `[0, 4)` | 下标 `2` 的 `245` | 不小于目标，边界在它或更前面；保留 `[0, 2)` 待检查 |
| `[0, 2)` | 下标 `1` 的 `245` | 不小于目标，继续检查 `[0, 1)` |
| `[0, 1)` | 下标 `0` 的 `240` | 小于目标，排除它；待检查区间变为 `[1, 1)` |

待检查区间收缩为空时，交会位置 `1` 就是结果。遇到相等值也没有立即停止，因为左侧还可能存在更早的相等值；`lower_bound` 需要定位整段“不小于目标”的起点。

这个排除过程依赖分区前提：中间元素小于目标时，它前面的元素也处在真前缀中，可以一起排除；中间元素不小于目标时，它及其后面的元素都不会属于真前缀，可以把边界搜索收向左侧。如果真假在序列中来回交错，就没有依据一次排除半段。

候选数量每次大致减半，因此对非空、含有 `n` 个元素的区间，比较次数按 `log₂ n` 的量级增长；这里的对数描述连续减半所需的次数，并不表示每次调用都有相同的比较次数。

`vector` 的[随机访问迭代器](01-sorting-and-element-positions.md#排序需要怎样的区间)能够直接偏移到中间位置，使位置移动也能配合这种缩减。对于不具备随机访问能力的前向迭代器，比较次数仍然是对数量级，推进位置的总次数却可能随区间长度线性增长。减少比较次数，不等于所有数据结构都能以相同成本到达中点。

## 有效位置与查找前提分别维护

[位置仍然有效](01-sorting-and-element-positions.md#排序改变位置中的值)，不代表输入仍然适合二分查找。例如，把可修改的升序序列 `240, 245, 245, 250` 的首元素改成 `260`，不会仅因这次整数赋值而使迭代器失效；但对目标 `246`，真假关系变成“假、真、真、假”，已经破坏分区。

改变参与排序的字段，或让后续查询采用与现有排列不匹配的比较规则，都需要重新检查这一关系。算法不会记住序列之前排过序，也不会在前提破坏后自动退回逐个查找。对不满足要求的输入调用 `lower_bound` 具有未定义行为，不能依靠某次返回值恰好正确来判断安全。

查询期间也必须保持区间和所用判断稳定。既有的容器存储、迭代器与借用有效期要求仍然适用；有序性是在这些要求之外增加的条件。

> [!PRACTICE]
> 无序数据只查询一次时，直接用 `find` 扫描通常更简单，也不必支付排序和重排的成本。数据较少改变、需要反复查询时，维护有序序列更容易摊薄建立顺序的成本。若原始次序具有业务含义，则先明确是否允许重排；保留原序列、另建排序副本，也需要承担复制和存储成本。
