# 模板实参推导与显式指定（Template Argument Deduction and Explicit Arguments）

调用普通函数时，形参类型已经写定，调用实参可以按规则转换到那个类型。调用函数模板时，可能还需要先回答一个问题：这次采用哪些模板实参，才能形成具体的函数接口？

**从实参推导类型，与向已确定的形参类型转换，是两个不同的判断。**能够把整数转换成浮点数，不代表推导遇到两种类型时会自动选出浮点数。

## 同一个类型参数需要得到一致结果

以下完整程序采用一个类型参数，同时描述两个按值形参：

```cpp
#include <iostream>

template <typename T> T larger(T first, T second) {
    if (first < second) {
        return second;
    }

    return first;
}

int main() {
    std::cout << larger(220, 240) << '\n';
    std::cout << larger(220.0, 240.5) << '\n';
}
```

输出为 `240` 和 `240.5`。推导会将各个含模板参数的形参类型，与对应调用实参的类型相匹配。在这里，两个位置都需要确定同一个 `T`：

| 调用 | 第一个位置推导出的 T | 第二个位置推导出的 T | 当前结论 |
| --- | --- | --- | --- |
| `larger(220, 240)` | `int` | `int` | 一致，采用 `T = int` |
| `larger(220.0, 240.5)` | `double` | `double` | 一致，采用 `T = double` |
| `larger(220, 240.5)` | `int` | `double` | 冲突，推导失败 |

将 `main` 中的任一调用替换为以下语句，会编译失败：

```cpp
std::cout << larger(220, 240.5) << '\n'; // 错误：同一个 T 得到不一致的推导结果
```

这里没有为两个位置分别声明独立的类型参数。推导不会先尝试把 `220` 转换成 `double`，也不会因为结果要比较数值，就自动采用算术表达式里的公共类型规则。

实参的类型而非数值外观决定这里的匹配。`220.0` 的数值没有小数部分，它仍是 `double`；一个 `short` 对象与一个 `int` 对象，也不会在这项推导中仅因允许整数提升就自动变成相同类型。

> [!WARNING]
> 对这里的 T、T 两个按值形参，混合类型导致的失败发生在确定模板实参时。不能用“普通函数允许这种隐式转换”来证明这次模板推导应当成功。

## 显式指定后按具体接口处理转换

可以在函数名后用尖括号写出模板实参：

```cpp
larger<double>(220, 240.5);
```

这是一条可放进上述 `main` 的调用语句。`<double>` 将类型模板实参明确指定为 `double`，后面圆括号里的 `220` 和 `240.5` 仍是函数调用实参。它们分别回答“采用哪种类型”和“传入哪些值”。

`T` 已经确定，当前函数的两个形参都是 `double`，于是 `220` 可以按[普通参数转换规则](../06-constants-literals-and-type-conversions/04-implicit-type-conversions.md#转换会出现在哪里)转换为 `double`。这次调用得到 `240.5`。

也可以保留推导，只把第一个实参明确转换成 `double`。下面两个调用可放在原程序的 `main` 中：

```cpp
std::cout << larger<double>(220, 240.5) << '\n';
std::cout << larger(static_cast<double>(220), 240.5) << '\n';
```

两行都输出 `240.5`。前一种写法直接选择模板的类型参数；后一种先形成两个同为 `double` 的实参，再从它们推导 `T`。

显式指定并不会赋予转换额外的安全保证。例如，选成 `larger<int>` 后再传入浮点实参，仍会受到浮点到整数转换的截断与范围规则约束。模板接受这种写法，不等于它保留了输入精度。

> [!TIP]
> 先看哪些模板实参已经明确给出，再从相应形参和实参推导剩余部分。具体接口形成后，才按该接口判断允许的转换与引用绑定。本篇只有一个类型参数，因此显式给出它后，已经没有剩余类型参数需要推导。

## 接收结果的类型不反向决定 T

把以下语句放进原程序的 `main`。两次调用使用相同数值，再把函数结果除以 `100`：

```cpp
const double deduced = larger(220, 240) / 100;
const double specified = larger<double>(220, 240) / 100;

std::cout << deduced << '\n';
std::cout << specified << '\n';
```

两行输出为 `2` 和 `2.4`。接收对象 `deduced` 和 `specified` 的类型都是 `const double`，但函数采用的 `T` 不同。

第一项调用从两个 `int` 实参推导出 `T = int`，返回 `int` 结果 `240`。它与整数 `100` 相除，先得到整数结果 `2`，随后才转换成 `double`，初始化 `deduced`。接收对象是浮点类型，并没有使右侧的调用和除法改用浮点类型。

第二项调用显式指定 `T = double`，返回 `double` 结果 `240.0`。随后 `100` 按算术转换规则转换成 `double`，除法采用浮点运算，因此输出 `2.4`。

这与[普通重载不根据接收结果的类型选择函数](../12-function-overloading-and-overload-resolution/03-best-viable-functions-and-ambiguous-calls.md#返回结果的去向不参与选择)相衔接。**接收对象的类型不反向参与本次调用的模板实参推导。**返回类型虽然也写成 `T`，却不使接收对象成为这次调用的推导来源。

## 选择类型之前先明确数值含义

自动推导适合实参已经表达所需类型关系的情况。显式指定类型适合调用者确实要形成一种统一接口、并且能够接受相应转换的情况。

这里的选择还包含业务前提。若两个读数分别使用不同单位，把它们转换成同一种 C++ 数值类型，并不能完成单位换算；如果转换会丢失有效的小数部分，也不能只以“推导成功”为标准选择 `int`。

> [!PRACTICE]
> 遇到推导冲突时，先判断输入是否应当属于同一类型，以及转换应由谁负责。确实需要统一数值类型时，可以在调用边界明确选择；若两种输入本来承担不同职责，应重新检查函数接口，而不是用随意的显式实参掩盖差异。
