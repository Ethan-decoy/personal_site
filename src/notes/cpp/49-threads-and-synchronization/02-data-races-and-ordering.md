# 数据竞争与先发生关系（Data Races and Happens-Before）

两个线程都能取得同一对象的引用，不意味着它们可以随意同时访问。并发正确性依赖被访问的内存位置、操作冲突和同步关系。

## 冲突操作需要有效顺序

对于这里的普通对象访问，两个潜在并发操作针对同一内存位置，至少一个修改，且没有相应先发生关系时，就可能形成数据竞争（Data Race）。数据竞争导致未定义行为，不只是“偶尔丢一次更新”。

先发生（Happens-Before）是语言定义的执行顺序关系，可以由单线程内的求值顺序和跨线程同步组成。线程启动、join、互斥量及原子同步分别提供规定的连接。

两个线程都执行普通 `++count`，不是安全计数：它涉及读改写。等两者都结束再 join，只约束最终读取时刻，不把两个更新互相排序。

假定主线程先调用 `first.join()`，再调用 `second.join()`，最后读取 `count`。这些等待建立的关系是：

```text
线程 first 的更新  --> first 结束  --> first.join 返回  --> 最终读取
线程 second 的更新 --> second 结束 --> second.join 返回 --> 最终读取
```

两次更新各自先于主线程的最终读取。可是，从这两条路径找不到“first 的更新先于 second 的更新”，也找不到反向关系。主线程先等谁，不决定另一个线程此前何时更新；两个更新之间仍缺少排序关系。

因此，检查同步时需要对准**发生冲突的那两个操作**，不能只证明它们都早于某次最终观察。这种普通对象竞争已经使程序行为未定义，不应通过运行它得到某个数值，再把该数值解释为语言允许的交错结果。

> [!IMPORTANT]
> 同时访问不是唯一判断；冲突和是否被同步排序共同决定正确性。观察到一次“输出正确”，不能证明不存在数据竞争。

## const 和共享拥有关系不提供同步

const 只限制该访问入口的修改能力，别的入口仍可能写同一对象。shared_ptr 保持寿命，也不保护目标成员。volatile 同样不是普通线程间通信或互斥工具。

共同读取不变对象通常可成立；访问独立内存位置也可以分别组织。容器的结构修改、再分配与迭代会涉及更广的共享状态，不能仅按“每个线程处理不同下标”推断安全。

普通容器有其不同元素并发修改保证，但 vector<bool> 等特殊关系须另查，元素代理可能涉及同一存储位置。

## 先减少共享，再选择同步

线程独立保存输入与结果，完成后组合，常比多线程频繁改一份状态清楚。需要共享可修改状态时，定义所有访问都遵守的同步协议。

> [!PRACTICE]
> 为每份共享状态说明谁读、谁写、何时开始、何时结束、由什么关系排序。同步应保护一个完整不变式，不能只在看起来“最危险”的写入旁边加锁。
