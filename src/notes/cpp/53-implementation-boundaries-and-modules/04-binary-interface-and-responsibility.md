# 二进制接口与责任边界（Binary Interfaces and Responsibility Boundaries）

同一头文件能分别编译，不证明两个产物一定能安全交互。应用二进制接口（Application Binary Interface，ABI）还涉及名称、调用方式、布局和运行库条件。

## 源码契约与产物兼容分别判断

| 边界 | 需要共同成立的条件 |
| --- | --- |
| 同一程序的翻译单元 | 声明与定义一致，ODR 与链接成立 |
| C/C++ 接口 | 语言链接、共同类型表示和调用约定 |
| 动态库边界 | 工具链 ABI、运行库、异常与分配释放约定 |
| 文件或网络协议 | 明确编码、字段、长度和版本，不直接借用对象布局 |

类大小、虚函数布局、标准库容器表示以及名称编码，都不由 C++23 统一规定成所有平台相同。模块编译产物同样不形成统一 ABI。

## 资源结束应回到能履行责任的接口

一侧创建不透明资源时，应提供匹配的释放入口。调用方可以用 RAII 包装它，但不能随意换成自己一侧的普通 delete 或其他不匹配释放方式。

结果中的文本与缓冲区明确是复制、借用还是交接；错误对象明确由谁保存、有效到何时。版本升级也要检查调用方已经依赖的表示与生命周期。

> [!PRACTICE]
> 内部程序以清楚的值和标准库接口组合；稳定外部边界缩小到真正需要公开的能力。隐藏表示降低部分依赖，但不替整个产物建立跨平台兼容保证。
