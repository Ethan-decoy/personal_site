# C++ 全书结构与覆盖

用于规划、维护与审阅 C++ 全书。当前主线为第 00–56 章，语言基准为 C++23；正文遵循 [writing-style.md](./writing-style.md)，代码遵循 [coding-style.md](./coding-style.md)。公开[总目录](../_index.md)只列已有内容，本页维护职责、依赖与扩展边界。

## 目标与完成范围

建立能够解释 C++ 程序行为、设计类型与接口、管理资源、组织程序，并正确组合标准库设施的知识体系。对影响正确性和工程选择的语义深入解释，对实现机制与精细规则按需下钻。

主线以这一能力闭环收尾，不以列尽关键字、标准库类型或标准条款判断完成。第 56 章将外部文本、领域值、失败状态、借用范围与输出责任组合成完整程序，说明扩展时如何保持契约。

C++ 正文负责设施的使用语义、生命周期、失败边界和成本契约。通用复杂度分析、算法设计与数据结构的系统推演归独立主题；数值分析、完整 Unicode 和平台 I/O 也有各自专业模型，不由语言工具代替。

## 成本模型与专业主题边界

22–27 的操作成本由 45 的共同模型补齐：规模与计数对象、比较和推进、最坏／平均／摊还、输入／输出／额外空间分别说明。各具体篇仍须就地保留结论的前提，不能只链接一个总模型。

45 的 deque、list 和适配器只补足双端访问、稳定位置和受限取项能力。这里不是所有数据结构的目录；算法证明、复杂度的系统推演与跨语言实现归相应专业主题。

## 维护与进一步深入

主线形成后，新增内容须说明实际新增能力和前置；不能仅因标准库还有未列出的名称就横向扩展。先检查当前模型是否能够解释新需求，再决定补主线、建附章还是归独立专题。

- **精细规则：** 复杂继承查找、对象替换、未初始化表示、约束排序及更多常量表达式条件，按影响当前正确性的实际问题下钻。
- **专门库：** tuple、正则表达式、专门数值类型、时区与日历、更多容器和执行策略，按真正用途引入，不视为当前所有日常接口的共同前提。
- **平台工程：** 操作系统 I/O、持久化协议、完整调度器、动态库发布及平台 ABI，建立对应实现条件，避免给标准设施添加额外承诺。
- **专业算法与文本：** 维持独立知识体系，C++ 示例负责语言与资源边界，不替领域模型完成证明。

审阅同时核对准确性、首次引入、可推演行为、失败条件、代码与导航。覆盖判断依靠这些能力及其边界，不依靠章节数量或一次构建成功。
