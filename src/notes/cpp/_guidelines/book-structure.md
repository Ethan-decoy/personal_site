# C++ 全书结构与覆盖

用于规划新章、调整分篇和审阅全书覆盖。当前内容范围为第 00–29 章，语言基准为 C++23；正文构造遵循 [writing-style.md](./writing-style.md)。本页维护内容归属与引入依赖，公开[总目录](../_index.md)保留已有篇章的查阅入口。

## 目标与边界

建立能够解释 C++ 程序行为、设计类型与接口、管理资源、组织程序，并正确组合标准库设施的知识体系。对影响正确性和工程选择的语义深入解释，对实现机制与精细规则按需下钻。

C++ 正文负责具体设施的使用语义、生命周期、失败边界和成本契约。复杂度的通用分析方法、算法设计与数据结构的系统推演归独立主题，C++ 仍须就地建立当前使用所需的模型。已有附章在公共正文形成后再评估归属与引用。

## 基础缺口的归属

这些是容易被大主题遮住的日常语义。按所在问题补齐；若新篇示例依赖它们，应先建立所需模型，而不是把它们集中堆成“其他语法”。

| 待补语义 | 引入位置与条件 |
| --- | --- |
| 枚举、类型别名 | 枚举接有限状态；别名接名称与接口表达，别名模板再接泛型。 |
| 跨文件类型接口的扩展 | 29 已建立普通类的前向声明、完整类型需求，以及重复包含与跨翻译单元定义的区别。智能指针等设施对不完整类型的具体要求，在实际隐藏表示或资源管理接口中补足。 |
| 局部静态对象、静态成员、跨文件初始化 | 分别解释跨调用存储期、类级状态与程序启动中的初始化关系；29 已用命名空间作用域的 `static` 函数建立内部链接，不能将其直接等同于静态对象语义。 |
| 默认实参、结构化绑定 | 分别接函数调用接口、多个返回成员的访问；结构化绑定同时交代复制与引用关系。 |
| 列表初始化与构造选择 | 承接构造、重载和模板使用契约，补 `initializer_list` 及其元素、生命周期条件。 |
| 非成员操作与比较 | 协作函数及 `friend` 接封装边界；28 已用普通结构体与非成员函数建立实参依赖查找（ADL），模板中的依赖查找另行展开。默认比较与三路比较接值类型的相等、顺序和运算符接口。 |
| 类型推导 | `decltype(auto)` 承接表达式类型规则与返回借用边界；类模板实参推导接构造实参与类型确定，在示例依赖它之前建立。 |
| 程序断言 | 承接类的不变式与接口前提，区分程序内部条件的验证和可恢复的外部失败；不因验证工具专题后置而推迟基本使用模型。 |

## 近期构建与选章

1. **承接多文件接口，按需补齐对象组织。** 28–29 已建立名称查找、共享接口、定义边界与实体身份，并用实际编译和链接诊断验证组织方式。跨文件变量、静态存储期与初始化关系仍待建立，按对象共享的具体需求展开，不作为所有泛型基础的前置。
2. **具体接口 → 泛型基础 → 约束。** 从重复的函数或类型提出参数化需求，先形成可用、可解释的泛型接口。推导与转发按包装接口的实际需要展开，不要求耗尽特化、参数包和元编程才切换方向。
3. **按前置接入其他分支。** 多态承接对象模型，编译期函数承接函数与常量，输入输出承接文本与失败；独立分支的编写先后可以调整。

**并行补强：** 第 22–27 章已有操作次数和复杂度结论，但共同的成本分析模型尚未建立，空间统计范围及最坏、平均、摊还的区别仍待补强。公共的时间与空间复杂度正文尚未编写；C++ 各篇先保证当前结论的规模、计数对象和适用条件明确。此项不阻塞名称与多文件等无关主线，新篇实际依赖的缺口则先补齐再使用。

选章时核对入口问题、实际前置和需补足的语义；二审同时检查准确性、概念引入、可推演行为及篇章职责。覆盖范围或依赖关系改变时同步本页，补强完成后更新状态。

## 专题扩展

- **精细对象模型：** 已有布局、对齐、原生数组、分配和构造附章；存储复用、对象表示、联合体活跃成员、自定义分配及复杂继承布局，按相关正确性问题深入。
- **高级泛型：** 依赖名称与查找、特化、参数包及更复杂的编译期类型计算，承接具体泛型设计问题。使用这些设施所必需的语义留在对应主线。
- **工程组织与验证：** 在多文件程序和资源模型之上扩展模块、构建、测试、性能分析、接口二进制兼容及 C 互操作；平台条件就近说明。
- **专门库与设施：** 位操作、时间、随机数、数值计算、正则表达式及其他容器，按实际用途选择入口；新增容器应补齐一种明确的组织或访问能力。
