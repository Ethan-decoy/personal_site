# C++ 速查写作规范

## 定位

本规范约束 `src/notes/cpp/` 中的速查正文及其目录索引，与 [主线写作规范](./writing-style.md)独立。速查面向已经知道类型或操作名称、需要立即查用的读者，回答“有哪些接口、能做什么、怎样调用”。语言基准为 C++23。

速查像公式表：**调用形式与作用直接对应，结果和条件就地可见。**质量取决于定位速度、对应关系和条件的准确性。主线的顺读依赖、概念推演、完整程序演示与掌握层级不作为速查的写作要求。

## 条目表达

以“调用 → 作用／返回值；必要条件”为基本关系。可以用紧凑表格、并列条目或带短注释的调用表达；按实际内容选用，不规定固定栏目或字数。

- 调用保留 C++ 写法，作用用短语或简单关系式表达。省略模板声明、重复的程序外壳和推演过程；需要辨认的类型、头文件、版本和符号在附近说明。
- 一个条目对应一个可查用的操作。语义相同的重载可以并列；参数形式、结果或前提有实质差别时分开，避免把不同契约压成含糊的一个词。
- 返回值与修改效果分别说清。返回引用、位置、数量或 `void` 会改变后续用法，应直接可见；“删除”“追加”等动词不能代替返回信息。
- 非空、有效下标、有效区间、顺序要求、借用失效和版本限制等必要条件与对应操作同处。共同条件可以集中说明，但不能依靠跳转才能判断当前调用是否成立。
- 示例只用于消除调用歧义，以短调用、前后状态或最小片段为宜。正文不展开问题引入、分步讲解、完整程序输出与学习提示。

例如，假设 `vec` 是可修改的普通 `std::vector<T>`，`x` 是元素值：

| 调用 | 作用／返回 | 条件 |
| --- | --- | --- |
| `vec.push_back(x)` | 尾部追加 `x`；`void` | 元素可从 `x` 复制构造；可能重新分配 |
| `vec.pop_back()` | 删除末项；`void` | 容器非空 |

例子的列数、符号和分组只是表达示意；保持关系完整比形式一致更重要。

## 页面组织

按类型或明确的查阅对象建立入口，页首简短标明范围、头文件与版本；调用中的占位符一次定义。同一对象的成员按能力就近分组，函数名与调用直接出现在条目中，避免先列一份名称目录再重复展开相同内容。

构造、运算符及相关非成员操作可以按需求补充，并标明归属。成员速查以对象的成员接口为主体，正文止于接口条目及其必要说明，不设置关联查阅、参考资料等附带栏目。目录索引负责定位已有条目，不承载讲解与规划。

代码与命名的共同约定见 [C++ 代码规范](./coding-style.md)。公式式调用中的占位符可以简短，但含义必须明确；真正的代码片段应能在注明的语境中编译。

## 维护与核对

写作或修改条目时，就当前用途核对标准接口与版本。检查调用、效果、返回值与条件能否独立查用，以及压缩后是否遗漏会改变结果或正确性的限制；必要细节在对应条目中给出，解释过程留在主线。
