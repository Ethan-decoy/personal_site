# 从源码到可执行程序

C++ 实现通常把源文件依次交给预处理器、编译器、汇编器和链接器。这个模型能解释命令的作用与产物之间的关系，但工具链不一定真的把每一种中间文件写入磁盘。

## 常见的概念流水线

```text
.cpp
  -> 预处理后的 C++ 源码
  -> 汇编代码
  -> .o / .obj 目标文件
  -> 可执行程序、共享库，或经归档形成静态库
```

GNU 工具链常用 `.ii` 表示预处理后的 C++ 文件，用 `.i` 表示预处理后的 C 文件，并用 `.s` 表示汇编文件。这些是常见命名约定，不是 C++ 语言强制要求的构建产物。

默认执行完整构建时，编译器驱动程序可以把中间结果直接传给下一阶段。只有显式要求保留中间结果时，才一定能在目录中看到 `.ii` 或 `.s` 等文件。

## 预处理

预处理阶段处理 `#include`、`#define` 和条件编译指令。被包含文件的内容会进入当前源文件，宏会展开，不满足条件的代码会被排除。

C++ 的早期翻译阶段还会处理注释。理解上可以说注释不再参与后续语法分析；更精确地说，注释会被替换为空白，而不是变成程序中的 C++ 标记。

使用 GNU 风格的编译器驱动程序时，可以只运行到预处理：

```bash
g++ -E main.cpp -o main.ii
```

## 编译

编译阶段分析 C++ 语法、名称、类型和表达式。当前翻译单元通常可被转换为目标平台的汇编表示，许多优化也发生在这一阶段。

工具链也可以使用集成汇编器，或不把汇编文本写入磁盘。开启链接时优化（LTO）后，一部分优化还可能推迟到链接相关阶段。

可以要求驱动程序运行预处理和编译，然后停在汇编文件：

```bash
g++ -S main.cpp -o main.s
```

该命令通常不会继续生成目标文件，也不会链接。

## 汇编

汇编器把汇编表示转换为目标文件：

```text
main.s -> main.o
```

目标文件已经包含机器代码和数据，但通常仍有尚未解析的外部符号以及供链接器使用的重定位信息，因此它还不是完整的可执行程序。

下面的命令运行预处理、编译和汇编，然后跳过链接：

```bash
g++ -c main.cpp -o main.o
```

`-c` 不是“只做编译阶段”。它会完成生成目标文件所需的前三个阶段，只是不再调用链接器。

## 链接

链接器组合一个或多个目标文件和库，解析跨文件的函数或变量引用，并处理重定位，最终生成可执行程序或共享库。

```bash
g++ main.o price.o -o app
```

“重定位”不等于把每个引用永久改成最终内存绝对地址。位置无关可执行程序、共享库和动态加载器可能让部分地址在装载时甚至运行期间才能确定。

在 Windows 上，可执行文件通常采用 `.exe` 后缀，并常使用 PE/COFF 格式。在 Linux 上，可执行文件通常采用 ELF 格式，但文件名不需要固定后缀，可以直接叫 `app`。

文件后缀、文件格式和“是否可执行”是不同问题。Linux 上的 `app` 没有后缀，不表示它不是二进制可执行文件。

## 一步构建与分步构建

一步生成可执行程序：

```bash
g++ main.cpp price.cpp -o app
```

分开生成目标文件，再链接：

```bash
g++ -c main.cpp -o main.o
g++ -c price.cpp -o price.o
g++ main.o price.o -o app
```

两种写法表达同一条基本流水线。第一种由驱动程序在一次命令中协调各阶段，第二种显式保留可复用的目标文件。

GNU 工具链还可以用 `-save-temps` 保留常见中间文件。具体文件名和选项属于工具链约定，不是 C++ 标准的一部分。

## `main` 与构建目标

单独生成目标文件时不要求当前 `.cpp` 定义 `main`：

```bash
g++ -c price.cpp -o price.o
```

静态库或动态库本身也不以 `main` 作为入口。最终构建可执行程序时，程序需要由实现规定的启动代码连接到合适的入口；普通托管 C++ 程序由它调用 `main`。

静态库可以看作供以后链接使用的一组目标文件。例如：

```bash
ar rcs libprice.a price.o
```

`libprice.a` 不是可直接运行的程序。通常只有某个目标链接它，并需要其中的符号时，它才参与构成最终产物。

## 构建阶段与未定义行为

语法错误、类型错误和找不到定义分别可能阻止编译或链接。如何根据最早证据识别失败阶段，见[失败阶段与最小复现](../diagnostics/failure-stages-and-minimal-reproduction.md)。

未定义行为不是预处理、编译、汇编或链接中的第五个阶段。它描述的是程序执行了 C++ 标准不规定结果的操作，例如某些越界访问或有符号整数溢出。

编译器可能对潜在的未定义行为发出警告，优化器也可以利用“程序不会执行未定义行为”的前提，但能成功构建不代表运行一定具有定义良好的行为。

## 核心检查

1. `.ii`、`.s` 和 `.o` 是可能出现的中间产物，不是每次构建都必须落盘。
2. `.o` 或 `.obj` 是目标文件，通常还不是最终可执行程序。
3. `-E` 停在预处理，`-S` 停在汇编文本，`-c` 停在目标文件。
4. 链接器组合目标文件和库，并完成符号解析与重定位。
5. Linux 可执行程序没有固定文件后缀；ELF 是常见文件格式，不是后缀。
6. 未定义行为属于程序语义，不是一个构建阶段。
