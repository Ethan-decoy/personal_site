# 第一课：对象、类型与值

## 对象、初始化与赋值

先建立三个关键区别：

- **对象**：程序运行时具有类型、生命周期和当前值的实体。
- **初始化**：创建新对象，并赋予它初始值。
- **赋值**：改变已有对象的值；不会创建新对象，也不会改变其类型。

例如：

```cpp
int tickets{4};         // 创建 int 对象 tickets，初始化为 4
int backup{tickets};    // 创建另一个独立对象 backup，初始化为 4
tickets = 9;            // 给已有对象 tickets 赋值
```

第二行读取 `tickets` 当时的值来初始化 `backup`。两个对象此后彼此独立，所以最后是 `tickets == 9`、`backup == 4`。这种复制得到的是源对象当时值的**快照**，而不是两个对象之间会自动同步的连接。

### 常见初始化写法

对于普通局部 `int`，常见写法及结果如下：

| 写法 | 初始化形式 | 对局部 `int` 的结果 |
| --- | --- | --- |
| `int x;` | 默认初始化 | 没有确定值，读取不安全 |
| `int x{5};` | 直接列表初始化 | `x == 5` |
| `int x = {5};` | 复制列表初始化 | `x == 5` |
| `int x(5);` | 直接初始化 | `x == 5` |
| `int x = 5;` | 复制初始化 | `x == 5` |

## 类型与窄化

`double` 可以表示小数，而 `int` 只能表示整数。把 `21.8` 转成 `int` 会丢失小数部分，得到 `21`，这称为**窄化转换**。

现代 C++ 通常优先使用花括号初始化：

```cpp
int count{3};
```

因为它会拒绝明显的窄化：

```cpp
int count{3.8};  // 编译错误：花括号初始化拒绝窄化
```

但下面两种写法在语言层面允许转换，编译器可能给出警告：

```cpp
int count = 3.8;  // 初始化，结果为 3
count = 6.9;      // 赋值，结果为 6
```

赋值不会改变对象的类型。`count` 始终是 `int`，因此赋值前会先把右侧的 `double` 值转换为 `int`。

所以花括号只能保护**初始化**，不能保护后续赋值。

### 语言错误与项目策略

还要区分两种情况：

```cpp
int a{temperature};
```

这会被语言规则判定为不合法，编译器必须给出诊断。

```cpp
int b = temperature;
```

这种转换在语言层面被允许，但编译器通常会给出警告。若项目把警告视为错误，构建也会失败，但那属于项目的构建策略，并不表示这条语句本身违反了 C++ 语言规则。

### 显式表达转换意图

如果确实决定丢弃小数，可以显式转换：

```cpp
double temperature{21.8};
int whole{static_cast<int>(temperature)}; // whole == 21
```

`static_cast<int>` 先产生一个 `int` 值，因此外层花括号不再发生窄化。

浮点数转换为整数时会**朝零截断**，而不是四舍五入：

```cpp
static_cast<int>(7.9)   // 7
static_cast<int>(-7.9)  // -7
```

但显式转换不等于“自动安全”。它只表示程序员主动接受该转换，因此使用前仍应确认：

- 丢失小数符合业务含义；
- 原值处于目标整数类型可表示的范围内。

如果截断后的值无法由目标整数类型表示，浮点数到整数的转换会产生**未定义行为**。写出 `static_cast` 并不能消除这个风险。

## 表达式先计算，再转换结果

赋值目标的类型不会反过来决定右侧表达式怎样计算。表达式会先根据操作数的类型完成计算，所得结果之后才被转换并赋给目标对象。

假设除数不为零：

```cpp
int points{7};
int players{2};

double average{};
average = points / players;
```

`points` 和 `players` 都是 `int`，所以先执行整数除法，得到 `7 / 2 == 3`；随后整数 `3` 才被转换为 `double`。最终 `average == 3.0`，已经丢失的小数部分不会因为赋给 `double` 而重新出现。

若希望执行浮点除法，必须在除法发生前把至少一个操作数转换为浮点类型：

```cpp
double precise{
    static_cast<double>(points) / players
};
```

`points` 先被转换为 `7.0`，为了完成同一次除法，`players` 也会被转换为 `double`，因此执行的是浮点除法，最终 `precise == 3.5`。

### 转换位置决定结果

```cpp
int distance{9};
int segments{4};

double after{
    static_cast<double>(distance / segments)
};

double before{
    static_cast<double>(distance) / segments
};
```

- `after == 2.0`：先执行整数除法 `9 / 4 == 2`，再把结果转换为 `double`。
- `before == 2.25`：先把 `distance` 转换为 `double`，再执行浮点除法。

在信息已经被整数除法丢弃后再转换，无法找回小数部分。
