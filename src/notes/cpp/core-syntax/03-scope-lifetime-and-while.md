# 第三课：作用域、生命周期与 while 循环

## 块作用域限制名称可见范围

一对花括号 `{}` 会形成一个块作用域。在块内声明的名称，只能从声明处开始在该块及其更内层作用域中使用：

```cpp
int total{3};

if (total > 0) {
    int added{5};
    total = total + added;
}

// added 在这里不可见
```

如果分支没有执行，分支中的局部对象不会被创建；如果执行了，对象会在进入声明时创建，并在离开该块时结束生命周期。

作用域回答“这个名称在哪里可见”，生命周期回答“这个对象在什么时候存在”。两者经常一起变化，但不是同一个概念。

## 遮蔽不是修改外层对象

内层作用域可以声明与外层同名的对象：

```cpp
int level{3};

{
    int level{10};
    level = 12; // 修改内层 level
}

// 外层 level 仍然是 3
```

内层名称会遮蔽外层名称。它们是两个独立对象，修改内层对象不会修改外层对象。若本意是更新外层状态，就不应在分支或循环体中重新声明同名对象。

## `while` 的执行顺序

`while` 在每轮循环体开始前计算条件：

```cpp
while (condition) {
    // 循环体
}
```

执行模型是：

1. 计算条件；
2. 条件为 `false` 时立即结束；
3. 条件为 `true` 时执行一次循环体；
4. 回到顶部，重新计算条件。

因此，条件一开始就是 `false` 时，循环体会执行零次。

## 区分控制状态、结果状态和轮次状态

循环通常同时维护几类状态：

```cpp
int current{1};
int total{0};
int rounds{0};

while (current <= 5) {
    total = total + current;
    current = current + 1;
    rounds = rounds + 1;
}
```

- `current`：决定是否继续，是控制状态；
- `total`：保存累计结果；
- `rounds`：记录已完成轮次。

每轮结束后是一个新的完整状态。下一次条件检查读取的是更新后的 `current`，而不是本轮开始时的旧值。

最终结果：

```text
current == 6
total == 15
rounds == 5
```

循环在 `current == 6` 时再次检查 `6 <= 5`，条件为 `false` 后结束。

## 边界和步长共同决定迭代序列

下面的循环：

```cpp
int level{12};

while (level > 3) {
    level = level - 4;
}
```

循环体开始时的 `level` 依次是：

```text
12, 8, 4
```

第三轮结束后 `level == 0`。循环不要求控制变量恰好落在边界 `3` 上；步长可以一次跨过边界。真正决定是否继续的是下一次条件 `level > 3`。

这也是 `<`、`<=`、`>`、`>=` 不能随意互换的原因：它们决定边界值是否进入循环体。

## 循环必须推动终止条件发生变化

```cpp
int guard{6};

while (guard > 0) {
    int work{1};
    work = work + 1;
}
```

循环体没有修改 `guard`，所以 `guard > 0` 会一直为 `true`。修改其他局部对象不会帮助这个条件变成 `false`。

正常终止通常需要：

- 控制状态在循环体中确实更新；
- 更新方向与条件边界一致；
- 每轮更新后最终能够越过或到达终止边界；
- 更新表达式本身不先触发未定义行为。

编译通过只能说明语法和静态规则被接受，不能证明循环一定终止。
