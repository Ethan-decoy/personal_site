# 调试器与调用栈

调试器用于观察一次具体执行中的控制流和状态。它能回答“这一次如何走到这里”，不能证明所有输入都走同一路径。

## 调试信息和优化是两个设置

Clang 的一个简单调试构建命令是：

```text
clang++ -std=c++23 -g -O0 main.cpp -o app
```

`-g` 请求生成源码行号、变量位置等调试信息。它不负责关闭优化，也不保证每个源码变量在任意位置都能被观察。

`-O0` 关闭大部分优化，使源码与执行位置通常更容易对应。它不改变 C++ 语言规则，也不是“逐行解释执行”的保证。

优化后的程序仍可携带调试信息，但变量可能被合并、移除或只在部分位置可用，单步位置也可能跳动。若问题只在优化构建出现，应保留该构建作为证据，不能只观察 `-O0` 后宣称问题消失。

编译器、链接器和平台对选项的支持不同。上面的命令适用于常见 Clang 环境；在 Visual Studio 工具链中应使用对应的 Debug 配置和调试信息选项。

## LLDB 的普通断点

以下命令属于 LLDB，不是所有调试器通用语法：

```text
breakpoint set --name discounted_price
run
frame variable
next
step
continue
```

- `frame variable`：查看当前栈帧可用的参数和局部变量；
- `next`：执行下一步，通常不进入被调用函数；
- `step`：执行下一步，并尝试进入被调用函数；
- `continue`：继续运行到下一次暂停或结束。

“当前不可见”不一定说明变量不存在。它也可能尚未进入生命周期、已离开生命周期、被优化掉，或缺少足够调试信息。

## 条件断点

循环或频繁调用的函数中，条件断点可减少无关暂停：

```text
breakpoint set --name category_for --condition 'score == 10'
```

条件必须能在断点位置的上下文中求值。名称不可见、表达式有副作用或调试信息不足，都可能让条件表现与预期不同。

断点命中证明这次执行到达了该位置。它不证明其他输入会到达，也不证明没有命中的分支不可达。

## 调用栈回答调用路径

调用栈记录当前尚未返回的函数调用链：

```text
main
└── invoice_total
    └── discounted_price
```

LLDB 使用 `bt` 查看回溯。每层调用对应一个栈帧；切换栈帧后，可以查看该层可用的参数和局部状态。

调用栈适合调查：

- 哪个调用者传入了错误参数；
- 同一函数是经由哪条路径到达的；
- 问题发生在调用点、被调用函数，还是更早的数据来源。

调用栈只描述当前线程在暂停时的活动调用。异步任务、其他线程、已经返回的调用和被优化内联的函数，需要结合调试器的其他视图解释。

## 一次可重复的观察

记录断点位置、触发输入、构建配置、调用栈，以及修改前的关键变量值。随后只改变一个假设并重跑，才能把观察变成可比较的证据。

调试器观察应与规格测试、严格警告和运行时检查配合。一次单步过程不是回归测试，也不能替代对接口和生命周期的静态推理。
