# 作用域与生命周期

## 两个不同的问题

- **作用域**回答：一个名称可以在源码的哪些位置使用？
- **生命周期**回答：一个对象从什么时候开始存在，到什么时候结束存在？

两者经常一起变化，但并不是同一个概念。

## 块作用域限制名称可见范围

作为复合语句使用的 `{ ... }` 会形成块作用域。在块内声明的名称，只能从声明处开始，在该块及其更内层作用域中使用：

```cpp
int total{3};

if (total > 0) {
    int added{5};
    total = total + added;
}

// added 在这里不可见
```

如果分支未执行，`added` 不会被创建。如果分支执行，它会在声明处开始生命周期，并在离开所在块时结束生命周期。

外层 `total` 在分支前已经存在，离开分支后仍然存在，并保留在分支内完成的修改。

## 遮蔽会引入另一个对象

内层作用域可以声明与外层同名的对象：

```cpp
int level{3};

{
    int level{10};
    level = 12;
}

// 外层 level 仍然是 3
```

内层名称会遮蔽外层名称。这里有两个独立对象，`level = 12` 修改的是内层对象。

若本意是更新外层状态，就不应在内层重新声明同名对象：

```cpp
int level{3};

{
    level = 12;
}

// 外层 level == 12
```

## 名称不可见不一定表示对象已消失

名称的可见范围与它所表示对象的生命周期必须分别判断。例如，块内的引用名称可以先变得不可见，而它绑定的外层对象继续存在；反过来，如果对象的生命周期先结束，仍保存的引用也不能再用来访问它。

相关代码示例和安全边界统一放在[引用与别名](references-and-aliasing.md)中。

## 函数调用也创建局部对象

函数的形参和普通非 `static` 局部对象会为每次调用分别建立，不会作为同一个对象跨调用保留。嵌套块中的对象可以在函数返回前结束生命周期；函数体这一层的普通自动对象会在离开函数时销毁。

函数内的局部 `static` 对象具有不同的存储期，不会随每次调用结束而销毁；它不在当前学习范围内。

不同函数的局部名称不会自动共享。函数调用、值形参与返回值见[函数、值传递与返回值](../functions/functions-value-passing-and-return.md)。
