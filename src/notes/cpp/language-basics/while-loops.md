# `while` 循环

## 执行顺序

`while` 在每轮循环体开始前计算条件：

```cpp
while (condition) {
    // 循环体
}
```

执行顺序是：

1. 计算条件；
2. 条件为 `false` 时结束循环；
3. 条件为 `true` 时执行一次循环体；
4. 回到顶部，重新计算条件。

因此，条件一开始就是 `false` 时，循环体会执行零次。

## 区分控制状态、结果状态和轮次状态

```cpp
int current{1};
int total{0};
int rounds{0};

while (current <= 5) {
    total = total + current;
    current = current + 1;
    rounds = rounds + 1;
}
```

- `current` 决定是否继续，是控制状态；
- `total` 保存累计结果；
- `rounds` 记录已完成轮次。

每轮结束后形成一个新状态。下一次条件检查读取更新后的 `current`，不是本轮开始时的旧值。

最终：

```text
current == 6
total == 15
rounds == 5
```

循环在 `current == 6` 时再次检查条件，得到 `false` 后结束。

## 边界和步长共同决定序列

```cpp
int level{12};

while (level > 3) {
    level = level - 4;
}
```

循环体开始时的 `level` 依次是：

```text
12, 8, 4
```

第三轮结束后 `level == 0`。控制变量不必恰好落在边界 `3` 上；步长可以一次跨过边界。

`<`、`<=`、`>`、`>=` 不能随意互换。它们决定边界值是否会进入循环体，步长则决定实际能够到达哪些值。

## 循环必须推动终止条件变化

```text
int guard{6};

while (guard > 0) {
    // 执行工作，但没有改变 guard
}
```

这段只用于分析控制状态，不应作为程序直接运行。若没有省略的 `break`、异常或其他退出机制，循环体没有修改 `guard`，条件就会一直为 `true`。修改不参与条件的无关局部对象不能帮助这个条件变为 `false`。

正常终止通常需要：

- 控制状态确实在循环体中更新；
- 更新方向与边界一致；
- 更新最终能使条件变为 `false`；
- 更新表达式不会先产生未定义行为。

编译成功只能说明源码通过了相应的静态检查，不能证明循环一定终止。

## 逐轮检查循环

分析循环时，可以为每一轮记录：

| 时点 | `current` | 条件 | 循环体是否执行 |
| --- | ---: | --- | --- |
| 第一次检查 | 1 | `1 <= 5` | 是 |
| 第一轮结束 | 2 | 尚未重查 | 已完成一轮 |

要明确区分“循环体开始时的值”和“本轮更新后的值”。这两个时点不同，不能混作同一状态。
