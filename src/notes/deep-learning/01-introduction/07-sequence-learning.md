# 序列学习

房价预测可以把一套房屋表示为固定长度的特征向量，图像分类也可以接收固定尺寸的图像。而在视频、语言和连续监测中，我们还需要考虑：当前输入处在什么位置，与前后的内容有什么关系？

## 顺序与上下文

### 从单个观测到一段历史

一个视频片段由多帧图像组成，不同片段可能包含不同数量的帧。通过前一帧，我们可能对后一帧发生的事情更有把握；如果只看彼此孤立的画面，就可能丢掉动作变化的线索。

一段视频本身可以作为一个样本，帧则是这个样本内部按时间排列的元素。**同一序列内部的元素相关，与不同样本之间是否独立，是两个不同的问题。**

再设想一个监控重症监护病人的预测任务：在某个时点，利用此前每小时的监测记录，估计病人在随后24小时内死亡的风险；超过约定阈值时发出警报。过去一段时间的变化可能提供单次测量没有的信息。输入必须是预测时已经获得的记录，未来24小时的实际结果用于形成标签。

> [!IMPORTANT] 顺序与上下文影响预测
> **序列学习利用按顺序组织的数据，学习位置之间的关系，并据此作出预测或生成序列。** 顺序可能是视频和监测数据中的时间，也可能是文本中的词序；忽略这些关系，可能丢掉任务需要的信息。

### 利用上下文的不同方式

**固定长度的输入也能包含历史。** 例如，把最近若干次测量按时间顺序组成一个固定长度向量，就能让模型利用这一段历史。原书后续的[序列模型](https://zh.d2l.ai/chapter_recurrent-neural-networks/sequence.html)会用固定历史窗口建立预测模型。

模型还可以逐步维护对过去信息的状态，或通过注意力关联给定上下文中的不同位置。例如，2017年提出的[Transformer](https://arxiv.org/abs/1706.03762)用注意力处理序列，不依赖循环结构。具体计算方式将在后续展开。

这里所说的“记忆”，应理解为**当前预测可用的上下文或状态**。在参数固定的预测过程中，输入历史或上下文发生变化，并不等于模型参数重新接受了训练。

## 输入输出的组织方式

> [!IMPORTANT] 输入输出不必同时为序列
> 序列学习可以接收输入序列、预测输出序列，或两者兼而有之。**输入输出不必同时为序列，也不必都是可变长度。** 先明确一个样本包含什么，再判断预测目标怎样组织。

下面几种任务可以作对照：

| 输入与输出形式 | 例子 |
| --- | --- |
| 序列 → 单个输出 | 一段历史监测记录 → 未来24小时的风险概率 |
| 序列 → 逐位置标签 | 一个句子的词序列 → 每个词的实体标记 |
| 序列 → 另一种序列 | 录音 → 转写文本，或源语言句子 → 译文 |

如果用输入与对应目标组成的数据训练，这些任务仍然可以采用[监督学习](04-supervised-learning-and-regression.md#用带标签的样本学习预测关系)。**“序列”描述输入输出的组织，“监督”描述训练信号的来源**，两者回答不同的问题。

## 序列之间的对应关系

### 逐词标记与结构解析

**序列标记**（sequence labeling）为序列中的各个位置附上标签。例如，给句子中的每个词标记是否属于命名实体。下面用 `Ent` 表示实体（entity），用 `-` 表示未标记为实体：

```text
Tom has dinner in Washington with Sally
Ent  -    -    -     Ent      -    Ent
```

这里有七个词，也有七个标签，`Tom`、`Washington` 和 `Sally` 被标为实体。这个简化例子只区分是否为实体，没有进一步区分人名、地名等类型。

逐词标记可以做到一个词对应一个标签，但**句法解析**还会描述词语怎样组成短语、彼此有什么结构关系。例如，[句法成分分析](https://stanfordnlp.github.io/stanza/constituency.html)可以输出一棵句法树，不能把所有解析任务都概括成相同数量的逐词标签。

### 语音识别中的不同粒度

**自动语音识别**（automatic speech recognition，ASR）的输入是录音，输出是说话内容的转写文本。同一段声音有不同的表示方式，比较长度前要先区分计数单位：

- **波形采样点**：数字音频在某个时刻记录的数值。16 kHz采样率表示每秒记录16,000个采样点。
- **声学帧**：从一小段声音中提取的特征，相邻帧对应的时间窗口可以重叠；一帧通常覆盖多个采样点。
- **文本单位**：可以按字、词或子词等计数，要与当前采用的文本表示对应。

例如，2022年的[Whisper论文](https://arxiv.org/html/2212.04356v1)将音频重采样到16 kHz，并以25毫秒窗口、10毫秒步长提取声学特征。采样点与声学帧是不同层次的表示，不能把每秒采样点数直接当作每秒帧数。

> [!IMPORTANT] 比较长度先明确表示单位
> 对同一段语音，按波形采样点或声学帧计数的输入，通常比按字或词计数的转写文本长得多。**输入输出不要求逐位置一一对应，长度关系要连同比较单位一起解释。**

### 从文本生成语音

**文本转语音**（text-to-speech，TTS）在输入输出方向上与语音识别相反：输入文字，输出表达这些文字的语音。按文本单位与波形采样点比较时，输出通常更长。

同一句话可以用不同语速、停顿和重音说出，产生的音频长度也可能不同。模型不仅要生成与文字相符的发音，还要组织这些发音在时间上的展开。

### 翻译中的词序重排

**机器翻译**（machine translation）把一种语言的文本序列转换成另一种语言的文本序列。与通常沿发音时间顺序写出文字的语音转写相比，翻译还需要按照目标语言的语法重新安排信息。

例如，同一个意思可以用下面的德语与英语句子表达：

> **德语**：Haben Sie sich schon dieses grossartige Lehrwerk angeschaut?
>
> **英语**：Did you already check out this excellent tutorial?
>
> **按德语词序直译**：Did you yourself already this excellent tutorial looked-at?

最后一行保留源语言的排列方式，却不符合自然的英语表达。原句的助动词 `Haben` 在句首，过去分词 `angeschaut` 在句末；这种前后分布可以结合德语的[句框结构](https://grammis.ids-mannheim.de/systematische-grammatik/1241)理解，不能简化成所有动词都在句尾。

**翻译需要的是词语和短语的重排，而非把整个序列倒过来。** 输入输出的词数也可能不同，但这个例子主要展示对应内容的位置变化。

### 文档阅读顺序与对话历史

序列问题也可以与空间布局联系。例如，根据一页文档中文字块的内容与二维位置，预测它们的逻辑阅读顺序。[LayoutReader（2021）](https://aclanthology.org/2021.emnlp-main.389/)就是结合文本与布局预测阅读顺序的例子；这里的目标是文档内容的排列，不是某个用户实际的视线轨迹。

对话任务则需要根据当前可用的对话历史生成后续回应。同一个问题放在不同的上下文中，可能需要不同的回答；哪些历史信息仍然可用、哪些信息与当前问题有关，都会影响预测。
