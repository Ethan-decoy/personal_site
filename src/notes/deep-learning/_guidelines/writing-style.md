# 深度学习写作与重点呈现规范

用于正文、章节索引、小结与练习的构建、修饰和审阅。范围与依赖见 [book-structure.md](book-structure.md)，图文表达见 [illustration-style.md](illustration-style.md)，代码见 [coding-style.md](coding-style.md)，接入与证据维护见 [authoring.md](authoring.md)。

“应”“须”“不得”表示要求；“默认”“优先”表示可依据具体内容调整的选择；“可以”表示可选做法。例子用于说明取舍，不构成固定栏目或数量配额。

## 原文与修饰边界

优先保留原书已经成立的概念、论证顺序、推导条件和有效例子。修饰从段落层次、术语强调、核心关系、精确对照及图文对应入手；成熟的解释可以直接保留，不要求换一种说法证明经过整理。

调整措辞、压缩叙述或提炼重点时，保留结论的对象、条件与程度。“可能”“通常”“在该例中”等限制若影响判断，须与结论一起保留。类比承担解释用途，提炼时应落回实际对象与关系。

发现疑似错误、内部矛盾或时效性表述时，先核对相应一手资料；尚未核实的内容标为待核实，不将其提炼成确定的核心结论。来源与实质修改按[来源与适配](authoring.md#来源与适配)维护。

## 问题与阅读层次

每节让读者知道当前在解释什么关系，能依据正文理解结果，并识别结论的适用范围。标题定位概念、问题或区别，使用普通文本，省略章节与小节编号。

段落按当前关系组织。转入新的判断、对照或计算阶段时，可以增加小标题、拆段或分步呈现；同一条推理保持连贯。原书用于建立直觉的叙述、例子和适量幽默可以保留，篇幅以理解所需为准。

普通 Markdown 正文中的单换行仍按同一段处理，段落之间使用空行分隔。按实际渲染确认定义、例子与条件的边界，避免多个解释层次因源码换行而挤在一段中；分段以完整关系为单位，不逐句机械拆开。

跨段、跨图或跨节时，名称、符号、样本和值应能对应。“前面”“上述”已有明确语境且当前解释充分时可以保留；必要的前提已经移到别篇时，恢复当前要用的最短联系并给出主要讲解入口。

索引承担导航，正文直接讲知识。构思说明、审阅理由、迁移进度与重复的逐篇落款留在维护材料中。

## 掌握要求

先判断读者怎样使用当前知识，再决定怎样突出：

| 掌握方式 | 选择依据 | 呈现重点 |
| --- | --- | --- |
| 熟记并直接调用 | 后续理解与判断反复依赖的定义、核心关系和条件 | 提炼可用于同类情形的关系，保留范围与用途 |
| 理解并能重建 | 例子的推演、公式的来由、数值变化与算法过程 | 显示必要的中间关系，让结果能够被重新解释 |
| 使用时查阅 | 随版本、数据、设备或历史时点变化的规格与具体事实 | 说明核对什么及可靠入口；历史数字不默认成为记忆任务 |

同一知识可以兼有不同掌握要求。公式的重要性由其作用决定，不能仅因出现数学符号就要求背诵；例子的具体数值也不自动成为通用结论。

需要直接调用的核心关系应在建立处用 `IMPORTANT` 就地突出；方法、工程做法与易错边界按各自职责呈现。章末小结可以串联，不能代替正文中的首次重点标识。

## 视觉层次与局部强调

- 加粗用于当前定义、关键区别、核心关系和影响判断的条件。强调完整到足以辨认含义的短语或句子，避免只把孤立术语标亮而藏住其作用。
- 原书的术语斜体可按本站的重点层次调整；数学中的变量与向量排版保留相应数学含义。首次必要术语保留中文与英文，后续称谓稳定。
- 普通正文承担因果、例子与推演，提示块承载可独立回顾的关系或判断。已有清楚的段落可以就地调整成框；有助回顾的提炼应承担新的取用作用。
- 对照表用于输入输出、标签关系、状态或条件的精确对应；图示用于结构、流动、变化与空间关系。选择依据见[图文分工](illustration-style.md#图文分工)。
- 从整节检查核心关系是否可定位，同时检查强调是否泛化或重复。仅有彩色边框不代表已建立理解，不用整段加粗、连续框体或装饰性配图替代解释。

不设每篇的框数、加粗比例、段落长度或配图数量。背景与史述可以依靠标题、时间线或局部强调形成层次，无需为了形式统一提炼记忆框。

## 重点与提示块

使用站点已有的 `> [!TYPE] 可选标题` 写法，块内各行含空行保留 `>`。本分类按以下职责选型，视觉样式复用 [Markdown 文档排版](../../../../docs/DESIGN.md#24-markdown-文档排版)。

| 类型 | 独立取用的内容 | 必须保留的信息 |
| --- | --- | --- |
| `IMPORTANT` | 需要直接调用的核心模型、关系或区别 | 哪些对象在什么条件下有什么关系；术语清单、口号或本例结果不足以成立 |
| `TIP` | 核对数值、形状、结果或定位问题的方法 | 查什么、怎样查，以及结果怎样影响判断 |
| `PRACTICE` | 数据、实验、实现或工作流程的组织建议 | 采用条件、理由，以及影响选择的收益与代价 |
| `WARNING` | 具体的错误预期或用法 | 触发条件、失效的假设和后果 |
| `NOTE` | 与主线有关、需要独立查阅的背景或旁支 | 补充事实与主线的联系，保留主线必需的解释 |
| `CAUTION` | 当前操作可能造成数据、文件、环境或外部状态损失 | 风险来自哪项操作，以及执行前的保护条件 |

核心关系的条件可以放在同一蓝框；需要额外纠正具体误判时再用 `WARNING`。解释关系与提供检查方法分别判断，信息重要也不意味着都应使用蓝框。普通的模型误差或运行失败不自动构成操作风险。

`IMPORTANT` 应有概括对象或关系的标题；其他类型按定位需要填写。标题与正文直接写知识，不额外写“核心”“需要熟记”等掌握标签，标题不再加粗或套行内代码。关联的结论、解释和例子可以同框，确需分别定位时再拆分。

例如，四个学习组件各自的作用可以在原列表处合成核心关系框；训练集表现好而新数据表现差的具体误判可以独立突出。是否成框要看当前解释和用途，不能将这些例子作为每篇的必备栏目。

## 数学、模型与证据

引入公式时，就近说明当前要计算或判断什么，以及所用符号、范围和必要条件。涉及向量、矩阵或张量运算时，补足当前判断所需的形状与轴含义；等式、近似、示意与实验观察分别表明。

区分模型结构、参数、训练信号、目标函数、优化过程与评价结果。训练误差与泛化表现、预测概率与决策代价、优化目标与评价指标的关系，应按当前任务说明，提炼时保留原有区别。

理论推导由假设与推理支持，实验结果由数据与运行条件支持；直觉示意用于建立关系。一次运行、一个可视化形状或一个历史成功案例，不能单独证明所有输入上的规律。

## 时效性与知识更新

修饰同时判断内容是否仍适合当前学习。按知识的作用选择更新方式：

| 内容性质 | 更新取舍 |
| --- | --- |
| 定义、数学关系、算法机制与有效例子 | 保留仍成立的解释；校正错误或补充缺失条件，不因年代较早而自动改写 |
| 历史过程、旧实验与当时的工具 | 写清事件、实验或叙述的时间范围；保留其解释用途，避免把历史纪录写成当前结论 |
| 当前能力、框架状态、接口、性能与应用判断 | 核对与判断直接相关的一手论文、官方文档或实际测量，说明适用任务、版本及核对范围 |

“目前”“最近十年”等表述应有可辨认的时间范围。源码快照、文献发表时间、实际核对日期与本站修订日期分别记录；取得新快照或改动年份不等于内容已更新。核对与适配证据按[来源与适配](authoring.md#来源与适配)维护。

新增进展须帮助理解当前问题，并与已有概念建立联系。例如，自监督预训练可以连接数据与目标函数，工具调用可以连接环境交互与参数更新。引言只建立必要的关系和阅读入口，具体机制随前置知识展开；产品名称、排行榜与最新纪录按实际用途选择。

描述能力时区分论文实验、产品功能与可稳定依赖的行为。模型的推理表现、工具调用、训练时的强化学习和使用时的参数更新分别核对，不能依据一个标签互相推定。对通用智能、意识、职业影响或长期风险的判断保留定义、证据与不确定性。

## 审阅时的使用

审阅覆盖本文及当前生效的关联要求，既检查已有强调是否合适，也检查值得突出却遗漏的核心关系。对每项取舍给出实际位置和理解上的影响；区分规范偏离、可选改进与待核实事项。

只扫标题、加粗与重点框，应能定位当前节需要反复调用的关系；顺读正文，应能追踪这些关系的来由与条件。工程检查、数学核对、实验与实际显示检查分别说明范围，不能相互代替。
