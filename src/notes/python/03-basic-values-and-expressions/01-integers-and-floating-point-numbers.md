# 整数与浮点数（Integers and Floating-Point Numbers）

`3` 与 `3.0` 都可以表示数学上的三，却得到不同类型的对象。整数与浮点数采用不同的表示方式，混合计算得到什么类型、数值能否精确表示，也需要按相应规则判断。

脚本示例均为完整程序，分别在 Windows 64 位 CPython 3.14.10 中独立核对。浮点数的表示按该环境说明。

## 整数的值与精度

`int` 表示整数，包括正整数、零与负整数。`3`、`1000` 这样的十进制整数字面量，求值得到相应的整数对象。

数字之间的单个下划线 `_` 可以用于分组，改善源码的可读性。`1_000` 与 `1000` 表示相同的整数值，下划线不会成为数值的一部分，也不会由普通的整数输出保留下来。

```python
value = 999_999_999_999_999_999
result = value + 1

print(result)
print(type(result))
```

右侧的加法取得两个整数对象，按整数值精确求和，再将名称 `result` 绑定到结果。输出为：

```text
1000000000000000000
<class 'int'>
```

结果比原数多了一位，类型仍是 `int`。[`type` 取得对象的类型](../02-names-objects-and-assignment/02-object-types.md#值类型与显示结果)，这里显示的是整数类型对象。整数的表示位数可以随数值增长，不需要因为这个结果多了一位，就由程序改用另一种整数类型。

> [!IMPORTANT] 整数的精确表示
> **`int` 的表示精度不由固定数量的十进制位数限定；普通整数加法正常完成时，得到精确的整数结果，结果所需的位数可以增长。**实际能处理的规模仍受可用内存和计算资源限制。

## 浮点写法与混合计算

包含小数点的 `3.0`、`0.5`，以及指数形式 `1e3`，都会得到浮点对象，类型为 `float`。浮点数（floating-point number）采用有限精度的表示；数值恰好是整数，也仍然可以由浮点对象表示。

`1e3` 中的 `e` 表示以十为底的指数：一乘以十的三次方，数值为一千。这整段写法是一个浮点字面量，不要求先建立名称 `e` 的绑定。

```python
print(type(3))
print(type(3.0))
print(type(1e3))
print(1e3)
```

输出为：

```text
<class 'int'>
<class 'float'>
<class 'float'>
1000.0
```

`3.0` 的值恰好是数学整数三，类型仍是 `float`。`1e3` 没有小数点，也因指数写法而得到 `float`。辨认类型时，要看完整的数值写法，不能只看输出中有没有小数部分。

内置 `int` 与 `float` 支持混合数值加法。计算采用浮点规则，正常完成时得到浮点结果；其精度与范围也遵循浮点表示的限制：

```python
count = 3
result = count + 0.5

print(result)
print(type(count))
print(type(result))
```

第二行读取 `count` 取得整数对象，与浮点数 `0.5` 相加，再将 `result` 绑定到所得对象。输出为：

```text
3.5
<class 'int'>
<class 'float'>
```

`result` 引用浮点结果 `3.5`，`count` 仍然引用原整数对象 `3`。计算中采用浮点数值，没有改变原对象的类型，也没有重新绑定 `count`；这符合[类型属于对象、赋值改变名称绑定的关系](../02-names-objects-and-assignment/02-object-types.md#重新绑定与对象类型)。

> [!IMPORTANT] 混合加法与结果类型
> **内置 `int` 与 `float` 的数值加法正常完成时，结果类型为 `float`，精度与范围遵循浮点规则。**原整数对象的类型与引用它的名称绑定，不会因为参与这次加法而改变。

本节讨论普通有限的浮点数值。处理极大或极小量级的数据时，需要核对实际浮点实现的精度与范围，规格入口见官方的 [`sys.float_info` 说明](https://docs.python.org/3.14/library/sys.html#sys.float_info)。

## 有限表示与舍入

本篇采用的 CPython 环境使用二进制浮点表示。二进制小数的各位依次对应二分之一、四分之一、八分之一等；`0.5` 正好是二分之一，`0.25` 正好是四分之一，都能用有限位表示。

有限位二进制小数可以写成某个整数除以二的若干次方。十分之一化成最简分数后，分母十还含有因子五，无法用这种有限表示精确保存。它类似于十进制中的三分之一：写下有限多个小数位，只能得到近似值。

不能精确表示的值，需要取附近可表示的值，这种按表示精度取近似值的处理称为舍入（rounding）。因此，源码中的 `0.1` 求值为浮点对象时，就已经产生了表示近似；运算结果也可能需要再次舍入。

`print` 通常采用简短的十进制形式显示浮点数。浮点对象显示为 `0.1`，不意味着其中保存的数值恰好等于十分之一。数值的表示与输出形式仍需区分。

```python
result = 0.1 + 0.2
print(result)
print(result == 0.3)
```

在本篇核对的环境中，输出为：

```text
0.30000000000000004
False
```

加法先取得 `0.1` 与 `0.2` 各自对应的浮点值，再计算并保存浮点结果。两个输入已经是近似值，加法结果又按可用精度保存。本例得到的数值与字面量 `0.3` 对应的浮点值不同，因此[相等比较](../02-names-objects-and-assignment/03-object-identity-and-equality.md#相等与身份分别判断)得到 `False`。

有些小数与运算结果则能精确表示：

```python
result = 0.5 + 0.25
print(result)
print(result == 0.75)
```

输出为：

```text
0.75
True
```

两个输入分别是二分之一与四分之一，结果四分之三也能用有限位二进制小数表示，这次加法可以精确完成。浮点表示不意味着每个数值、每次运算都必然产生误差。

> [!IMPORTANT] 浮点表示与舍入
> **在这里的二进制浮点环境中，能够精确表示的有限值可以按原值保存，不能精确表示的值需要舍入；运算结果也可能再次舍入。**这些数值的相等比较按实际数值判断，不能把理想的十进制等式直接当作浮点比较结果。

`==` 判断两个数值是否相等；允许一定误差的“是否足够接近”，还需要另外的判断标准。输出的小数位数与实际保存的数值也须区分，缩短显示不会自动改变此前已经完成的计算。
