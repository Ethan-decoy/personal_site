# 列表切片赋值（List Slice Assignment）

[切片读取](02-list-slicing.md#切片写法与选取结果)返回新列表，切片作为赋值目标时则修改原列表。采用默认步长一的区间赋值，可以用不同数量的来源元素替换原区间，改变列表长度；共享同一列表的名称，也会继续取得修改后的内容。

本篇以内置列表作为目标和替换来源，示例的目标切片均省略步长，实际步长为一。各个 `python` 代码块都是独立的完整脚本，分别在 Windows 64 位 CPython 3.14.10 中核对；预期失败的脚本也单独运行。

## 切片目标与替换来源

切片赋值（slice assignment）的基本写法是 `values[start:stop] = replacement`。先对右侧求值，取得替换来源，再由左侧切片指定原列表中需要替换的范围。左侧不作为切片读取来取得副本，列表名称本身也没有重新绑定。

替换来源需要能够逐个提供元素，也就是[可迭代对象](04-adding-and-removing-list-elements.md#追加一个对象与扩展一组元素)。列表按自身的元素顺序提供对象，替换的单位是其中的元素引用。

```python
values = [30, 10, 20, 40]
alias = values
values[1:3] = [99]

print(values)
print(alias)
print(values is alias)
print(len(values))
```

输出为：

```text
[30, 99, 40]
[30, 99, 40]
True
3
```

索引一、二处原来的两个元素，被右侧列表提供的一个元素替换。整数四十随后位于索引二处，列表长度由四变为三。`alias` 与 `values` 的绑定都没有改变，仍引用同一个列表，因此经两个名称取得的都是修改后的内容。

这延续了[共享引用与原地修改的关系](../02-names-objects-and-assignment/04-mutation-and-shared-references.md#修改同一个列表)。切片赋值改变原列表保存元素引用的安排，不因为内容或长度改变，就把列表名称绑定到另一个列表。

右侧本身是列表时，[单项赋值](01-lists-length-and-indexing.md#读取元素与替换元素)与切片赋值采用不同的替换单位。下面的 `one` 与 `many` 分别是接受单项替换和区间替换的两个独立列表：

```python
replacement = [99, 88]
one = [30, 10, 20, 40]
many = [30, 10, 20, 40]

one[1] = replacement
many[1:3] = replacement

print(one)
print(many)
print(one[1] is replacement)
```

输出为：

```text
[30, [99, 88], 20, 40]
[30, 99, 88, 40]
True
```

`one[1] = replacement` 把整个右侧列表对象作为一个元素，放在索引一处；身份比较确认这个元素就是 `replacement` 所指的列表。`many[1:3] = replacement` 则依次使用右侧的整数九十九、八十八，替换区间中的两个元素。

来源列表里的元素也没有被继续复制。如果元素本身是可变对象，插入后仍可与来源共享它；这一层引用关系与[切片读取保留元素引用](02-list-slicing.md#新列表与共享元素)的规则相通。

> [!IMPORTANT] 切片赋值的修改对象与替换单位
> **内置列表的切片赋值修改原列表，保持列表身份，不重新绑定列表名称。**右侧提供替换元素来源；对于本篇的列表来源，按顺序使用其中的元素引用，而不是自动把整个来源列表作为一个元素。其他仍引用同一目标列表的名称可以取得这项修改。

整数九十九可以成为列表的一个元素，却不能直接充当这里的一组替换元素来源：

```python
values = [30, 10, 20, 40]
print("start")
values[1:3] = 99
print("end")
```

源码合法，脚本先输出：

```text
start
```

第三行在执行切片替换时，因为右侧整数不能提供所需元素而引发 `TypeError`。本篇核对的 CPython 3.14.10 中，错误诊断的最后一行为：

```text
TypeError: must assign iterable to extended slice
```

本例的目标区间和默认步长都合法，失败的是替换来源的输入条件。本次尚未替换元素，`values` 仍为 `[30, 10, 20, 40]`。异常未被处理，脚本终止，`end` 不会输出；先前的 `start` 输出仍然存在。

## 步长为一时的长度变化

实际步长为一时，来源元素数可以与被替换元素数不同。每一项操作都先确定目标区间，再用来源中的元素替换它；区间之外的元素保留相对顺序，其位置可能随长度变化而调整。

下表每一行都从 `values = [30, 10, 20, 40]` 开始独立执行，不承接上一行的修改：

| 独立操作 | 操作后的列表 | 长度 |
| --- | --- | --- |
| `values[1:3] = [99]` | `[30, 99, 40]` | `3` |
| `values[1:2] = [99, 88]` | `[30, 99, 88, 20, 40]` | `5` |
| `values[2:2] = [99, 88]` | `[30, 10, 99, 88, 20, 40]` | `6` |
| `values[1:3] = []` | `[30, 40]` | `2` |

第一行用一个元素替换两个元素，因此缩短一项；第二行用两个元素替换一项，因此增加一项。第三行选中的区间为空，没有移除原元素，在起点处插入两个元素。第四行的来源为空，没有补入新元素，因而移除原区间。

**新长度等于原长度减去被替换的元素数，再加上来源元素数。**把目标写成 `values[:]`、来源写成 `[]`，就会移除全部元素，清空同一个列表。

边界仍按[切片的换算与裁剪规则](02-list-slicing.md#省略边界负值与越界)调整。空区间没有原元素可移除，来源元素插入到调整后的起点处。

> [!IMPORTANT] 步长为一的区间替换
> **实际步长为一时，列表切片赋值允许来源元素数与被替换元素数不同，因此可以改变列表长度。**空来源移除所选区间，空区间在调整后的起点插入来源元素；区间之外的元素保留相对顺序。增长、缩短、插入和删除都修改同一个目标列表。

这些允许改变长度的替换适用于实际步长为一的切片。**合法步长不等于一时，来源元素数必须与所选位置数相等，替换不改变列表长度。**零步长、浮点边界等仍不符合[切片的输入条件](02-list-slicing.md#步长方向与默认终点)。空区间的边界细则与带步长的逐项替换，见附章：[切片的边界与赋值细则](deep-dives/02-slice-boundaries-and-assignment-details.md)。

## 整体替换与名称重新绑定

`values[:] = replacement` 替换原列表的全部内容。右侧也可以是切片读取表达式；普通赋值先对右侧求值，再执行目标赋值，因此可以先生成所需顺序，再用它修改原列表：

```python
values = [30, 10, 20, 40]
alias = values
values[:] = values[::-1]

print(values)
print(alias)
print(values is alias)
```

输出为：

```text
[40, 20, 10, 30]
[40, 20, 10, 30]
True
```

右侧 `values[::-1]` 先生成逆序的新列表。左侧 `values[:]` 随后指定原列表的全部位置，使用右侧列表提供的元素引用替换原内容。两个名称仍引用原来的同一个列表，所以都取得逆序后的内容。

若左侧改为简单名称，右侧的读取不变，目标赋值的作用却不同。下面是从相同初始状态开始的另一份独立脚本：

```python
values = [30, 10, 20, 40]
alias = values
values = values[::-1]

print(values)
print(alias)
print(values is alias)
```

输出为：

```text
[40, 20, 10, 30]
[30, 10, 20, 40]
False
```

右侧仍生成逆序的新列表，随后 `values` [重新绑定](../02-names-objects-and-assignment/01-names-and-assignment.md#重新绑定与多个名称)到这个结果。`alias` 继续引用原列表，原列表的内容没有改变，两个名称此后取得不同对象。

两份脚本中，`values` 最后显示相同的内容，`alias` 的结果和身份关系却不同。赋值目标决定了结果如何被使用：简单名称绑定到右侧结果，切片目标则要求已有列表替换相应的元素引用。右侧是否出现切片，不能独自决定原列表是否被修改。
