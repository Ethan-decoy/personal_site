# 切片的边界与赋值细则（Slice Boundaries and Assignment Details）

切片的默认边界随步长方向改变，显式边界则先换算再裁剪。切片用于赋值时，实际步长还决定是否允许改变列表长度。

边界换算沿用[切片读取](../02-list-slicing.md#步长方向与默认终点)，赋值部分以[基本区间替换](../03-list-slice-assignment.md#切片目标与替换来源)为基础。各个 `python` 代码块都是独立的完整脚本，分别在 Windows 64 位 CPython 3.14.10 中核对；预期失败的脚本也单独运行，目标和替换来源均为内置列表。

## 反向边界的换算与裁剪

显式边界仍按数值处理。负值先加上当前长度；正步长把边界限制在零到长度之间，负步长则限制在负一到长度减一之间。反向调整后得到的负一，是位于索引零之前的边界，不会再次按负索引换算。

```python
values = [30, 10, 20, 40]

print(values[::-1])
print(values[:-1:-1])
print(values[99::-1])
print(values[-99::-1])
```

输出为：

```text
[40, 20, 10, 30]
[]
[40, 20, 10, 30]
[]
```

第一行的起点默认为索引三，省略的终点在索引零之前，因而能够取完整个列表。第二行显式写出终点 `-1`，要先换算为索引三；起点也为三，终点不取，所以结果为空。`values[:None:-1]` 则仍采用反向的默认终点，与 `values[::-1]` 选取相同位置。

第三行的起点九十九超过末尾，在反向选取中限制为索引三，因此也能完整逆序。第四行的起点负九十九按长度换算后仍过小，被限制为索引零之前的边界；它与默认终点相同，没有任何可选位置。反向切片也不会因这些整数边界越界而自动失败。

## 空区间与显式步长一

实际步长为一时，边界沿用[切片的换算与裁剪规则](../02-list-slicing.md#省略边界负值与越界)。没有选中原元素的区间，可以在调整后的起点处插入元素：

```python
values = [30, 10, 20, 40]
values[99:99] = [99]
print(values)

values = [30, 10, 20, 40]
values[3:1] = [99]
print(values)
```

输出为：

```text
[30, 10, 20, 40, 99]
[30, 10, 20, 99, 40]
```

第一组操作中，两个边界九十九都被限制到长度四，在末尾插入一个元素，没有补出索引四到九十八之间的位置。第二组先重新建立相同初始内容，再对 `[3:1]` 赋值：正向区间选不到原元素，但插入点仍是调整后的起点三，因此九十九放在原来的四十之前。

这里与[单项索引赋值的条件](../01-lists-length-and-indexing.md#索引边界与失败位置)不同。`values[len(values)] = 99` 要求这个位置已经存在，会越界失败；步长为一的空区间赋值则可以插入新元素。

显式写出步长一，仍然采用这组规则：

```python
values = [30, 10, 20, 40]
values[::1] = [99]

print(values)
```

输出为：

```text
[99]
```

`values[::1]` 指定全部位置，四个元素可以被一个元素替换。步长写成 `None` 时采用默认值一，也属于这一组；判断依据是实际步长，不是是否出现了第二个冒号。

## 其他步长的逐项替换

实际步长合法且不等于一时，来源元素必须与所选位置逐项配对，数量相同。这包括步长二，也包括步长负一。

```python
values = [30, 10, 20, 40]
values[::2] = [99, 88]

print(values)
```

输出为：

```text
[99, 10, 88, 40]
```

目标切片依次选取索引零、二，来源依次提供九十九、八十八。两个位置分别被替换，未选中的索引一、三仍引用原元素，列表长度保持为四。

负步长也按照切片选取位置的顺序配对：

```python
values = [30, 10, 20, 40]
values[3:0:-1] = [99, 88, 77]

print(values)
```

输出为：

```text
[30, 77, 88, 99]
```

所选位置依次是三、二、一：索引三接收九十九，索引二接收八十八，索引一接收七十七。打印列表时仍按索引从小到大显示，因此结果中的三个替换元素以七十七、八十八、九十九的顺序出现；索引零没有被替换。

> [!IMPORTANT] 其他合法步长的数量约束
> **合法步长不等于一时，列表切片赋值按所选位置的顺序与来源元素逐项配对，数量必须相同，因此不改变列表长度。**数量不匹配会引发 `ValueError`。步长负一同样受此约束，不能因为它逐个选择位置，就套用正步长一的不等长替换规则。

下面是一份来源数量不足的独立脚本：

```python
values = [30, 10, 20, 40]
print("start")
values[::2] = [99]
print("end")
```

程序先输出：

```text
start
```

第三行选中两个位置，来源却只提供一个元素。检查数量时引发 `ValueError`，错误诊断的最后一行为：

```text
ValueError: attempt to assign sequence of size 1 to extended slice of size 2
```

本例尚未执行这次元素替换，目标列表仍为 `[30, 10, 20, 40]`。异常未被处理，脚本终止，`end` 不会输出，已经完成的 `start` 输出保留。

同一个初始列表中，`values[::2] = []` 也会失败：两个位置不能与零个来源元素配对，因此这不是删除方式。`values[::-1] = [99]` 则选中四个位置，只提供一个元素，同样不满足数量约束。若所选位置为空，这组规则也只允许零个来源元素，不会借空区间插入新元素。

数量匹配以合法的切片为前提。步长零、浮点边界等失败条件仍按[切片的输入规则](../02-list-slicing.md#步长方向与默认终点)判断，赋值不会取消这些条件。
