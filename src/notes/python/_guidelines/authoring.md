# Python 书页维护

用于新内容接入、已有篇目整理与交付验证。

## 接入约定

Python 复用现有笔记清单、懒加载、搜索、Markdown 渲染与引用速览。内容入口为 `src/notes/python/_index.md`，无需新增 React 页面、路由或独立搜索实现。

| 位置 | 职责 |
| --- | --- |
| `_index.md` | 已有分篇与章节的公开总目录，使用 `sidebarGroups: headings` |
| `NN-topic/_index.md` | 章节入口，列出现有正文及阅读关系 |
| `NN-topic/NN-question.md` | 以问题组织的公开正文；目录和文件编号用于排序 |
| `NN-topic/deep-dives/` | 确有内容时创建的附章，索引标题为“附章”并设置 `sidebarAfter` |
| `_guidelines/` | 作者规范与覆盖规划，排除于公开目录、搜索和生产正文 |
| `_drafts/` | 有研究底稿时按需创建，同样不公开 |

公开笔记填写 `title`、`date`，需要覆盖默认顺序时填写 `order`。本目录只放总索引与子目录；分篇由总索引的二级标题和直属章节索引链接构成，每个公开章节恰好归属一篇。计划章节留在 [book-structure.md](book-structure.md)，正文成稿后再接入总目录。

## 建设与整理

规划、单篇设计、正文构建与已有内容整理按用户当次要求交付。新正文按指定篇目逐篇构建与审阅，全书底稿不作为批量生成后续正文的授权；整理已有内容时，保留当前任务之外的正文和草稿。

1. 核对 [book-structure.md](book-structure.md) 的已有模型、实际前置与范围，确定本篇解决的问题及当前缺口。
2. 主线按 [writing-style.md](writing-style.md)组织，接口速查按 [quick-reference-writing-style.md](quick-reference-writing-style.md)组织。代码共同遵循 [coding-style.md](coding-style.md)，使用或审阅提示块时核对[提示块职责与写法](../../cpp/_guidelines/markdown-callouts.md)。
3. 创建或调整完整正文与必要索引；概念回指使用相对 Markdown 路径和实际标题锚点，目录导航使用全文入口。
4. 同步总目录、章索引与当前覆盖，保留知识前置和实际内容的对应。发布后路径尽量稳定，逻辑分篇调整不要求移动正文；确需迁移、删篇或改标题时，清理因此失效的目录和引用，包括私有研究稿中的有效引用，不顺带改写其余内容。
5. 按写作与代码规范审阅，完成适用的示例验证和工程检查。已有内容整理应核对正文、代码块和输出的变化范围，区分迁移、引用调整与语义改动。

附章的 `sidebarAfter` 是相对该附章索引的同级正文路径，例如 `../03-mutation-and-sharing.md`。选择确已建立前置的正文作为插入点，并在章索引注明阅读关系。

## 示例验证

网站没有自动执行 Python 代码块的通用检查。按声明的 Python、库版本和执行语境验证，而不把网站构建成功当作示例已实跑：

- **完整脚本：**在声明环境的一次新运行中核对输出、关键状态与副作用；多个独立例子不继承彼此的名称绑定。
- **片段：**提供声明的初始状态和必要外壳后验证，确认外壳没有掩盖正文需要解释的前提。
- **交互记录：**按记录顺序在同一会话核对，区分提示符、表达式回显与程序输出；独立对照恢复相应初始状态。
- **Notebook：**从可重建的内核状态开始，按声明的单元格顺序执行；若研究乱序或重复执行，记录形成相应状态的步骤。
- **预期失败：**单独确认失败阶段、位置、类型、先前已发生的效果及后续执行；错误是论证对象，不通过静默修正来制造成功结果。
- **外部条件或性能：**记录路径、编码、数据、依赖、设备等当前所需条件；不确定输出只核对稳定性质，性能结论保留相应测量条件。

接口或实现结论按对应版本的一手资料核对。运行结果只能支持所验证的环境与情形，不能单独证明语言保证或所有输入的行为。验证记录区分文档核对、Python 实跑、静态工具检查、性能测量与网站构建，注明实际完成的部分。

## 工程检查

- 修改正文链接或标题后，运行 `pnpm check:python-links`，核对公开笔记链接及实际渲染锚点。
- 新增、迁移或删除正文，以及调整导航后，核对 `pnpm check:sidebar`，检查分组、顺序、加载、搜索分类与私有目录隔离。
- 新章接入、正文迁移或目录调整交付前运行 `pnpm build`。完整构建包含上述两项；已通过完整构建时不必重复运行，开发中可单独运行以定位问题。
- 修改内部规范的文件或标题时，另外核对规范自身的相对链接和锚点；公开笔记检查不会覆盖这些私有文档。

构建还检查 Markdown 渲染、性能预算和私有正文泄漏。这些检查不执行 Python 示例，也不验证外部网址、兼容性或技术结论。
