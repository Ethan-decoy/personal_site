# Python 代码示例规范

## 适用范围与选择依据

适用于 Python 书页及后续示例项目中的代码；语言、解释器与环境基线见 [book-structure.md](book-structure.md)。讲解的前置与语义要求见 [writing-style.md](writing-style.md)。

出现多种合法写法时，依次判断：语言与库契约是否正确、对象共享和状态是否清楚、是否直接表达当前意图、是否已有合适的内置或库抽象、是否便于阅读与验证，最后再考虑有证据的性能和平台约束。

语言基础优先使用内置功能与标准库；工具专题使用已建立契约的相应库。前置尚未具备时可用已知基础形式表达当前问题，但不把演示所需的临时形式暗示为通用首选。演示错误、比较写法或解释遗留接口时，明确例子的角色和成立语境。

## 内置功能与标准库

- 容器依据数据的关系与操作选择：有序序列、键到值的映射、唯一性与成员判断各有相应设施，不凭写法短或类型名称机械选择。操作成本结论保留数据规模、计数对象及成立条件。
- 已有合适且前置允许的内置函数、容器方法或标准库功能时，优先组合它们；手工实现用于确实需要说明算法、协议或差异的情形。
- 迭代优先直接取得元素；同时需要位置与元素时可用已建立契约的 `enumerate`，并行消费可用 `zip`。需要下标含义、截断或长度检查时，分别保留条件。
- 推导式用于直接数据变换，普通循环用于多步状态变化、提前退出或复杂分支。抽象、推导式和普通循环以意图清楚为准，不追求压成一行。
- 路径操作可优先采用语义合适的 `pathlib` 接口；确需字符串路径或平台接口时，注明边界。文本与字节各按实际数据契约处理。

## 格式与名称

- 四个空格缩进，不混用制表符；一行保持一项清楚的操作，长表达式使用括号换行。示例优先控制在 88 字符内，这是本书排版选择。
- 变量、函数、模块使用 `snake_case`，类使用 `CapWords`，模块级约定常量使用 `UPPER_SNAKE_CASE`。特殊方法采用语言规定名称，不自行仿造没有契约的双下划线接口。
- 名称以当前作用域内角色清楚为准，不重复已有语境中的类型与背景。小范围例子优先直观短名，如 `value`、`source`、`target`、`alias`、`count`；确需区分再增加限定，保留必要的单位和角色差别。
- 避免含义不明的缩写，不遮蔽 `list`、`str`、`type` 等当前仍需使用的内置名称。
- 复杂表达式用括号和有含义的中间名称表达结构，不依赖读者背诵优先级表。字符串引号以清楚表达内容、减少不必要转义为准，语义对照保留所需差别。
- `python` 用于可复制的脚本或片段，`pycon` 用于含提示符的交互记录，shell 命令按实际环境标为 `powershell`、`sh` 或 `bash`，输出用 `text`。运行命令、Python 源码和输出分别呈现。

当前书页不引入仓库级 Python 环境、依赖锁或格式化器。独立示例项目建立后，在其目录维护工具配置；格式化不能代替语义和接口判断，网站保持现有 Node 工具链。

## 源文件与依赖

- 示例直接导入实际使用的模块或名称，不依赖先前隐藏执行、通配符导入或其他文件偶然提供的名称。
- 导入通常放在文件顶部，按标准库、第三方、自有模块分组。局部或条件导入用于确有语义需求的场景，并解释执行时机。
- 别名以惯例明确、上下文易辨认为准；导入路径、包的分发名称与对象名称分别说明。
- 安装命令绑定到运行示例的解释器。第三方示例记录实际 Python、库版本和必要平台条件，按所用依赖的官方支持说明核对。

## 接口与状态

- 函数的计算结果默认通过返回值表达；以修改或输出为职责时，分别说明其效果。`print` 承担输出任务或示例观测，不以输出文本代替返回值契约。
- 参数角色、返回结果和修改责任应清楚。修改传入对象时说明共享范围；重新绑定参数与修改对象分别解释。跨调用共享状态通过明确接口交代，避免用隐藏的全局可变状态通信。
- 每次调用需要独立的可变默认状态时，在本次调用内建立它；确实共享默认对象时明确其责任。默认参数的求值与复用在使用前说明，不能让跨调用共享成为隐藏效果。
- 返回原对象、新对象、视图或惰性结果时，保留影响后续使用的区别。复制说明独立到哪一层，不把额外复制当作省略共享关系解释的办法。
- 用 `None` 表示缺失的接口采用 `is None`；一般相等比较使用 `==`，需要辨认同一对象时使用 `is`。缺失与零、空值含义不同时，按接口语义显式区分。
- 类型注解在接口语义建立后逐步引入，不要求早期例子处处注解；不以 `Any` 掩盖当前应解释的关系，也不暗示注解自动执行数据验证。
- 对象协作优先保持接口和状态责任清楚。基本类、组合、继承或特殊方法根据实际语义选择，不为形式上面向对象增加额外层次。

## 失败、资源与示例复现

- 在能够处理的边界捕获具体异常，说明恢复、传播或转换的责任；清理后需要继续传播时保留原失败，不吞掉异常后制造成功结果。
- 外部资源使用明确关闭协议。已有上下文管理协议时优先 `with`，手动管理则保证相应清理路径；文本文件标明编码。
- 外部输入校验采用明确的运行时判断。`assert` 用于内部不变式，不承担必需的输入验证；使用时交代它可能随优化选项被移除。
- 完整脚本、片段、交互会话和 Notebook 标明各自的初始状态与执行顺序。预期失败示例与成功示例分开，复用名称不等于复用前一份独立脚本的状态。
- 随机性、时钟、文件、网络、线程或设备调度影响输出时，控制相应条件或只断言稳定性质。时间与内存结论说明测量对象、规模和环境，不以单次耗时作通用规律。
- 注释补充代码不易直接表达的原因、约束与边界，随代码变更核对；文中语义解释与代码注释各承担所需信息，避免重复翻译每行。

## 数值与视觉示例

以下要求在对应专题已建立所需概念后适用：

- 明确形状、轴含义、数值类型、取值范围和设备；图像注明颜色与通道约定，跨库衔接时核对这些条件。
- 每项变换说明返回结果、修改效果及共享存储范围，视图和复制按所用库与具体操作判断；转换接口不自动保证独立数据。
- 图像与标注发生相同几何变换时保持对应；训练、验证和推理的执行状态、梯度设置及数据处理责任按当前任务明确。
- 使用小到足以追踪关键变化的数据；真实数据与实验另行记录来源、划分、依赖和复现条件。
- 选择 Python 循环、数组运算或张量操作时兼顾已建立的契约与实际意图；性能比较说明预热、同步及测量范围等所需条件。

## 示例审阅

检查抽象是否适合当前前置，名称与状态责任是否清楚，返回与修改是否分明，导入与外部条件是否充分；确认代码、输出、注释和正文解释一致。将示例放入声明语境验证，分类方法与验证记录见 [authoring.md](authoring.md#示例验证)。
