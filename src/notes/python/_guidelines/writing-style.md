# Python 笔记写作规范

用于主线正文、章节索引、附章与综合篇的构建、改稿和审阅。范围与版本见 [book-structure.md](book-structure.md)，代码选择与格式见 [coding-style.md](coding-style.md)，接入与验证见 [authoring.md](authoring.md)；接口速查使用独立的[速查写作规范](quick-reference-writing-style.md)。

本规范约束知识、解释和证据的质量；讲述顺序与篇幅按内容选择。“应”“须”“不得”表示要求，“默认”“优先”表示可依据具体内容调整的选择，“可以”表示可选做法。构思与审阅要求供作者使用，不作为正文栏目、练习或学习进度表。

## 定位

笔记兼顾顺序理解与长期查阅。默认读者缺少编程经验，但读过前置正文；介绍过不等于已经熟练。语言基础应独立成立，工具专题说明相应库的用法与限制。

写成知识笔记：直接解释概念、行为、来由和使用判断，操作说明交代方法、条件与结果，不预设读者正在逐步跟做。文字自然、清楚，语气平等；背景、类比与幽默按内容使用，语法简短不意味着可以省略解释。

## 整体要求

每篇围绕一个可辨认的问题组织：读者面对什么现象或任务，需要解释、区分或决定什么。同一问题可以包含多个紧密依赖的关系；不按术语、符号或接口名称的数量划分篇目。

技术概念的“模型”，是涉及哪些对象、它们有什么关系，以及操作在什么条件下产生什么结果的解释。当前层次建立完成，应有正文依据支持以下判断：

- 能区分当前容易混淆的对象、写法与行为。
- 能根据条件与规则判断未逐一列举的同类情形；涉及代码时，能推演其行为，而非只复述本例输出。
- 能解释结果怎样产生，指出必要的状态变化或中间关系。
- 能说明何时不能照用该结论、会有什么后果，以及当前操作或选择为何适用。

当前用法所需的写法、合法语境、输入、返回结果、修改效果与失败条件，合称使用契约，按实际涉及的项目建立。内部如何实现可以后置；当前正确使用依赖的条件须在使用前说明。分类与精细规则按判断需要展开，不能以“以后再讲”省略必要前提。

早期模型可以限定范围，后续补足机制和边界；不得依靠日后必须推翻的错误关系推进。事实背景与目录索引按各自问题组织，不机械套用程序执行模型。

## 顺序阅读与理解成本

以掌握同一关系的总负担判断详略，兼顾辨认写法、回忆前置、追踪状态和筛选重点的成本。

- 新代码形式应说明当前用到的组成、名称角色、合法位置与结果。仅给出写法或术语，不能视为已建立使用能力。
- 复用前置时，就地恢复当前判断实际依赖的关系，并链接讲解小节；链接和章节进度不能代替必要解释。
- 跨段落或代码块时，保持名称、对象、共享关系和调用可追踪；更换表示或情境，应交代对应关系。进入子问题与返回时，保留原目标及中间结果的用途。
- 需同时保留多组状态或未完成关系时，用有含义的名称、局部表格或图示承载。简短正文已能说清时保持简洁。
- 先让关系形成可用判断，再补不影响当前结论的背景与机制。熟悉的关系可缩减支撑，必要条件仍须保留。

## 内容分层

| 位置 | 职责 |
| --- | --- |
| 章节索引 | 定位已有内容及阅读关系；标题已足够导航时保持简洁，必要时补充前置或关键区别 |
| 主线 | 建立当前行为、失败边界与正确使用所需的判断依据 |
| 附章 | 在具备前置后展开实现机制、精细规则与版本或平台差异 |
| 综合篇 | 组合已建立的模型解决问题，解释共同作用与取舍；新增使用契约仍须就地补齐 |

归属以当前用途和知识依赖判断。主线所需的条件不能只留在附章；领域背景只补理解当前工具所需的部分，语言规则、库契约与领域理论保持清楚归属。

## 篇章构造与查阅

**正文直接陈述知识关系、条件、行为与因果。**作者如何选例、安排讲解、引导观察或评价讲解效果，留在作者工作中。程序执行顺序、结论推导、前置补充与复现条件仍须就近交代；按句子的作用判断，不按个别词语机械筛选。

- 开头与过渡提供当前理解所需的事实、现象、例子或问题。删去后只少了讲解预告或主题提纲，不损失知识、因果与必要条件的句子，应删去或改为实际知识。
- 段落围绕明确的对象、操作与结果展开，使抽象关系能落回代码。条件如何改变行为、当前结果支持什么判断，应在论述中可见。
- 标题帮助定位对象、问题或结论。单篇查阅通过就地回顾、前提说明与链接恢复必要联系，不要求重建整条知识链。
- 操作说明写清输入位置、动作、结果与约束；命令说明由谁执行、作用于什么，不以完成提示串联知识。

## 示例

示例须显现正在说明的关系，代码共同遵循 [coding-style.md](coding-style.md)。情境是否恰当、语义是否正确、证据是否支持结论，应分别判断。

- 优先采用背景负担小、对象用途自然的情形。依赖情境含义时，说明数据或对象代表什么、操作要完成什么，不让读者只凭标识符猜测。
- 只依赖已建立的语义；确实不可替代的新设施，先给出当前所需的使用契约。程序外壳与辅助操作以当前问题所需为限。
- 已有例子仍适合时优先沿用。新例子应让模型用于新的判断；对照优先只改变影响当前结论的条件，多处变化时说明对应关系。
- 声称的区别须有能够区分它们的依据。相同输出不能独自证明对象相同、发生复制或存储共享；由语言或库契约支持的结论，与本次运行观察分别说明。
- 错误示例交代失败阶段、位置、类型、原因、先前已发生的效果及后续执行。错误直觉用能暴露后果的条件说明，由正文解释，不留作练习。
- 标明完整脚本、片段、交互会话或 Notebook。片段给出初始状态与嵌入语境，会话说明输入顺序和保留状态，环境、路径、编码与依赖按需要就近交代。代码、输出、注释与正文应一致；实际验证按 [authoring.md](authoring.md#示例验证)执行。

## 掌握要求

先选择当前判断实际需要掌握的内容，再决定怎样呈现。

| 掌握方式 | 选择与呈现依据 |
| --- | --- |
| 熟记并直接调用 | 后续阅读或操作会反复依赖、临场重建容易中断判断或遗漏条件的通用关系与方法。提炼关系、范围与用途，不把实例数值或整段程序作为记忆对象 |
| 理解并能重建 | 用于说明结论依据、状态变化和推演的过程。写清必要联系，使读者能重建判断，不要求逐句复述 |
| 使用时查阅 | 依赖实现、版本、平台或任务而需核对的数据、规格与细则。说明触发条件、核对项目和可靠入口，在依赖这些条件的操作前完成核对 |

选为熟记内容，应能指出哪些同类判断会反复依赖它。具体例子的结果通常承担理解用途；能够推导的常用关系仍可熟记，但须有独立的使用价值。同一知识可以兼有三种掌握要求，查用也须先建立足以识别触发条件与使用边界的理解。

需要熟记的核心关系，在建立处用 `[!IMPORTANT]` 蓝框就地突出，保留条件与判断用途。方法、易错边界和工程做法即使需要熟记，也按[各自的内容职责](../../cpp/_guidelines/markdown-callouts.md#内容与选型)选择类型。文末回顾不能代替就地标识；长篇推导、命令表与配置对照易被误当作整体记忆任务时，就近交代理解或查用要求。

## 重点的选择与呈现

正文承担解释与推演，加粗标记当前定义、关键区别、通用关系与重要边界，表格用于精确对应，图示用于关系与过程。形式应降低追踪和查阅成本，同一信息不作冗余呈现。

提示块的成框依据、类型分界、重叠取舍与标题，统一按[提示块职责与写法](../../cpp/_guidelines/markdown-callouts.md)判断。相同条件下的同一关系集中突出，后续恢复当前所需联系；不同判断或失败条件按需要分别保留。重点提炼须保留对象范围与成立条件，工程建议应区分语言规则、库契约、项目约定与有条件的建议。

## Python 的解释边界

以下要求在相应主题出现时适用：

- **名称与对象：**区分绑定、取得对象和修改对象，追踪名称当前引用谁；示意按名称到对象的引用关系组织，避免赋值复制的暗示。
- **类型、身份与值：**类型属于对象，动态类型仍有操作约束。值相同、身份相同与共享存储分别判断；具体 `id` 数值或字面量缓存不能代替关系解释。
- **函数与作用域：**跟踪实参求值、参数绑定、函数体执行与返回，区分重新绑定参数与修改共享对象。默认值、闭包与装饰器分别交代求值、绑定和读取时机，不用“传值／传引用”标签代替推演。
- **容器与复制：**分别追踪外层容器及元素对象，说明哪一层获得独立状态。不可变性说明作用于哪个对象，区分容器结构与元素对象的变化。
- **迭代与延迟执行：**区分可迭代对象与迭代器，说明创建、消费、保留状态与耗尽；生成器和异步设施交代执行、暂停、恢复及清理时机。
- **模块与运行环境：**区分源码、导入与安装依赖，核对实际解释器、依赖版本、搜索位置及执行入口；文件路径、编码与会话状态属于复现条件。
- **异常与资源：**区分源码检查与运行失败，跟踪传播、已完成操作和清理责任。异常不自动撤销先前操作，资源释放依据明确协议，不依赖垃圾回收时机的猜测。
- **类型注解：**静态契约与运行时行为分别说明，注解本身不验证外部数据；额外库的验证能力按其契约判断。
- **实现与工具：**字节码、地址、引用计数、缓存与锁注明实现、版本和构建条件；诊断与单次观察不能独自证明跨实现保证。
- **数组、图像与框架：**在工具专题建立存储、形状、轴、数值类型、设备和梯度关系。跨库转换、视图与复制按具体操作说明，不能由 Python 对象关系直接推出。

## 术语、引用与呈现

- 专业术语在需要命名当前关系时引入，首次给出中文与英文，之后使用稳定称谓。
- 标题使用普通文本，不额外加粗或使用行内代码。
- 概念引用指向实际讲解小节，目录导航指向全文；引用处仍保留当前必需的解释。
- 文末只列与当前问题直接相关的一手资料。语言规则使用固定版本 Language Reference，库使用对应版本官方文档，PEP 用于设计背景，实现与工具使用各自官方说明。

## 审阅清单

审阅覆盖本规范及当前适用的关联要求。代码能运行、输出相符或链接检查通过，只回答各自验证的问题，不能代替对解释、示例和呈现取舍的判断。

1. 对照本篇问题与全部新增内容，检查每项规则、例子与补充是否有当前用途，必要前置和使用契约是否已经建立。
2. 逐例追踪对象、调用、状态、结果与失败后果，核对说明是否相互一致，证据是否足以支持抽象结论。
3. 从全文识别应熟记、理解与查用的内容，再核对实际呈现；检查核心关系、关键条件和判断方法有无遗漏。
4. 按[提示块选型复核](../../cpp/_guidelines/markdown-callouts.md#写作与审阅)比较已有框与相邻候选类型，检查成框必要性、结论、条件和重复；不能以复述已用类型的定义作为选型证据。
5. 逐段检查作者选例理由、讲解安排与空泛提纲，同时保留必要的知识推演、前置和复现条件；检查顺读与单篇查阅是否都能定位结论及其条件。

涉及取舍的结论应由具体内容与比较支持；规范允许的不同写法不判为偏离。未检查或依据不足的部分单独说明，完成适用的示例、链接与接入验证后再给出相应范围的结论，验证要求见 [authoring.md](authoring.md)。
